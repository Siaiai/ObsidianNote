# 个人 C 编码风格

  

跨项目复用的个人 C 编码规范。从 Panel_RTOS 现有代码归纳，剔除项目专属内容（HAL 分层 / 初始化顺序 / 仓库结构 / 构建告警 flag 清单）。格式基准由 `.clang-format` 强制。

  

---

  

## 一、编码风格

  

- **编-1** 缩进 4 空格，禁 Tab。

- **编-2** 行宽 100，超长折行。

- **编-3** 大括号：开括号与声明/语句同行（Attach）。

- **编-4** 指针星号靠左（靠类型）：`uint8_t* data`、`void (*cb)(void)`。

- **编-5** 续行缩进一级（4 空格），不对齐到首参数。

- **编-6** 禁单行 `if`/`loop`/`case`/`function`，一律多行带括号。

- **编-7** switch：`case` 与 `switch` 同级缩进；每个 `case` 都用 `{}` 包；保留 `default` 兜底；fall-through 用 `case A: case B: { }`。

- **编-8** 声明可在块内任意位置（C99+）。

- **编-9** 未使用形参显式 `(void)param;`。

- **编-10** 指针判空用 `NULL`，不用 `0`：`if (ptr == NULL)`。

- **编-11** 结构体对齐：优先重排字段消除 padding；无法消除时 `#pragma pack(push, 1)` / `pack(pop)`。

- **编-12** 整数字面量无符号加 `U`（`0U`、`1000U`）；十六进制 `0x..`。

- **编-13** 一律用定宽类型（`uint8_t`/`int16_t`/`uint32_t`…），不用裸 `int`/`char`。

- **编-14** 收窄/改符号赋值显式 cast：`(uint16_t)x`。

- **编-15** 连续宏定义、连续赋值做列对齐。

- **编-16** 注释统一中文，技术术语保留英文。

- **编-17** 注释形式：段注释 `/* */`、行内/短注释 `//`；分区用 `/* ---- 标题 ---- */` 或 `#pragma region`。

- **编-18** 返回值/错误码：各库内部自洽，不强制跨库统一。

  

## 二、命名风格

  

- **命-1** 函数：外部（公开 API）`Module_PascalCase`；内部 `static` 用 `lowercase_with_underscores`。中断回调虽 `static` 也用小写下划线；向量表符号（如 `SysTick_Handler`）需外部链接，加原型声明而非 `static`。

- **命-2** 类型：`Module_PascalCase_t`，统一 `_t` 后缀。

- **命-3** typedef struct：普通用匿名 `typedef struct { ... } Name_t;`；需自引用（链表节点、回调拿自身类型）用具名 + 前向声明。

- **命-4** 枚举值：统一用 `ePascalCase`（`eOk`、`eKeyUp`、`eStateIdle`）。宏仍用 `UPPER_CASE`（见 命-5），二者视觉区分。

- **命-5** 宏与常量：简单值替换 `#define UPPER_CASE`；枚举集合用 `enum`；类型相关只读变量用 `static const`。

- **命-6** 变量前缀：全局 `g_`、文件局部 `static` 用 `s_`、局部无前缀小写。

- **命-7** 函数指针类型：按语义命名，不强制统一后缀--回调 `_Cb_t`、处理 `_Handler_t`、收发 `_Send_t`/`_Receive_t`/`_GetTime_t`、指令 `_Callback_t`。

  

## 三、头文件 / 源文件规范

  

- **文-1** 包含守卫：`#ifndef NAME_H_` / `#define NAME_H_` / `#endif /* NAME_H_ */`（单下划线尾，符合 C 保留标识符规则）。

- **文-2** 文件头注释（doxygen 风格）：`@file` / `@brief` / 详细说明。

- **文-3** 接口与实现分离：`inc/` 放公开头，`src/` 放实现；内部助手在 `.c` 内 `static`，不进头文件。

- **文-4** `#include` 顺序：手工分组，不自动排序。
