# 一、通信协议

## 1.1 物理层

- **SR3**: HC32F002, LPUART1, 48MHz RCH → PCLK 6MHz（[main.c:39](D:\Reader\HC32F002_DDL_Rev1.2.0（卡号错误问题解决优化版）\example\gtimer\gtimer_timer\source\main.c:39)）

## 1.2 0x10 帧格式（日常通信）

所有日常通信使用 0x10 帧：

```
┌────────┬────────┬────────┬────────────────────┬─────────┐
│  0x10  │  0xFF  │  CMD   │  DATA（变长）        │  BCC?   │
│  帧头   │  帧头   │  命令   │                     │  可选    │
└────────┴────────┴────────┴────────────────────┴─────────┘
```

- **帧头固定** 0x10 0xFF
- **CMD** 即第三个字节，决定包类型和数据长度
- **DATA 长度由 CMD 决定**，不在帧中传递 LEN 字段
- **BCC 可选**，模式 2/3 时附加在末尾：`BCC = XOR(全部字节)`

### BCC 计算规则（代码实证）

[S3 RFID.c:675-691](D:\Reader\HC32F002_DDL_Rev1.2.0（卡号错误问题解决优化版）\midware\RFID\RFID.c:675)：
```c
uint8_t BCC_Check(uint8_t *data, uint16_t length)
{
    uint8_t bcc = 0;
    while(length--) bcc ^= *data++;
    return bcc;
}
```

**BCC = 缓冲区内所有字节 XOR**（从 0x10 到 DATA 最后一个字节）：
- 卡号包 BCC: `BCC_Check(FirstLu_Kahao_buffer, 8)` → 8 字节 XOR（[RFID.c:453](D:\Reader\HC32F002_DDL_Rev1.2.0（卡号错误问题解决优化版）\midware\RFID\RFID.c:453)）
- Fail 包 BCC: `BCC_Check(FirstLu_Send_ERR, 7)` → 7 字节 XOR（[main.c:85](D:\Reader\HC32F002_DDL_Rev1.2.0（卡号错误问题解决优化版）\example\gtimer\gtimer_timer\source\main.c:85)）

## 1.5 忙保护规则

接收指令时，以下任一条件为真则**静默忽略**（不回应任何东西）：

| 标志 | 含义 | 持续时间 |
|---|---|---|
| `B_TX1_Busy != 0` | 串口正在发送 | 一次发送时间（几 ms） |
| `Read_card_100ms_flag != 0` | 进站 100ms 等待/冷却中 | ~150ms |

# 三、位置行为

## 3.1 进站（Send_Manner = 0x55）

指令 `0x7A` 或 `0x9A` 设置为进站方向。

### 完整时序

```
新卡检测 → 立即上报（第1次）
         → 启动 100ms 定时器（flag=1）
         → 100ms 后 → 二次上报（第2次，同卡号）（flag=2）
         → 发送完成 → 进入 50ms 冷却（flag=3）
         → 冷却结束 → 恢复正常（flag=0）
```

### 100ms 计时

| 项目 | SR2 | SR3 |
|---|---|---|
| 节拍源 | Timer0 10ms | ATIM3 50ms |
| 计数阈值 | `timer >= 10` | `timer >= 2` |
| 触发动作 | flag=2 → TI 中断发卡号（[main.c:164-174](D:\Reader\RFID_STC15_C语言（EM4095收指令发） (2)\main.c:164)） | flag=2 → 主循环 `RFID_Send_Handler()` 发卡号（[RFID.c:229-238](D:\Reader\HC32F002_DDL_Rev1.2.0（卡号错误问题解决优化版）\midware\RFID\RFID.c:229)） |

### 50ms 冷却

| 项目 | SR2 | SR3 |
|---|---|---|
| 计数阈值 | `timer >= 5`（5×10ms） | `timer >= 1`（1×50ms） |
| 冷却期行为 | 忽略上位机指令 | 忽略上位机指令 |
| 结束后 | `flag=0`，正常 | `flag=0`，正常 |
| 模式3例外 | — | 不进冷却（[RFID.c:240](D:\Reader\HC32F002_DDL_Rev1.2.0（卡号错误问题解决优化版）\midware\RFID\RFID.c:240)） |

# 五、固件升级

> 详细内容见 [260802SR3读卡器需求.md] 第十一~十四章。此处列关键速查。

## 5.1 Flash 布局

| 地址 | 内容 | 大小 |
|---|---|---|
| 0x0000 ~ 0x1BFF | Bootloader | 7KB |
| 0x1C00 (APP_START_ADDR) | Application | 最大 0x2A00 (10KB) |
| 0x4600 (UPD_PARAM_FLASH_ADDR) | Upgrade Param | 512B |
| 0x4800 | Flash 末尾 (共 18KB) | — |

## 5.2 UpdateFlg 状态机

| 值 | 含义 | Bootloader 动作 |
|---|---|---|
| 0xFF | 擦除态/正常 | 立即跳 App |
| 0 (rNormal) | 正常 | 驻留监听 |
| 5 (rRecive) | 正在收固件 | 驻留监听 |
| 3 (rUpdated) | 升级完成 | App 见后发 0x03 上报 |

## 5.3 三端架构

PC（UDP 下发）→ S3 控制器（存 W25QXX, sUpdate→sErase→sRecive→sWaitRes）→ 读卡器 Bootloader（擦/写/XOR解密/跳转）

## 5.4 0x55 升级帧格式

```
上位机 → 读卡器（含 PackNo）:
┌──────┬─────┬──────────┬──────────┬──────────────┬──────────┬──────┐
│ 0x55 │ CMD │ Len(LE)  │ PackNo   │ Data[Len]    │ CRC16 LE │ 0xAA │
└──────┴─────┴──────────┴──────────┴──────────────┴──────────┴──────┘

读卡器 → 上位机（不含 PackNo）:
┌──────┬─────┬──────────┬──────────────┬──────────┬──────┐
│ 0x55 │ CMD │ Len(LE)  │ Data[Len]    │ CRC16 LE │ 0xAA │
└──────┴─────┴──────────┴──────────────┴──────────┴──────┘
```

## 5.5 升级命令

| CMD | 方向 | 语义 |
|---|---|---|
| 0x81 | 上位机→BL | 启动升级（含 PackedNum） |
| 0x82 | 上位机→BL | 发送一包数据（256B+CRC16） |
| 0x83 | 上位机→BL | 查询升级结果 |
| 0x01 | BL→上位机 | 启动确认 |
| 0x02 | BL→上位机 | 数据包 ACK（uOK=0xAA/uFail=0x55） |
| 0x03 | BL/App→上位机 | 状态报告（版本+结果） |
| 0x04 | BL→上位机 | 启动通知（4 字节零） |

## 5.6 安全机制

| 机制 | 参数 |
|---|---|
| CRC | CRC16-USB (0x8005), 初值/结果 XOR 0xFFFF |
| 加密 | XOR, key="603337"（6 字节循环），仅 Bootloader 解密 |
| 包序号 | 严格递增，跳跃则静默丢弃 |
| 重传 | S3 侧最多 5 次 / Bootloader 无重传逻辑 |
| 超时 | S3: 30s 整体 + 3s 单步 / BL: ~4s（8000×500μs） |

## 5.7 恢复机制

- **Bootloader 区永不被擦写**——永远完好
- **App 启用 IWDT** ~3.2s 超时复位——损坏 App 跑飞后自动回 Bootloader
- **UpdateFlg≠0xFF 时 Bootloader 驻留**——0x81 来者不拒可重新升级
- **结论：OTA 不会永久变砖**，但恢复依赖 PC/S3 重新发起升级

# 六、SR2 ↔ SR3 差异与兼容

## 6.1 兼容基线（上位机只发 0x7A/0x75）

上位机仅使用 `10 FF 7A` 和 `10 FF 75` 时，SR2 和 SR3 可互换：

| # | 行为 | SR2 | SR3 |
|---|---|---|---|
| 1 | 0x10 0xFF 3 字节命令帧 | ✅ | ✅ |
| 2 | 0x7A → 进站 0x55 + 应答 Fail | ✅ | ✅ |
| 3 | 0x75 → 下放 0xAA + 有卡报卡号/无卡 Fail | ✅ | ✅ |
| 4 | 8 字节卡号包（10 FF 05 + 5B 卡号） | ✅ | ✅ |
| 5 | 7 字节 Fail 包（10 FF 04 Fail） | ✅ | ✅ |
| 6 | 卡号变化立即上报（不等轮询） | ✅ | ✅ |
| 7 | 进站 100ms 二次上报 | ✅ | ✅ |
| 8 | 下放单次上报 | ✅ | ✅ |
| 9 | 进站 50ms 冷却 | ✅ | ✅ |
| 10 | 忙保护（Busy / 100ms_flag） | ✅ | ✅ |
| 11 | 同卡去重（比较 buffer2） | ✅ | ✅ |
| 12 | 200ms 无卡超时清零 | ✅ | ✅ |
| 13 | Send_Manner 方向 | ✅ | ✅ |
| 14 | SHD: 高 50ms → 低 | ✅ | ✅ |
| 15 | 125kHz 硬件产生 | ✅ | ✅ |
| 16 | 曼彻斯特脉宽分类 + 64 位还原 | ✅ | ✅ |
| 17 | 行校验 + 列校验 | ✅ | ✅ |
| 18 | 40 位 → 5 字节卡号（大端） | ✅ | ✅ |
| 19 | 19200-8-N-1 | ✅ | ✅ |

## 6.2 完整差异表

| 维度 | SR2 (STC15) | SR3 (HC32F002) |
|---|---|---|
| **MCU** | STC15W4K32S4 | HC32F002 |
| **主频** | 29.4912MHz | 48MHz RCH |
| **Flash/RAM** | 32KB / 4KB | 18KB / 2KB |
| **命令条数** | 2（0x7A, 0x75） | 7（+0x9A/0x95/0x9D/0x90/0xA0 0x05） |
| **模式** | 仅模式1 | 模式1/2/3 |
| **BCC** | ❌ | 模式2/3 ✅ |
| **校验关数** | 2（行+列） | 3（+停止位） |
| **LED** | 极简 | 模式闪烁/红绿互斥/黑卡时序 |
| **看门狗** | ❌（被注释） | ✅ IWDT ~3.2s |
| **节拍定时器** | Timer0 10ms | ATIM3 50ms |
| **发送方式** | TI 中断 + SBUF 逐字节 | LPUART_Transmit 阻塞 |
| **Bootloader** | ❌ | ✅ 0x55 帧协议 |
| **远程升级** | ❌ | ✅ 三端架构 |

## 6.3 新 SR3 开发注意事项

| 旧版问题 | 新 SR3 建议 |
|---|---|
| SR3 主循环阻塞发送（LPUART_Transmit） | 用 FIFO + ISR 发送 |
| Data_check() 期间关 125kHz（Gtim_Disable） | 输入捕获 ISR 记录边沿，不停载波 |
| Bootloader 无看门狗 | BL 也启用看门狗 |
| Flash 写失败仍回 uOK 且置 flag=1 | 检查 Flash 写返回值 |
| Len>256 未处理导致误判完成 | 增加 Len 严格校验 |
| S3 控制器解析读卡器响应时不检查 BCC | 新协议若加 BCC，两端都检查 |
