# SR3 读卡器 · 完整功能需求文档

> 整合自 HC32F002 读卡器固件 + S2 控制器 + S3 控制器 三个工程。
> 仅描述软件功能行为，不涉及代码实现、不涉及硬件设计。

## 一、系统全景：读卡器在整个吊挂系统中的位置

```
                           ┌─────────────────────────────┐
                           │       PC 上位机服务器         │
                           │   (任务调度 / 衣架追踪 / MES) │
                           └──────┬──────────────────┬────┘
                                  │ UDP/Ethernet     │ UDP/Ethernet
                    ┌─────────────┴──┐          ┌────┴──────────────┐
                    │ S2 控制器 (旧) │          │ S3 控制器 (新)     │
                    │ PIC18F97J60    │          │ GD32F407/427       │
                    │ lwIP + 串口    │          │ lwIP + CAN + 串口  │
                    └───┬──┬──┬──┬──┘          └──┬──┬──┬──┬──┬──┬──┘
                        │  │  │  │   WK2114       │  │  │  │  │  │
                        │  │  │  │  (SPI扩4串口)   │  │  │  │  │  │
                        │  │  │  │                │  │  │  │  │  │
               ┌────────┤  │  │  ├────────┐       │  │  │  │  │  │
               ▼        ▼  ▼  ▼  ▼        ▼       ▼  ▼  ▼  ▼  ▼  ▼
           ┌──────┐  ┌──────┐  ┌──────┐      ┌──────┐  ┌──────┐  ┌──────┐
           │ 进站  │  │ 下放  │  │ 出站  │      │ 进站  │  │ 下放  │  │ 出站  │
           │读卡器 │  │读卡器 │  │读卡器 │      │读卡器 │  │读卡器 │  │读卡器 │
           │ A站口 │  │ A站口 │  │ A站口 │      │ B站口 │  │ B站口 │  │ B站口 │
           └──────┘  └──────┘  └──────┘      └──────┘  └──────┘  └──────┘
             入口       工作站      出口           入口       工作站      出口

            ←────────── 一个站口(A) ──────────→  ←────────── 一个站口(B) ──────────→
```

**关键概念：**
- 一块控制器板同时管理 **2 个站口**（A 站 + B 站）
- 每个站口有 **3 个读卡器**：进站口、下放口、出站口
- 一块控制器板最多接 **6 个读卡器**（2站 × 3位置）
- 读卡器之间**完全独立**，通过 UART 与控制器点对点通信
- 所有读卡器**硬件完全相同**，仅通过安装位置区分角色

## 二、读卡器本身的功能（Reader 端）

### 2.1 一句话定位

125kHz RFID 读卡器。读出 EM4100/EM4102 标签的卡号，通过串口应答上位机的轮询指令。

### 2.2 核心流程

```
上电 → 产生125kHz载波 → 等待标签进入
                           ↓
                    曼彻斯特解码 64位原始数据
                           ↓
                    头部/行/列/停止位 四重校验
                           ↓ 通过
                    提取 5字节卡号
                           ↓
                    等待上位机轮询指令 → 应答卡号（或 Fail）
```

### 2.3 RFID 解码能力

| 项目 | 规格 |
|------|------|
| 频率 | 125kHz |
| 标签协议 | EM4100 / EM4102 (EM4001 族) |
| 编码方式 | 曼彻斯特编码 (Manchester) |
| 原始数据 | 64 位 (9头 + 40数据 + 10行校验 + 4列校验 + 1停止位) |

**四重校验（任一失败则丢弃，重新读）：**

```
校验1: 头部校验 ── 前9位必须全为 1
校验2: 行校验   ── 10行 × (4数据位+1奇偶位)，每行奇校验
校验3: 列校验   ── 4列 × (10数据位+1奇偶位)，每列奇校验
校验4: 停止位   ── 第64位必须为 0

附加过滤: 5字节卡号全为 0x00 时不上报
```

**脉宽分类（曼彻斯特边沿检测）：**

```
窄脉冲: 约 160 ~ 328 μs  → 类型1
宽脉冲: 约 328 ~ 656 μs  → 类型2
超出范围 → 复位解码器，重新开始
```

### 2.4 三种工作模式

```
┌──────────────────────────────────────────────────────────────┐
│ 模式1 · 默认模式                                             │
│   触发: 0x7A(进站) 或 0x75(下放)                             │
│   ┌─读到卡─→立即上报卡号(8字节)                               │
│   │   ↓ ~100ms                                               │
│   │  二次上报(同一卡号，防丢)                                  │
│   │   ↓ ~50ms 冷却                                           │
│   └─等待下次读卡或指令                                        │
│   方向: 进站=0x55, 下放=0xAA (内部标识，不影响协议帧)          │
├──────────────────────────────────────────────────────────────┤
│ 模式2 · 校验模式                                             │
│   触发: 0x9A(进站) 或 0x95(下放)                             │
│   同上，但每帧末尾追加 1字节 BCC (XOR 校验)                    │
│   卡号包: 9字节  失败包: 8字节                                │
├──────────────────────────────────────────────────────────────┤
│ 模式3 · 连续发送                                             │
│   触发: 0x9D                                                 │
│   有卡: 每 ~100ms 上报一次卡号                                │
│   无卡: 每 ~500ms 上报 "Fail"                                │
│   红灯常亮，不等待上位机轮询                                   │
└──────────────────────────────────────────────────────────────┘
```

### 2.5 串口协议（读卡器 ← 上位机）

**物理层：** 19200 bps, 8-N-1, 无流控

#### 上位机 → 读卡器（3 字节轮询帧）

```
  0x10    0xFF    命令字节
  ────    ────    ──────
  帧头1   帧头2   功能码
```

| 命令 | 功能 | 切换模式 | 方向 |
|------|------|---------|------|
| `0x7A` | 进站读取 | → 模式1 | 进站 |
| `0x75` | 下放读取 | → 模式1 | 下放 |
| `0x9A` | 进站读取(BCC) | → 模式2 | 进站 |
| `0x95` | 下放读取(BCC) | → 模式2 | 下放 |
| `0x9D` | 连续发送 | → 模式3 | — |
| `0x90` | 查询版本 | 不变 | — |
| `0xA0 0x05` | 系统复位 | MCU软件复位 | — |

#### 读卡器 → 上位机（应答帧）

```
▸ 有卡 (模式1/3):
  0x10  0xFF  0x05  卡号[3]  卡号[4]  卡号[5]  卡号[6]  卡号[7]
  ────  ────  ────  ───────  ───────  ───────  ───────  ───────
  帧头   帧头  长度    ←────────── 5字节卡号 (40位) ──────────→

▸ 有卡 (模式2, 加校验):
  0x10  0xFF  0x05  卡号[3..7]  BCC     ← 9字节，末尾BCC = 前面所有字节的XOR

▸ 无卡 (模式1/3):
  0x10  0xFF  0x04  'F'  'a'  'i'  'l'   ← 7字节

▸ 无卡 (模式2):
  0x10  0xFF  0x04  'F'  'a'  'i'  'l'  BCC   ← 8字节

▸ 版本号:
  0x10  0xFF  0x01  'V' 'e' 'r' '0' '3' '1' '0'   ← 10字节
```

### 2.6 LED 行为规范

```
        绿灯 LEDG (有卡指示)          红灯 LEDR (状态/错误)
        ──────────────────          ──────────────────
模式1:   有卡亮 · 无卡灭              绿灯灭时亮 · 绿灯亮时灭 (与绿灯互斥)
模式2:   同模式1                      同模式1
模式3:   有卡亮 · 无卡灭              ● 常亮

模式切换闪烁 (绿灯):
  切到模式1 → 闪 2 次
  切到模式2 → 闪 4 次
  切到模式3 → 闪 6 次
  闪烁速度: 每 ~200ms 翻转一次

读卡保持: 模式1/2 读到卡后绿灯亮，无新卡则 ~200ms 后灭

特殊 · 立杆小车黑卡 (卡号[5..7] = 0x00,0x00,0x5A):
  两灯全灭 → ~300ms 后 → 两灯同时亮
```

### 2.7 指令冲突保护

下列情况读卡器**不应响应**上位机轮询：
- 正在发送应答数据中（TX busy）
- 处于卡号二次上报的 100ms 等待期内

### 2.8 远程升级能力

```
升级帧格式:
  ┌─────┬─────┬───────┬───────┬──────────────┬───────┬─────┐
  │0x55 │ CMD │ Len(2)│PackNo(2)│  Data(≤256B) │CRC16(2)│0xAA │
  └─────┴─────┴───────┴───────┴──────────────┴───────┴─────┘
   帧头   命令   长度    包序号     数据           校验    帧尾

升级指令:
  0x81 → 启动升级
  0x82 → 传输固件数据块 (包序号必须连续递增)
  0x83 → 查询升级结果

状态机: 空闲 → 接收中 → 更新中 → 等待结果 → 完成/失败

安全:
  CRC16-USB (多项式 0x8005)
  固件数据用密钥 "603337" 加密
  包重发最多 5 次
  上电时自动上报上次升级结果
```

### 2.9 定时基准

系统需要一个 **50ms 周期节拍**，所有定时基于它的倍数：

```
  50ms × 1  =   50ms   EM4095 初始化稳定时间
  50ms × 2  =  100ms   卡号二次上报延迟 / 连续模式有卡周期
  50ms × 4  =  200ms   读卡 LED 超时 / 模式切换闪烁半周期
  50ms × 6  =  300ms   立杆小车 LED 延迟
  50ms × 10 =  500ms   连续模式无卡上报周期
  50ms × 2+ = ~106ms   看门狗超时
```

### 2.10 错误处理全表

| 错误 | 行为 |
|------|------|
| 无卡 | 应答 "Fail" |
| 头部校验失败 | 复位解码器，重读 |
| 行/列校验失败 | 复位解码器，重读 |
| 停止位错误 | 复位解码器，重读 |
| 全零卡号 | 不上报，LED灭 |
| 脉宽超范围 | 复位解码计数器 |
| 升级帧头缺失 | 解析错误码 1 |
| 升级CMD无效 | 解析错误码 2 |
| 升级帧尾缺失 | 解析错误码 3 |
| 升级数据超长 | 解析错误码 4 |
| 升级CRC16不匹配 | 解析错误码 5 |
| 升级包序号跳跃 | 忽略该包 |
| TX忙时收到轮询 | 静默忽略 |
| 看门狗超时 | MCU硬件复位 |

## 三、控制器端如何使用读卡器（S2 & S3 通用逻辑）

### 3.1 一个站口的物理流程

```
  ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
  │  主轨道   │ ──→ │ 进站读卡  │ ──→ │ 进站阀   │ ──→ │ 缓冲区    │ ──→ │ 下放读卡  │
  │ (输送链)  │     │ (入口)    │     │ (放行)   │     │ (排队)    │     │ (工作站)  │
  └──────────┘     └──────────┘     └──────────┘     └──────────┘     └──────────┘
       ↑                                                                   │
       │                              ┌──────────┐     ┌──────────┐        │
       └────────────────────────────  │ 出站读卡  │ ←── │ 出站阀   │ ←──────┘
                                      │ (出口)    │     │ (推回)   │  (操作完成)
                                      └──────────┘     └──────────┘
```

### 3.2 三个读卡器的角色

```
┌───────────────────────────────────────────────────────────────┐
│                       进站读卡器 (Entry)                       │
│  位置: 主轨道到站台的入口                                      │
│  轮询命令: 0x10 0xFF 0x7A                                     │
│  功能:                                                         │
│    1. 读取经过入口的每个衣架 RFID                              │
│    2. 控制器匹配 PC 下发的"本站应接收的衣架清单"                │
│    3. 匹配成功 → 开进站阀，放行衣架进站                        │
│    4. 匹配失败 → 不动作，衣架继续沿主轨道前进                   │
│  关键: 这是一个"过滤器"——只放行属于本站的衣架                   │
├───────────────────────────────────────────────────────────────┤
│                       下放读卡器 (Store/Release)               │
│  位置: 站台内，操作工位上方                                    │
│  轮询命令: 0x10 0xFF 0x75                                     │
│  功能:                                                         │
│    1. 读取到达操作工位的衣架 RFID                              │
│    2. 向 PC 请求"下放授权" (这个衣架可以操作了吗？)             │
│    3. PC 回复 → 控制器驱动提升臂/吊篮放下衣架                  │
│    4. 兼作"员工登录读卡器"——刷员工卡登录/退出工位              │
│  关键: 这是"请求-授权"模型，PC 掌握全局调度权                   │
├───────────────────────────────────────────────────────────────┤
│                       出站读卡器 (Out/Exit)                    │
│  位置: 站台出口，回到主轨道的通道                              │
│  轮询命令: 0x10 0xFF 0x75  (与下放相同命令)                     │
│  功能:                                                         │
│    1. 读取离开站台的衣架 RFID                                  │
│    2. 向 PC 确认"衣架已出站"                                   │
│    3. PC 更新衣架位置，调度下一站                              │
│  注意: 仅在"桥接模式"启用；标准模式可能不需要出站读卡器         │
└───────────────────────────────────────────────────────────────┘
```

### 3.3 控制器轮询策略

```
      ┌────────────────────────────────────────────┐
      │         控制器主循环 (~1ms / ~10ms 周期)     │
      │                                            │
      │  ┌──────────────────────────────────┐      │
      │  │         RFID_Send()               │      │
      │  │  每 300ms 向每个读卡器发送轮询指令  │      │
      │  │  进站: 0x10 0xFF 0x7A             │      │
      │  │  下放: 0x10 0xFF 0x75             │      │
      │  │  出站: 0x10 0xFF 0x75             │      │
      │  └──────────────────────────────────┘      │
      │                    ↓                       │
      │  ┌──────────────────────────────────┐      │
      │  │         RFID_Recv()               │      │
      │  │  解析应答: 提取 4字节卡号(大端)     │      │
      │  │  超时 300ms 无应答 → 判定丢包       │      │
      │  │  超时 1000ms+ → 判定读卡器掉线      │      │
      │  └──────────────────────────────────┘      │
      │                    ↓                       │
      │  ┌──────────────────────────────────┐      │
      │  │        BusinessLogic              │      │
      │  │  进站: 匹配 InTaskList → 开阀      │      │
      │  │  下放: 发 store_RFID_apply → 等授权 │      │
      │  │  出站: 发 out_RFID_apply → 等授权  │      │
      │  └──────────────────────────────────┘      │
      └────────────────────────────────────────────┘
```

### 3.4 S2 与 S3 控制器差异

```
                     S2 (旧版)                      S3 (新版)
                     ────────                      ────────
 MCU               PIC18F97J60                  GD32F407/427/450
 时钟              约 41MHz                     240MHz
 UART 方案         2路原生 + WK2114 SPI扩4路      8路原生UART
 读卡器连接        进站=UART1, 下放=UART2+WK2114  进站=UART0, 下放=UART2, 出站=UART6 (A站)
                   出站=WK2114 CH2               UART4, UART7, UART1 (B站)
 轮询命令          0x10 0xFF 0x7A / 0x75 / 0x3B  0x10 0xFF 0x7A / 0x75 (统一)
 读卡器掉线检测    标志位 + LCD显示              标志位 + UDP上报PC + 操作面板消息
 卡号去重          有(相同ID不重复处理)            有(相同ID不重复处理)
 管理员RFID        3组硬编码管理员卡              无硬编码(由PC统一管理)
 固件升级          通过TCP/IP下载 → IAP写入        通过UDP下载 → W25QXX外置Flash → 分发给各读卡器
 升级分发          仅升级自身控制器                可升级: 控制器自身、面板、读卡器、CAN电机
 高速线模式         有(高速/低速出站)              无(统一由Motion状态机管理)
```

### 3.5 控制器 → PC 通信（读卡器触发的报文）

```
进站读卡器读到卡:
  → 匹配成功: MAIN_COMM_COME_IN_STATION_HANGER_ID (186) — 衣架已进站
      内容: 4空字节 + 4字节卡号
  → 匹配失败: MAIN_COMM_NO_STATION_HANGER_ID (187) — 衣架不在本站任务清单
      内容: 4空字节 + 4字节卡号

下放读卡器读到卡:
  → 请求下放: MAIN_COMM_STORE_HANGER_ID (152) — 请PC授权这个衣架下放
      内容: 1命令字节 + 8字节卡号

出站读卡器读到卡:
  → 确认出站: MAIN_COMM_HANGER_OUT (139) — 衣架已离开本站

读卡器掉线:
  → FALT_READER_LOST — 上报PC + 推送操作面板消息

员工卡:
  → 登录: MAIN_COMM_RFID_LAND (129)
  → 退出: MAIN_COMM_EMP_EXIT (130)
  → 求助: MAIN_COMM_HELP (131)
```

## 四、衣架数据流全景

```
 ┌────────┐     ┌─────────────┐     ┌──────────┐     ┌──────────┐     ┌────────┐

 │         │     │ InTaskList  │     │  读到卡    │     │ 匹配？    │     │ 开/不开 │
 │ 下发:    │     │             │     │            │     │           │     │         │
 │ 哪些衣架  │     │ [ID1,ID2..] │     │ 0x10FF7A   │     │ 在表里→开  │     │         │
 │ 应该进站  │     │             │     │            │     │ 不在→不开  │     │         │
 └────────┘     └─────────────┘     └──────────┘     └──────────┘     └────────┘
                                                                          │(开阀)

                                                                   │  缓冲区   │

                                                                   └────┬─────┘
                                                                        │
 ┌────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐          │
 │ PC服务器 │ ←── │ UDP应答  │ ←── │ 下放读卡器 │ ←── │ 衣架到达  │ ←────────┘
```

## 五、两种站台模式下的读卡器行为差异

### 5.1 标准站模式（普通工作站）

```
 ┌───────────────────────────────────────────────┐
 │               标准站 · 读卡器行为               │
 │                                               │
 │  进站读卡器: 匹配InTaskList → 开进站阀          │
 │  下放读卡器: 读衣架ID → 请求PC授权 → 下放       │
 │             读员工卡 → 登录/退出                │
 │  出站读卡器: (可能不安装/不启用)                 │
 └───────────────────────────────────────────────┘
```

### 5.2 桥接模式（中转/过渡站）

```
 ┌───────────────────────────────────────────────┐
 │               桥接站 · 读卡器行为               │
 │                                               │
 │  进站读卡器: 同标准站                           │
 │  下放读卡器: 读衣架ID → 直接请求PC放行(不倒挂)   │
 │  出站读卡器: 确认衣架离开 → 上报PC              │
 │                                               │
 │  特殊逻辑: 如果进站读卡器损坏，桥接站跳过ID验证   │
 │            直接放行所有衣架(保守安全策略)         │
 └───────────────────────────────────────────────┘
```

## 六、读卡器配置与运维

### 6.1 控制器对读卡器的管理

```
每个读卡器 3 个关键参数:
  ① UART 端口分配 —— 哪个串口接哪个位置的读卡器，存在外置 Flash 中，可动态修改
  ② 监控使能标志 —— 是否监控该读卡器的在线状态
  ③ 掉线检测阈值 —— 连续 1000ms+ 无应答 → 判定掉线 → 上报故障

每个读卡器独立的状态机:
  NORMAL ──超时──→ LOST ──恢复──→ NORMAL
    │                │
    └── 上报PC正常 ──→│←── 上报PC故障 + 推送面板消息
```

### 6.2 固件升级流程

```
  PC ──(UDP)──→ 控制器 ──(存储到W25QXX Flash)──→ 分发升级

                    ├──→ 升级控制器自身  (IAP，写内部Flash)
                    ├──→ 升级读卡器     (通过UART，0x55帧协议)
                    ├──→ 升级操作面板   (通过UART)
                    └──→ 升级CAN电机    (通过CANopen)
```

## 七、S2 特有功能（旧版存在、新版可能继承）

```
  高速线模式 (High Line Mode):
    快速出站: 进站读到就推 → 不等操作
    慢速出站: 进站读到后蜂鸣器提示 → 等操作完成后出站

  管理员 RFID 卡 (硬编码3组):
    用于调试/维护模式，刷管理卡可进入后台功能

  低频/高频双读系统:
    某些旧站可能同时装有高频(13.56MHz)和低频(125kHz)读卡器
    控制器需同时处理两种协议的应答

  按键矩阵扫描:
    30键矩阵(F1-F6, 0-9, 方向, 确认, 取消等)，操作面板独立管理

  LCD 显示:
    文本模式液晶屏，支持中文字符，显示衣架信息/故障信息/操作提示
```

## 八、S3 特有功能（新版新增、重构关注点）

```
  8路原生UART:
    不再依赖WK2114 SPI扩串口，每路独立DMA收发

  CAN 总线电机控制:
    主轨道电机通过 CANopen 协议控制
    可读电机参数: 转速、电流、运行状态、故障码、电压

  多读卡器冲突检测:
    RFID_Used[] 数组追踪每个UART是否已被分配给读卡器
    避免同一UART被两个读卡器占用

  操作面板消息队列:
    30+ 种消息类型，队列化推送，支持超时自动消失
    读卡器掉线消息(进站/下放)均通过此机制通知操作员

  网络远程升级:
    通过 UDP 下载固件 → W25QXX 外置 Flash 暂存
    → 校验通过 → 分发给目标设备(控制器/读卡器/面板/电机)
    升级状态全程上报 PC

  读卡器重连检测:
    掉线恢复时自动上报 PC (SendFault 清零)
```

## 九、重构要点汇总

重构新读卡器 / 新控制器时，需要实现的核心行为：

### A. 读卡器端 (Reader)

| # | 必须实现 |
|---|---------|
| 1 | 125kHz 载波产生 + EM4100/EM4102 曼彻斯特解码 |
| 2 | 四重校验(头/行/列/停止位) + 全零过滤 |
| 3 | 3字节轮询协议: `0x10 0xFF 0xXX` → 应答卡号或Fail |
| 4 | 7条指令全部支持 (0x7A/0x75/0x9A/0x95/0x9D/0x90/复位) |
| 5 | 3种工作模式 (默认/校验/连续)，模式切换绿灯闪烁 |
| 6 | 双次上报 (100ms重复防丢) + TX忙时拒绝指令 |
| 7 | 绿灯(有卡) + 红灯(状态) 行为规范 |
| 8 | 50ms 系统节拍基准 |
| 9 | 看门狗 (~106ms) |
| 10 | 远程升级 (0x55帧协议, CRC16-USB, 密钥"603337")

### B. 控制器端 (Controller)

| # | 必须实现 |
|---|---------|
| 1 | 每300ms向每个读卡器发送轮询 |
| 2 | 解析应答: 7/8/9字节，提取4字节卡号(大端) |
| 3 | 进站: 卡号匹配InTaskList → 开进站阀 / 不匹配 → 放过 |
| 4 | 下放: 卡号 → 请求PC授权 → 授权后驱动下放机构 |
| 5 | 出站: 卡号 → 确认出站 → 上报PC |
| 6 | 员工卡识别: 刷员工卡 → 登录/退出/求助 |
| 7 | 读卡器掉线检测 (1000ms+无应答) → 上报故障 |
| 8 | 读卡器UART端口可配置 (存入非易失存储) |
| 9 | 升级分发: 控制器接收固件 → 分发给读卡器 |

## 十、测试验收清单

### 读卡器基础
- [ ] 有卡靠近 → 绿灯亮，无卡 → 绿灯灭
- [ ] 卡号上报格式: `0x10 0xFF 0x05` + 4字节卡号(大端)
- [ ] 同一张卡不重复上报（模式3除外）
- [ ] 换另一张卡 → 立即上报新卡号
- [ ] 非法卡（校验失败/全零）→ 不上报

### 协议交互
- [ ] 0x7A / 0x75 轮询 → 正常应答
- [ ] 0x9A / 0x95 轮询 → 应答带BCC(最后字节=XOR)
- [ ] 0x9D → 连续发送，红灯常亮
- [ ] 0x90 → 返回版本号
- [ ] 无卡时 → 应答 "Fail"
- [ ] TX忙时不响应后续指令
- [ ] 100ms内收到第二次卡 → 第二次上报

### 模式切换
- [ ] 进站切下放 → LED闪2次，方向更新
- [ ] 切到校验模式 → LED闪4次，数据带BCC
- [ ] 切到连续模式 → LED闪6次，红灯常亮

### 掉线恢复
- [ ] 断掉读卡器 → 控制器判定掉线 → 上报PC
- [ ] 重接读卡器 → 控制器判定恢复 → 清故障

### 固件升级
- [ ] 0x81 启动升级 → 进入升级状态
- [ ] 0x82 顺序发包 → 接收成功
- [ ] 0x82 包序号跳跃 → 忽略
- [ ] 0x83 查询结果 → 返回成功/失败
- [ ] CRC16校验 → 正确
- [ ] 上电检测上次升级结果 → 上报

### 系统联调
- [ ] 进站读卡器 → 匹配任务表 → 开阀放行
- [ ] 进站读卡器 → 不匹配 → 衣架放行(不开阀)
- [ ] 下放读卡器 → 读衣架 → 请求PC → 授权后下放
- [ ] 下放读卡器 → 读员工卡 → 登录/退出
- [ ] 出站读卡器 → 确认出站 → 上报PC
- [ ] 桥接模式 → 进站读卡器损坏 → 直接放行

### 鲁棒性
- [ ] 看门狗超时 → MCU 复位
- [ ] 格式错误的轮询帧 → 不崩溃，正常工作
- [ ] 干扰/非法卡片 → 正确拒绝
- [ ] 连续快速刷卡 → 不丢卡不重复
- [ ] 多读卡器同时工作 → 互不干扰
