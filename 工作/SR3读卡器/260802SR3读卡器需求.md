# SR3 读卡器功能需求文档（重构用）

> 本文档仅描述"这个读卡器要做什么"，不涉及代码、MCU 型号、具体实现方式。
> 用于新的框架/平台下重构或测试验收。

## 1. 设备概述

**产品定位：** 125kHz RFID 读卡器，用于服装吊挂/立杆输送系统，读取衣架上的 RFID 标签（卡号），通过串口上报给上位机。

**硬件组成：**
- 一颗 MCU
- 一颗 EM4095 125kHz RFID 基站芯片
- 一颗绿色 LED（有卡指示）
- 一颗红色 LED（状态/错误/连续模式指示）
- 一路 UART 串口（与上位机通信）

**工作流程：**
- 上电后持续产生 125kHz 载波，等待 RFID 标签进入感应范围
- 检测到标签后，解码卡号，通过 UART 上报
- 根据上位机指令切换工作模式/方向

---

## 2. RFID 读卡功能

### 2.1 载波产生
- 频率：**125kHz** 方波
- 持续产生，设备上电即开始

### 2.2 标签类型
- **EM4100 / EM4102** 兼容（EM4001 系列）
- 调制方式：**曼彻斯特编码**（Manchester encoding）
- 数据格式：**64 位**
  - 9 位头部（全 1）
  - 40 位数据（10 行 × 4 位，每行附带 1 位行校验）
  - 4 位列校验位
  - 1 位停止位（必须为 0）

### 2.3 解码校验规则
- **头部校验：** 前 9 位必须全为 1，否则丢弃
- **行校验：** 10 行数据，每行 4 位 + 1 位奇校验（奇数校验），任一行不通过则丢弃
- **列校验：** 4 列数据，每列 10 位 + 1 位奇校验，任一列不通过则丢弃
- **停止位校验：** 第 64 位必须为 0，否则丢弃
- **全零过滤：** 5 字节卡号全为 0x00 时不上报
- 任何校验不通过 → 复位解码状态机，重新开始读

### 2.4 卡号提取
- 从 64 位数据中提取 40 位有效数据
- 组装为 **5 字节卡号**

### 2.5 卡号变化检测
- 每次解码成功后与上一次卡号比较
- **相同卡号：** 不重复触发上报（模式 3 除外）
- **不同卡号：** 标记为新卡，触发上报流程

---

## 3. EM4095 基站芯片控制

### 3.1 控制信号

| 信号 | 方向 | 功能 |
|------|------|------|
| SHD（开关） | MCU 输出 | 高电平 = 关闭芯片，低电平 = 使能芯片 |
| DEMOD_OUT（解调数据） | MCU 输入 | 曼彻斯特编码的位流数据 |

### 3.2 初始化时序
- 上电后 SHD 拉高 **50ms**
- 然后 SHD 拉低 → 芯片开始工作，产生 125kHz 载波

### 3.3 曼彻斯特解码（边沿检测）
- 监控 DEMOD_OUT 引脚的电平跳变
- 测量相邻两次跳变之间的时间间隔（脉宽）
- 脉宽分两档：
  - **窄脉冲（类型1）：** 约 160~328 μs
  - **宽脉冲（类型2）：** 约 328~656 μs
- 脉宽超出范围 → 复位解码器，重新开始
- 按曼彻斯特规则从脉冲序列中还原 64 位原始数据

---

## 4. 工作模式

设备有 **3 种工作模式**，通过上位机指令切换：

### 4.1 模式 1 — 默认模式（进站/下放）
- **触发指令：** `0x7A`（进站）或 `0x75`（下放）
- **上电默认：** 模式 1 + 进站方向
- **卡号上报格式：** 8 字节固定长度
- **上报策略：**
  - 第一次读到卡 → 立即上报
  - 间隔 ~100ms → 第二次上报（同一卡号，防丢）
  - 之后 ~50ms 冷却 → 等待下次读卡或指令
- **方向标识：** 进站 = `0x55`，下放 = `0xAA`

### 4.2 模式 2 — 校验模式
- **触发指令：** `0x9A`（进站校验）或 `0x95`（下放校验）
- **卡号上报格式：** 9 字节（8 字节数据 + 1 字节 BCC 校验）
- **上报策略：** 同模式 1（立即 + 100ms 重复 + 50ms 冷却）
- **BCC 算法：** 对全部数据字节依次做异或（XOR）

### 4.3 模式 3 — 连续发送模式
- **触发指令：** `0x9D`
- **行为：**
  - 有卡：每 ~100ms 上报一次卡号
  - 无卡：每 ~500ms 上报一次失败包
  - 只要有卡在感应范围内就一直发送
- **LED：** 红灯常亮
- **卡号格式：** 同模式 1（8 字节，无 BCC）
- **失败包格式：** 发送 "Fail" 错误包

## 5. 通信协议（UART 串口）

### 5.1 物理层

| 参数 | 值 |
|------|-----|
| 波特率 | **19200 bps** |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 |
| 流控 | 无 |

### 5.2 上位机 → 读卡器（指令帧）

格式：`0x10` + `0xFF` + 命令字节（3 字节）

| 命令字节 | 功能 | 切换模式？ |
|----------|------|-----------|
| `0x7A` | 进站（Entry） | → 模式 1，方向 = 进站 |
| `0x75` | 下放（Release） | → 模式 1，方向 = 下放 |
| `0x9A` | 进站校验（Entry+BCC） | → 模式 2，方向 = 进站 |
| `0x95` | 下放校验（Release+BCC） | → 模式 2，方向 = 下放 |
| `0x9D` | 连续发送 | → 模式 3 |
| `0x90` | 查询固件版本 | 不切换模式 |
| `0xA0 0x05` | 系统复位 | 软件复位 |

### 5.3 读卡器 → 上位机（应答帧）

#### 模式 1 / 模式 3 — 卡号包（8 字节）
```
0x10  0xFF  0x05  CardData[3]  CardData[4]  CardData[5]  CardData[6]  CardData[7]
```

#### 模式 2 — 卡号包 + BCC（9 字节）
```
0x10  0xFF  0x05  CardData[3]  CardData[4]  CardData[5]  CardData[6]  CardData[7]  BCC
```

#### 模式 1 / 模式 3 — 失败包（7 字节）
```
0x10  0xFF  0x04  'F'  'a'  'i'  'l'
```

#### 模式 2 — 失败包 + BCC（8 字节）
```
0x10  0xFF  0x04  'F'  'a'  'i'  'l'  BCC
```

#### 版本查询应答（10 字节）
```
0x10  0xFF  0x01  0x56  0x65  0x72  0x30  0x33  0x31  0x30
```
即 ASCII：`"Ver0310"`

### 5.4 指令冲突保护
以下情况下读卡器**不应响应**上位机指令：
- 正在串口发送中（TX busy）
- 处于卡号二次上报的 100ms 等待期内

## 6. 远程固件升级（Bootloader）

### 6.1 升级帧格式
```
帧头:   0x55
CMD:    1 字节（> 0x80）
Len:    2 字节（小端）
PackNo: 2 字节
Data:   变长（最大 256 字节）
CRC16:  2 字节
帧尾:   0xAA
```

### 6.2 升级指令

| CMD | 名称 | 说明 |
|-----|------|------|
| `0x81` | 启动升级 | 上位机发起固件升级流程 |
| `0x82` | 文件数据包 | 传输固件数据块，包序号必须连续（递增1） |
| `0x83` | 查询升级结果 | 上位机查询升级成败 |

### 6.3 升级状态机
```
空闲(sInit) → 接收中(sRecive) → 更新中(sUpdate) → 等待结果(sWaitRes) → 完成(sFinish)/失败(sFail)
```

### 6.4 升级应答

| 场景 | 上位机收到的应答 |
|------|-----------------|
| 上次升级成功 | 版本号 + `uOK`(0xAA) |
| 上次升级失败 | 版本号 + `uFail`(0x55) |

### 6.5 CRC 校验
- 算法：**CRC16-USB**
- 多项式：`0x8005`

### 6.6 安全
- 固件数据使用密钥 `"603337"`（6 字节）加密
- 上电时检测升级标志位，如有未完成的升级结果则上报给上位机

### 6.7 超时与重试
- 单次升级操作超时
- 等待指令超时
- 包重发次数：最多 5 次

## 7. LED 指示规范

| LED | 颜色 | 驱动方式 | 含义 |
|-----|------|----------|------|
| LEDG | 绿色 | 低电平点亮 | 读卡成功 / 卡在感应范围内 |
| LEDR | 红色 | 低电平点亮 | 状态 / 错误 / 连续模式指示 |

### 7.1 各模式 LED 行为

| 模式 | 绿灯 | 红灯 |
|------|------|------|
| 模式 1（进站/下放） | 有卡亮、无卡灭 | 绿灯灭时亮、绿灯亮时灭（与绿灯互斥） |
| 模式 2（校验） | 同模式 1 | 同模式 1 |
| 模式 3（连续发送） | 有卡亮、无卡灭 | **常亮** |

### 7.2 模式切换 LED 提示
模式切换时绿灯闪烁：

| 切换到的模式 | 绿灯闪烁次数 |
|-------------|-------------|
| 模式 1 | 2 次 |
| 模式 2 | 4 次 |
| 模式 3 | 6 次 |

- 闪烁速度：每 ~200ms 翻转一次（同一开一关为一个闪烁周期的一半）

### 7.3 读卡成功指示
- 模式 1/2：读到卡后绿灯亮起，若无新卡则约 **200ms** 后自动熄灭

### 7.4 特殊：立杆读卡器小车模式
- 触发条件：卡号字节 [5]=0x00, [6]=0x00, [7]=0x5A 时（特殊"黑卡"）
- 行为：两灯均灭 → 约 **300ms** 后两灯同时亮起

## 8. 系统定时基准

设备需要一个周期性的系统节拍，建议 **50ms** 周期。

所有定时基于 50ms 节拍的倍率计算：

| 定时项目 | 时长 |
|----------|------|
| 读卡成功 LED 超时 | 200ms（4 个 tick） |
| 第二次卡号上报延迟 | 100ms（2 个 tick） |
| 连续模式有卡上报周期 | ~100ms（2 个 tick） |
| 连续模式无卡上报周期 | ~500ms（10 个 tick） |
| 模式切换 LED 闪烁半周期 | ~200ms（4 个 tick） |
| 立杆小车 LED 延迟 | ~300ms（6 个 tick） |
| EM4095 初始化稳定时间 | 50ms |

## 9. 看门狗

- 独立看门狗（IWDT），超时时间约 **106ms**
- 主循环中周期性喂狗
- 超时 → 芯片硬件复位

## 10. 错误处理清单

| 错误场景 | 行为 |
|----------|------|
| 无卡在感应范围内 | 发送 "Fail" 错误包 |
| 卡头部校验失败 | 复位解码器，重新开始读 |
| 行校验失败 | 复位解码器，重新开始读 |
| 列校验失败 | 复位解码器，重新开始读 |
| 停止位错误 | 复位解码器，重新开始读 |
| 卡号全零 | 不上报，LED 熄 |
| 脉宽超出合法范围 | 复位解码计数器 |
| 上位机指令帧头缺失 | 解析错误码 1 |
| 指令 CMD 无效 | 解析错误码 2 |
| 帧尾缺失 | 解析错误码 3 |
| 数据长度超限 | 解析错误码 4 |
| CRC16 不匹配 | 解析错误码 5 |
| 升级包序号不连续 | 忽略该包 |
| TX 忙时收到指令 | 静默忽略，不应答 |
| 看门狗超时 | MCU 硬件复位 |

## 12. 中断优先级建议（从高到低）

|--------|--------|------|
| 最高 (0) | 50ms 定时器 | 系统节拍基准 |
| 1 | 125kHz 定时器 | 载波产生 + 曼彻斯特边沿捕获 |
| 2（最低） | UART 接收 | 上位机指令接收 |

## 13. 上电启动流程

1. 初始化时钟（48MHz 系统时钟）
2. 配置 GPIO（LED、EM4095 控制线、UART）
3. 初始化 UART（19200-8-N-1）
4. 初始化 125kHz 载波定时器
5. 初始化 50ms 系统节拍定时器
6. 配置并启动独立看门狗（~106ms）
7. 初始化 EM4095（SHD 高 50ms → 拉低使能）
8. 检测是否有未完成的固件升级结果，如有则上报
9. 进入主循环：读卡 → 解码 → 上报 → 接收指令 → 喂狗

---

## 14. 主循环功能要点

- 持续监控 DEMOD_OUT 引脚的边沿事件（由 125kHz 定时器 ISR 捕获）
- 曼彻斯特解码状态机 → 校验 → 提取卡号
- 卡号变化检测
- 根据当前模式决定上报时机和格式
- 接收 UART 指令帧（`0x10 0xFF xx`）
- 指令解析与模式切换
- LED 状态更新（基于定时器）
- 喂狗

## 15. 测试验收清单

### 基本读卡
- [ ] 有卡靠近 → 绿灯亮，无卡 → 绿灯灭
- [ ] 卡号上报格式正确（8 字节：0x10 0xFF 0x05 + 5字节卡号）
- [ ] 同一张卡不重复上报（除模式3外）
- [ ] 换另一张卡 → 立即上报新卡号

### 双次上报
- [ ] 模式 1/2：读卡后约 100ms 自动第二次上报（防丢）
- [ ] 上报期间收到指令 → 不理睬

### 模式切换
- [ ] 0x7A → 模式 1 进站，绿灯闪 2 次
- [ ] 0x75 → 模式 1 下放，绿灯闪 2 次
- [ ] 0x9A → 模式 2 进站校验，绿灯闪 4 次
- [ ] 0x95 → 模式 2 下放校验，绿灯闪 4 次
- [ ] 0x9D → 模式 3 连续发送，绿灯闪 6 次，红灯常亮

### BCC 校验
- [ ] 模式 2：卡号包第 9 字节 = 前 8 字节 XOR 结果
- [ ] 模式 2：失败包第 8 字节 = 前 7 字节 XOR 结果

### 连续模式
- [ ] 有卡：每 ~100ms 上报
- [ ] 无卡：每 ~500ms 上报 "Fail"
- [ ] 红灯始终亮

### 版本查询
- [ ] 0x90 → 返回 "Ver0310"

### 错误卡
- [ ] 非法卡（校验失败、全零） → 不上报
- [ ] 无卡时 0x7A 指令 → 返回 "Fail"

### 固件升级
- [ ] 0x81 启动升级 → 进入升级模式
- [ ] 0x82 传输数据 → 包序号连续有效
- [ ] 0x82 包序号跳跃 → 忽略
- [ ] 0x83 查询结果 → 返回成功/失败
- [ ] CRC16 校验正确
- [ ] 升级超时处理
- [ ] 上电检测上次升级结果并上报

### 鲁棒性
- [ ] 看门狗未喂 → 系统复位
- [ ] 格式错误的指令帧 → 不崩溃，正常工作
- [ ] 干扰卡片 → 正确拒绝
