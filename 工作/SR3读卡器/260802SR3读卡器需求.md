# SR3 读卡器 —— 行为全景图

> 你一页一页往下看就行。每张图解释一个概念，从最简单的问题开始。

---

## 〇、读卡器到底是什么

读卡器就是一个串在衣架轨道上的小盒子：

```
┌─────────────────────────────────────────────────────┐
│                    主轨道 (衣架在走)                  │
│  ═══════════════════════════════════════════════════  │
│       ↓ 衣架滑过来                                   │
│  ┌─────────┐                                        │
│  │ 读卡器   │ ← UART 一根线连到控制器                  │
│  │ 125kHz  │   19200-8-N-1                           │
│  │ 线圈    │                                         │
│  └─────────┘                                        │
│       ↓ 读到标签卡号                                  │
│  控制器收到卡号 → 决定要不要放行                        │
└─────────────────────────────────────────────────────┘
```

**核心任务只有一个：** 衣架经过时，读出它身上的 RFID 标签卡号，告诉控制器。

```mermaid
sequenceDiagram
    participant 衣架 as 🏷️ 衣架标签
    participant 读卡器 as 📡 读卡器
    participant 控制器 as 🖥️ 控制器

    衣架->>读卡器: 滑入感应区
    读卡器->>读卡器: 125kHz 激活标签 → 曼彻斯特解码 → 算出卡号
    读卡器->>控制器: UART: 0x10 0xFF 0x05 + 卡号 (8字节)
    控制器->>控制器: 查任务清单 → 匹配就开闸门放行
```

---

## 一、读卡器怎么"读"到卡号（解码全链路）

这是读卡器上电后**一直在做**的事，不需要上位机叫它才做。

```mermaid
flowchart TB
    载波["① 产生 125kHz 载波<br/>EM4095 芯片, 上电就不停"] --> 跳变["② 检测 DEMOD_OUT 引脚跳变<br/>每 125kHz 周期 (8us) 查一次<br/>宽脉冲 ≈ 2bit · 窄脉冲 ≈ 1bit"]
    跳变 --> 曼彻斯特["③ 曼彻斯特解码<br/>跳变方向决定 0/1<br/>64 位凑齐 → decode_end_flag=1"]
    曼彻斯特 --> 校验["④ 五道校验<br/>停止位 → 行奇偶(10行) → 列奇偶(4列)<br/>→ 非全零 → 提取卡号"]
    校验 --> 卡号["⑤ 5 字节卡号<br/>FirstLu_Kahao_buffer[3..7]"]
    卡号 --> 比较{"⑥ 跟上次一样吗?<br/>vs FirstLu_Kahao_buffer2"}
    比较 -->|"不同(新卡)"| 上报["⑦ 立即 UART 上报！"]
    比较 -->|"相同"| 跳过["跳过 (同一张卡还在)"]

    style 载波 fill:#e8f5e9,stroke:#50B86C
    style 上报 fill:#D94A4A,color:#fff
    style 跳过 fill:#999,color:#fff
```

**关键点：** 第⑥⑦步——读到新卡号就立刻上报，**不等待上位机来问**。

## 二、主动 vs 被动：谁先动

这是最容易搞混的地方。读卡器和上位机**各干各的**，不是一问一答。

```mermaid
sequenceDiagram
    participant 读卡器
    participant 上位机

    Note over 读卡器: ═══ 主动行为（一直跑，不停） ═══
    rect rgb(232, 245, 233)
        读卡器->>读卡器: 125kHz 载波 + 解码 + 校验
        读卡器->>读卡器: 检测到新卡 → 立即上报！
        Note over 读卡器: 不管上位机在干嘛，先发再说
    end

    Note over 上位机,读卡器: ═══ 被动行为（上位机来问才答） ═══
    rect rgb(227, 242, 253)
        上位机->>读卡器: 0x7A (进站轮询)
        读卡器->>上位机: Fail (心跳确认)
        上位机->>读卡器: 0x75 (下放轮询)
        读卡器->>上位机: 有卡→卡号 / 无卡→Fail
    end
```

**一句话总结：**
- **主动 = 读卡器自己发现新卡，自己上报**（不等任何人）
- **被动 = 上位机来问"你还在吗？什么模式？"，读卡器回答**
- 上位机的轮询**不是**用来取卡号的——卡号早就主动上报过了。轮询只是心跳 + 模式管理。

## 三、进站 vs 下放：同样的新卡，不同的处理

一张卡进入感应区，读卡器的反应取决于它被设成了**进站方向**还是**下放方向**。

### 3.1 进站方向 (Send_Manner = 0x55)

衣架从主轨道滑进工位——需要确保上位机**一定收到**卡号，所以多发一次：

```mermaid
sequenceDiagram
    participant 标签
    participant 读卡器
    participant 上位机

    标签->>读卡器: 进入感应区
    读卡器->>读卡器: 解码: 卡号=0xAABBCCDDEE

    rect rgb(255, 235, 238)
        Note over 读卡器: 🔴 触发立即上报
        读卡器->>上位机: 第1次: 0x10 0xFF 0x05 AA BB CC DD EE
    end

    rect rgb(255, 243, 224)
        Note over 读卡器: 🟠 Read_card_100ms_flag=1<br/>开始计时 100ms
        Note over 读卡器: ...100ms 后...
        读卡器->>上位机: 第2次: 0x10 0xFF 0x05 AA BB CC DD EE
        Note over 读卡器: 🟡 进入 50ms 冷却<br/>期间忽略上位机指令
    end

    rect rgb(232, 245, 233)
        Note over 读卡器: 🟢 冷却结束，恢复正常
        上位机->>读卡器: 0x7A (进站轮询)
        读卡器->>上位机: Fail 7字节 (心跳)
    end
```

**为什么发两次？** 进站是关键动作——衣架要进工位了。两次发送间隔 100ms，确保上位机在轮询间隙也能收到。

**为什么冷却 50ms？** 防止二次发送还没完成就被上位机的轮询打断。

### 3.2 下放方向 (Send_Manner = 0xAA)

衣架在工位上操作完了，要放回主轨道——发一次就够了：

```mermaid
sequenceDiagram
    participant 标签
    participant 读卡器
    participant 上位机

    标签->>读卡器: 进入感应区
    读卡器->>读卡器: 解码: 卡号=0xAABBCCDDEE

    rect rgb(255, 235, 238)
        Note over 读卡器: 🔴 触发立即上报
        读卡器->>上位机: 仅1次: 0x10 0xFF 0x05 AA BB CC DD EE
    end

    rect rgb(232, 245, 233)
        Note over 读卡器: 🟢 没有二次发送，没有冷却<br/>立刻可以响应指令
        上位机->>读卡器: 0x75 (下放轮询)
        读卡器->>上位机: 0x10 0xFF 0x05 AA BB CC DD EE (有卡)
    end
```

**为什么只发一次？** 下放不像进站那么关键。而且上位机可以通过 0x75 随时查询。

## 四、三种模式：一张表看懂

三种模式的区别，核心就三个维度：**上报方式、数据格式、LED**。

```mermaid
flowchart TB
    subgraph M1["模式 1 —— 默认 (上电就是它)"]
        direction LR
        M1_1["上报: 新卡立即发<br/>+ 进站二次发"]
        M1_2["格式: 无 BCC<br/>8 字节"]
        M1_3["LED: 绿灯=有卡<br/>红灯=绿灯取反"]
        M1_4["轮询: 0x7A/0x75"]
    end

    subgraph M2["模式 2 —— 加校验"]
        direction LR
        M2_1["上报: 同模式1<br/>新卡立即发 + 进站二次发"]
        M2_2["格式: 有 BCC<br/>9 字节"]
        M2_3["LED: 同模式1<br/>闪烁 4 次 vs 2 次"]
        M2_4["轮询: 0x9A/0x95"]
    end

    subgraph M3["模式 3 —— 连续发"]
        direction LR
        M3_1["上报: 不等新卡<br/>有卡每 100ms 发<br/>无卡每 500ms 发"]
        M3_2["格式: 有 BCC<br/>9 字节"]
        M3_3["LED: 红灯常亮<br/>250ms 无卡绿灯灭"]
        M3_4["轮询: 不处理<br/>0x7A/0x75 退出"]
    end

    M1 -->|"0x9A/0x95"| M2
    M2 -->|"0x7A/0x75"| M1
    M1 -->|"0x9D"| M3
    M2 -->|"0x9D"| M3
    M3 -->|"0x7A/0x75/0x9A/0x95"| M1

    style M1 fill:#e8f5e9,stroke:#50B86C
    style M2 fill:#fff3e0,stroke:#FF9800
    style M3 fill:#e3f2fd,stroke:#2196F3
```

**一句话区分：**
- 模式 1 = 有卡才发，发完就停
- 模式 2 = 有卡才发 + 数据末尾加 BCC 校验
- 模式 3 = 不管有没有卡，一直发（像心跳一样）

### 4.1 模式 3 的工作方式

模式 3 最特殊——它不依赖"新卡出现"这个事件，而是**定时器到了就发**：

```mermaid
sequenceDiagram
    participant 定时器 as ⏱️ 50ms 定时器
    participant 读卡器
    participant 上位机

    Note over 读卡器: 进入模式 3

    rect rgb(232, 245, 233)
        Note over 读卡器: 有卡时:
        定时器->>读卡器: 100ms (2 tick)
        读卡器->>上位机: 卡号 9字节 (含BCC)
        定时器->>读卡器: 又 100ms
        读卡器->>上位机: 卡号 9字节 (含BCC)
        定时器->>读卡器: 又 100ms
        读卡器->>上位机: 卡号 9字节 (含BCC)
    end

    rect rgb(255, 243, 224)
        Note over 读卡器: 卡离开了，变成无卡:
        定时器->>读卡器: 250ms (5 tick) → 绿灯灭
        定时器->>读卡器: 500ms (10 tick)
        读卡器->>上位机: Fail 8字节 (含BCC)
        定时器->>读卡器: 又 500ms
        读卡器->>上位机: Fail 8字节 (含BCC)
    end
```

**适用场景：** 需要实时知道工位上有没有衣架的场合。上位机不用轮询，读卡器自己会一直报。

## 五、上位机 7 条命令速查

读卡器不是主动发完就完了——上位机也会发命令过来。这些命令**全部是被动响应**。

```mermaid
flowchart LR
    subgraph 命令["上位机 → 读卡器"]

        C1["0x7A 进站心跳"]
        C2["0x75 下放查询"]
        C3["0x9A 进站+BCC"]
        C4["0x95 下放+BCC"]
        C5["0x9D 连续模式"]
        C6["0x90 查版本"]
        C7["0xA0 0x05 复位"]
    end

    subgraph 响应["读卡器 → 上位机"]
        direction TB
        R1["Fail 7字节"]
        R2["有卡→卡号8字节<br/>无卡→Fail 7字节"]
        R3["Fail 8字节(含BCC)"]
        R4["有卡→卡号9字节(含BCC)<br/>无卡→Fail 8字节(含BCC)"]
        R5["不应答<br/>进入自主上报"]
        R6["Ver0310 10字节"]
        R7["无应答<br/>直接复位"]
    end

    命令 --> 响应

    style C1 fill:#e8f5e9,stroke:#50B86C
    style C2 fill:#e8f5e9,stroke:#50B86C
    style C3 fill:#fff3e0,stroke:#FF9800
    style C4 fill:#fff3e0,stroke:#FF9800
    style C5 fill:#e3f2fd,stroke:#2196F3
    style C6 fill:#f3e5f5,stroke:#9C27B0
    style C7 fill:#ffebee,stroke:#f44336
```

### 忙保护（重要！）

读卡器正在发送卡号（或处在进站冷却期）时，上位机发命令过来会被**静默忽略**：

```mermaid
flowchart TD
    命令来["上位机发来 0x7A 或 0x75"] --> 检查{"Read_card_100ms_flag != 0<br/>或 B_TX1_Busy != 0 ?"}

    检查 -->|"是, 正忙"| 忽略["静默忽略<br/>不回应任何东西<br/>上位机下次轮询再说"]
    检查 -->|"否, 空闲"| 正常["正常处理 + 应答"]

    style 忽略 fill:#999,color:#fff
    style 正常 fill:#50B86C,color:#fff
```

**为什么这样设计？** 卡号上报是最高优先级。如果正在发卡号时被打断去响应轮询，上位机可能收到半个包，解析出错。宁可这次不答，等上位机下次再问。

## 六、一个完整场景：衣架进站全过程

把所有概念串起来，看一个衣架从进入感应区到上位机做出决定的完整流程：

```mermaid
sequenceDiagram
    participant 衣架 as 🏷️ 衣架 (卡号0xAABBCCDDEE)
    participant 读卡器 as 📡 读卡器 (模式1, 进站)
    participant 控制器 as 🖥️ 控制器
    participant PC as 🖧 PC 服务器

    Note over 读卡器: ═══ 后台一直跑: 125kHz + 解码 ═══

    rect rgb(255, 235, 238)
        衣架->>读卡器: ① 滑入感应区 (物理靠近)
        读卡器->>读卡器: ② 解码 → 校验通过<br/>卡号=AABBCCDDEE
        读卡器->>读卡器: ③ 跟上次不一样! → 新卡!
        读卡器->>控制器: ④ 立即上报!<br/>0x10 0xFF 0x05 AA BB CC DD EE
        Note over 读卡器: 不等轮询, 先发再说
    end

    rect rgb(232, 245, 233)
        控制器->>控制器: ⑤ 收到卡号<br/>查 InTaskList
        控制器->>PC: ⑥ CMD 186: 衣架进站 AA BB CC DD EE
        PC->>控制器: ⑦ 匹配! 可以放行
        控制器->>控制器: ⑧ 开进站阀门
    end

    rect rgb(255, 243, 224)
        Note over 读卡器: ⑨ 100ms 后...
        读卡器->>控制器: ⑩ 二次上报<br/>0x10 0xFF 0x05 AA BB CC DD EE
        Note over 读卡器: ⑪ 50ms 冷却
    end

    rect rgb(227, 242, 253)
        控制器->>读卡器: ⑫ 0x7A (心跳轮询)
        读卡器->>控制器: ⑬ Fail (确认还在)
    end

    Note over 衣架,PC: ✅ 衣架进入工位, 开始操作
```

**理解这个流程的关键：** 第④步是读卡器**自己**发的，不是控制器⑫步问出来的。控制器的轮询在第⑫步才来——那时候衣架早就决定放行了。

## 七、数据包格式速查

所有 UART 通信都是 19200-8-N-1。

### 卡号包

```
模式 1:
┌──────┬──────┬──────┬──────────────────────────┐
│ 0x10 │ 0xFF │ 0x05 │ 5 字节卡号 (大端)          │
│ 帧头  │ 帧头  │ 长度  │ Card[3] Card[4]...Card[7]│
└──────┴──────┴──────┴──────────────────────────┘
  8 字节，无 BCC

模式 2 / 模式 3:
┌──────┬──────┬──────┬──────────────────────────┬─────┐
│ 0x10 │ 0xFF │ 0x05 │ 5 字节卡号 (大端)          │ BCC │
│ 帧头  │ 帧头  │ 长度  │ Card[3] Card[4]...Card[7]│ XOR │
└──────┴──────┴──────┴──────────────────────────┴─────┘
  9 字节，BCC = 所有前 8 字节 XOR
```

### Fail 包

```
模式 1:
┌──────┬──────┬──────┬───┬───┬───┬───┐
│ 0x10 │ 0xFF │ 0x04 │ F │ a │ i │ l │
└──────┴──────┴──────┴───┴───┴───┴───┘
  7 字节，无 BCC

模式 2 / 模式 3:
┌──────┬──────┬──────┬───┬───┬───┬───┬─────┐
│ 0x10 │ 0xFF │ 0x04 │ F │ a │ i │ l │ BCC │
└──────┴──────┴──────┴───┴───┴───┴───┴─────┘
  8 字节，BCC = 前 7 字节 XOR
```

## 十、控制器怎么用读卡器

```mermaid
flowchart TD
    主轨道["主轨道衣架流动"] --> 进站["进站读卡器<br/>方向=0x55<br/>读到新卡→自动上报"]

    进站 --> 匹配{"控制器查任务清单<br/>这个衣架要来这个工位吗?"}
```
