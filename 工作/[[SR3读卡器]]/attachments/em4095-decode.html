🔍 EM4095 解码状态机

Idle 空闲 Seek 搜前导 Receive 接收 Verify 校验 CardIn 事件 CardOut 事件
I Idle · 空闲
  • 监听 GTIM 边沿捕获
  • base_us = 256µs (默认)
  • 等待 LONG + 下降沿
S SeekPreamble · 搜前导
  • 计数交替 SHORT 边沿
  • 方向不交替 → 回 Idle
  • 非SHORT → 回 Idle (容错3)
  • ≥16 交替 SHORT → 测 base_us
R Receive · 接收
  • 预填 9-bit 帧头 = 1
  • need_skip 相位跟踪
  • 下降沿 → bit=1, 上升沿→bit=0
  • 边沿记录到 Ring Buffer (16条)
  • 满 64-bit → 校验
  • Debris/Ambig → err++ ≥3 → Idle
V Verify · 校验
  • 停止位 = 0
  • 帧头 9-bit 全为 1
  • 10 行偶校验通过
  • 4 列偶校验通过
✓ 全过 → 提取 5 字节卡号
✗ 失败 → 回放 Ring Buffer → Idle 重搜
▲ CardIn · 进卡
  • 2/3 帧投票一致性检查
  • 新卡或卡号变化 → 推入事件 FIFO
  • 更新 current_id + last_card_ms
  • card_present = true
▼ CardOut · 离卡
  • EM4095_Poll 每轮检查超时
  • now - last_card_ms ≥ 200ms
  • 推入 CardOut 事件到 FIFO
  • card_present = false
  • 清 current_id + 投票缓冲
Idle LONG + ↓ → Seek ≥16 交替 SHORT → Receive 64-bit 满 → Verify
← 回退：校验失败 → 回放 Ring Buffer → Idle / 状态异常 → Idle / err≥3 → Idle

📏 边沿分类器 (classify)

以 base_us (动态测得, 默认 256µs) 为 100%, 每条 GTIM 边沿按比例分类:
Debris
<70% SHORT
70~140% A
140~155% LONG
155~260% TIMEOUT >260%
SHORT = 正常半位周期 | LONG = 全位周期 (无中间跳变) | Debris/Ambiguous = 噪音/临界 | TIMEOUT = 长时间无边沿

📦 EM4102 帧 & 位缓冲布局

bit_buf[8] 压缩 64 bits, MSB-first 顺序填充:
帧头×9 111111111 D0..3+P0 DDDDP ×10行 …………… 列偶×4 PPPP 停止 0
5 字节卡号 = bit 9~57 (跳过行偶校验位 bit 13, 18, 23, 28, 33, 38, 43, 48, 53, 58)

🔄 Manchester 解码

边沿方向解码 bit含义
下降沿 ↓ (level=0)1信号中间从高到低
上升沿 ↑ (level=1)0信号中间从低到高
相位跟踪 skip 机制: 每个 SHORT 边沿交替 = 信号中点 vs 位边界。 skip=1 → 跳过下一个边界 glitch → skip=0 → 下一个是中点, 解码 → skip=1 ... LONG 边沿总是中点 (因为中间没有跳变), 解码后 skip=1。

🗳 投票机制 (vote_frame)

vote_buf[3][5] 缓存最近 3 帧的解码结果
2 帧: 两帧一致 → 通过
3 帧: 选出现最多的卡号, ≥2 票 → 通过 (2/3 多数)
新卡号入队: 清空旧投票缓冲, 重新收集 (card_on() 中)

♻ 边沿回退 (Ring Buffer Recovery)

Receive 期间每条边沿都记录到 edge_ring[16]. 校验失败时:
handle_frame() 失败 → 重置为 Idle → 回放 edge_ring 中边沿 → idle_process 重新搜帧头
避免丢失帧间隙中的有效前导。
