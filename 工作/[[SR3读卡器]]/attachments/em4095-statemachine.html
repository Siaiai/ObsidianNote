三态解码状态机 — dispatch_edge()

EM4095_Poll while 消费 GTIM FIFO 中的每条边沿 → classify(delta_us, base_us) 分五类 → dispatch_edge(state, cls, level, delta_us) 分发给对应 handler。
Idle · 空闲
函数: idle_process()
  • 挂起等待，不做任何 bit 操作
  • 判断: cls==LONG && level==0
  • 满足 → 初始化 seek 字段 → 转 SeekPreamble
  • 不满足 → 停留 Idle (该边沿丢弃)
初始化: alt_cnt=0, alt_sum=0, last_dir=0, err_count=0
SeekPreamble · 搜前导
函数: seek_process()
  • 非SHORT → reset_decoder 回 Idle
  • level==last_dir → 方向不交替, reset 回 Idle
  • SHORT+交替: alt_cnt++, alt_sum+=delta, last_dir=level
  • alt_cnt≥16 → 锁 base_us → 预填帧头 → 转 Receive
base_us = clamp(avg(alt_sum, 16), 200, 312)
Receive · 接收
函数: receive_process()
  • SHORT+skip=1: 边界glitch, skip=0, err=0
  • SHORT+skip=0: 中点解码 bit, skip=1, err=0
  • LONG: 中点解码 bit, skip=1, err=0
  • Debris/Ambig: err++, ≥3 → reset 回 Idle
  • TIMEOUT: reset 回 Idle
  • bit_count≥64 → handle_frame()
进状态时: bit[0..8]=1, bit_count=9, need_skip=1
每条边沿同步记到 edge_ring[16] (回退用)
Idle LONG + level=0 SeekPreamble ≥16 交替 SHORT Receive bit_count ≥ 64 handle_frame()
← 回退路径 (全部回到 Idle):
Seek 中: 非SHORT | 方向不交替 (last_dir重复) → reset_decoder()
Receive 中: Debris/Ambig 累积 err≥3 | TIMEOUT → reset_decoder()
handle_frame: 校验/投票失败 → replay_and_reset() (回放 edge_ring 中所有边沿后从 Idle 重搜)
Manchester skip 相位跟踪详解
每个 bit 周期 = 2 个半位。第一个半位的中点有边沿 (承载数据)，第二个半位的中点也可能有边沿 (取决于下一 bit 是否相同)。 但 bit 周期边界处也会产生边沿 (两个相同 bit 之间无边沿，两个不同 bit 之间有边沿)。 这里的 skip 机制用 need_skip 标记区分"中点"和"边界":
  • need_skip=0: 当前边沿是中点，解出一个 bit → 设 skip=1 (下次遇到的是边界，跳过)
  • need_skip=1: 当前边沿是边界/glitch，不解码只跳过 → 设 skip=0 (下次遇到的是中点)
  • LONG 边沿: 两个半位周期都没跳变 = 连续两个相同 bit，LONG 的中点 = 两个 bit 的中点，skipped 不用管，直接解码 → skip=1
进 Receive 时 need_skip=1 是因为前导的最后一位和第一个数据位之间必然有边界，跳过保护。
Manchester 解码规则
level==0 (下降沿) → bit=1  |  level==1 (上升沿) → bit=0
这正是 EM4102 的 Manchester 编码定义: 每个 bit 周期的前半段为数据、后半段为取反。
err_count 容错机制
Receive 期间遇到 Debris 或 Ambiguous 边沿不会立刻退出，而是 err++。
只有连续累积 RECEIVE_ERROR_MAX = 3 个才能触发 reset_decoder。
任意一次成功的 SHORT/LONG 解码会 err_count=0 清零，容忍偶发噪声。
SeekPreamble 中没有容错: 只要一个非 SHORT 或方向重复就触发 reset (无 err_count 字段可用)。
