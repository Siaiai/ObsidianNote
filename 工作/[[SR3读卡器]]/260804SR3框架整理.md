# 需求

## Flash 布局

| 地址 | 大小 | 用途 | 谁读写 |
| :--: | :--: | :--- | :----- |
| 0x0000 | 7KB | Bootloader | 仅 bootloader |
| 0x1C00 | 10.5KB | 主程序 | 仅 app |
| 0x4600 | 16B | FlashData_t (升级标志+读卡器参数) | bootloader + app |

> [!note] FlashData_t 布局
> 升级标志和读卡器参数合并在一个结构体，共享同一个 512B 扇区。
> 擦写时整体读-改-写，互不清零。
> - 前 6 字节：BootParam（bootloader 读写，结构必须和 bootloader 一致）
> - 后面：读卡器参数（仅 app 读写）
>
> 升级后 bootloader 只写前 6 字节，读卡器参数变 0xFF -> app 用默认值（不可避免）。

## 升级 (IAP)

### 升级流程

```mermaid
sequenceDiagram
    participant 控制器
    participant 读卡器APP
    participant Bootloader

    控制器->>读卡器APP: 10 A0 05 (进bootloader)
    读卡器APP->>读卡器APP: 读FlashData_t
    读卡器APP->>读卡器APP: 改update_flag=rNormal, 写回(保留参数)
    读卡器APP->>读卡器APP: NVIC_SystemReset()

    Note over Bootloader: 复位，读0x4600
    Bootloader->>控制器: 55 04 (boot通知)
    Note over Bootloader: update_flag≠0xFF，不跳app

    控制器->>Bootloader: 55 81 (开始升级，带总包数)
    Bootloader->>Bootloader: 擦app区(0x1C00起)
    Bootloader->>控制器: 55 01 (擦除完成)

    loop 每个固件包
        控制器->>Bootloader: 55 82 (256字节固件包)
        Bootloader->>Bootloader: 解密(XOR "603337") + 写Flash
        Bootloader->>控制器: 55 02 (包OK, Data=0xAA)
    end

    Bootloader->>Bootloader: 写update_flag=rUpdated
    Bootloader->>读卡器APP: 跳转app (0x1C00)

    读卡器APP->>读卡器APP: 读FlashData_t, 发现rUpdated
    读卡器APP->>控制器: 55 03 (升级成功, Data=0xAA)
    控制器->>读卡器APP: 55 83 (ACK)
    读卡器APP->>读卡器APP: 改update_flag=0xFF, 写回(保留参数)
    Note over 读卡器APP: 正常运行
```

### 0x55 协议帧格式

```
字节:  0     1     2-3        4-5         6~6+Len-1      6+Len  7+Len   8+Len
       0x55  CMD   Len(小端)  PackNo(大端) Data[Len]      CRC_HB CRC_LB  0xAA
```

- CRC: CRC-16/USB (poly=0x8005, init=0xFFFF, refin/refout, xorout=0xFFFF)，仅对 Data 计算
- PackNo/CRC: **大端**（控制器按大端解析）
- Len: 小端

### 升级标志值

| 值 | 含义 |
| :--: | :--- |
| 0xFF | 擦除态，bootloader 直接跳 app |
| 0x00 | rNormal，bootloader 不跳 app，等命令 |
| 0x03 | rUpdated，升级完成，app 上报后清 |

## 模式与功能

> [!note] 约定
> **新卡**：
>  - 有卡的情况下卡号变了
>  - 从无卡到有卡

### 模式表
| MODE | 模式名称 |                          主动行为                           |               被动行为               |    场景    |
| :--: | :--: | :-----------------------------------------------------: | :------------------------------: | :------: |
| 0x00 | 桌面模式 |                  有新卡后发送一次卡号，蜂鸣器响50ms                   |                无                 |  桌面读卡器   |
| 0x01 | 进站模式 | 读到新卡主动上报一次后**间隔一段**时间再次上报<br>若期间**读到新卡**则结束上次上报后开始上报新卡号 | 收到查询指令后不管实际有没有读到卡<br>都上报**没有卡号** |  进站读卡器   |
| 0x02 | 下放模式 |                       读到新卡主动上报一次                        |      收到查询指令后**根据实际情况**上报卡号       | 下放/出站读卡器 |
| 0x03 | 连续模式 |                       周期发送实际读卡情况                        |                无                 |  分拣读卡器   |

### 模式切换与自动适应

> [!note] 拔插自动适应
> 读卡器可以随意拔插换位置，控制器通过 0xFF 查询指令自动切换模式：
> - 控制器发 `0x7A/0x9A` -> 读卡器切进站模式（不存Flash，重启后恢复Flash模式）
> - 控制器发 `0x75/0x95` -> 读卡器切下放模式（不存Flash）
> - 首次收到切模式+Fail，后续收到按模式轮询应答
> - BCC 使能/失能也由 0xFF 指令控制，不存 Flash，重启后恢复 Flash 值

> [!note] 桌面模式硬件检测
> 桌面模式在读卡器上电时通过 PC06 引脚电平判断：
> - PC06 低 = 桌面硬件（蜂鸣器三极管下拉）-> 强制桌面模式 + 写Flash
> - PC06 高 = 非桌面硬件（10K 上拉）-> 若 Flash 存了桌面模式则改为进站 + 写Flash
> - 检测完后 PC06 切为输出（桌面模式驱动蜂鸣器）

> [!tip] 主动和被动
> **主动**:主要是主动上报 **被动**: 主要是对于指令的响应
> 主动行为和被动行为是独立的互不影响，所以等待期间如果有查询也会上报

### 不同模式通信流程
#### 进站
```mermaid
sequenceDiagram
    participant 衣架芯片
    participant 读卡器
    participant 控制器

    读卡器->>读卡器: 解码: 无卡

    rect rgb(232, 245, 233)
        控制器->>读卡器: 0x7A (进站轮询)
        读卡器->>控制器: Fail
    end

    衣架芯片->>读卡器: 进入感应区
    读卡器->>读卡器: 解码: 新卡

    rect rgb(255, 235, 238)
        Note over 读卡器: 触发上报
        读卡器->>控制器: 第1次: 10 FF 05 AA BB CC DD EE
    end

    rect rgb(255, 243, 224)
        Note over 读卡器: 100ms 等待
        读卡器->>控制器: 第2次: 10 FF 05 AA BB CC DD EE（同一卡号）
    end

    衣架芯片->>读卡器: 还在感应区
    读卡器->>读卡器: 旧卡，不触发上报

    rect rgb(232, 245, 233)
        控制器->>读卡器: 0x7A (进站轮询)
        读卡器->>控制器: Fail
    end
```
- **两次上报间隔默认 100ms，可设置**
- **进站轮询只应答 Fail，不报卡号**

## 初始化流程

```mermaid
flowchart TB
    START["上电"]
    subgraph INIT["Reader_Init()"]
        direction TB
        VTOR["VTOR = 0x1C00
        (向量表重定位)"]
        INIT_SUB["EM4095_Init + Protocol_Init + Led_Init"]
        CHECK_UPD["check_update_result()
        读FlashData_t.update_flag"]
        UPD_OK["rUpdated"]
        UPD_FAIL["异常"]
        UPD_NONE["0xFF/0x00 正常"]
        SEND_OK["发 55 03 成功"]
        SEND_FAIL["发 55 03 失败"]
        WRITE_BACK["改update_flag=0xFF
        写回(保留参数)"]
        FLASH_LOAD["flash_init()
        从FlashData_t读读卡器参数"]
        DESK["detect_desktop()
        PC06判断桌面/非桌面"]
        LED_INIT["LED初始场景"]
        DONE["初始化完成"]

        VTOR --> INIT_SUB
        INIT_SUB --> CHECK_UPD
        CHECK_UPD --> UPD_OK
        CHECK_UPD --> UPD_FAIL
        CHECK_UPD --> UPD_NONE
        UPD_OK --> SEND_OK
        UPD_FAIL --> SEND_FAIL
        SEND_OK --> WRITE_BACK
        SEND_FAIL --> WRITE_BACK
        UPD_NONE --> FLASH_LOAD
        WRITE_BACK --> FLASH_LOAD
        FLASH_LOAD --> DESK
        DESK --> LED_INIT
        LED_INIT --> DONE
    end
    START --> VTOR
```

## Reader_Poll 流程

```mermaid
flowchart TB
    POLL["Reader_Poll()"]

    P1["Protocol_Poll()
    收: UART -> 解析 -> RX FIFO
    发: TX FIFO -> 检查空间 -> 发送"]

    P2["poll_protocol_cmds()
    从RX FIFO取指令 -> dispatch_cmd"]

    P3["EM4095_Poll()
    边沿解码 -> 事件FIFO"]

    P4["poll_em4095_events()
    CardIn -> card_in (按模式上报+蜂鸣器)
    CardOut -> card_out"]

    P5["poll_active()
    进站: 二次发送定时
    蜂鸣器: 50ms超时关
    连续: 周期发送"]

    P6["update_led()
    有卡->绿灯(≥1s)
    无卡->按模式闪"]

    P7["Led_Poll()
    场景FIFO消费
    帧推进"]

    POLL --> P1
    P1 --> P2
    P2 --> P3
    P3 --> P4
    P4 --> P5
    P5 --> P6
    P6 --> P7
```
