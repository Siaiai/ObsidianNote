# 规划与代码一致性讨论

> 触发：T4-8 回报与 §3.3/C9 的表述被 AI 判为冲突；用户确认“以当前代码为准，之前需求有些问题”。
> 目的：讨论 Splan 如何避免“方案没讨论全 → 文档长期记错 → AI 读错”。

## 1. 当前事实（面板文档）

- 现行：`C11` + `§3.3` + `§6` 的 T4-8 摘要，代码提交 `c963ef3`/`8087b79`。
  - `0x04` 成功由 `0x82`（分支条件 `>=0x81`）清状态回主页；
  - `0x04` 超时回件数页 + `TNoAck`；
  - 页响应仅 state 1 留页；
  - `WaitKind`/D9 未落地。
- 部分 / 未落地：`C9`（0/1/2 + `0x80` 已落地，WaitKind 未落地）、`D9`（C11 标未落地/部分）、`C7`（旧“ACK 不回主页”已被 C9/C11 取代）。
- AI 的“0x04 回主页与 §3.3/C9 相反”按当前文档是**过期/误读**：§3.3/C11/§6 已写回主页；C9 只写“等 0x82 或超时”，没有写“结果页”。AI 没有优先读 C11，或读了旧版本。
- 真正开放点：`>=0x81` 会收 `0x81/0x83`，C11 只写“需注意”，没有对应 T；这是代码现状，是否算最终需求要确认。

## 2. 问题

- 同一行为在 R/T/C/D/§3/§5/§6 多处重复，旧版本未标“未落地/历史”，AI 读到哪条都可能当真。
- C 只追加，不更新旧 §3/D；C11 已改 §3.3，但 C9/D9/C7 仍像现行。
- R 与方案没有显式映射（R4 → §3.3/§3.4 → C11 → T4-8/T4-2），用户和 AI 都要靠猜。
- 方案未确认就开 T；代码先落地后，文档只补 C，不清理旧方案。
- 文档层数多、历史多；AI 上下文有限，旧信息干扰。
- lint 只查结构，不查“哪条是现行/是否与代码一致”。

## 3. 建议（先讨论，不落任务）

1. **§3.0 当前行为**：每个 R 只在这里写“代码已验证的现行行为 + commit + 代码位置”；C/D/§3 其他段只写变化/方案，不重复行为。
2. **状态三态**：§3/D/C 增加 `现行 / 未落地 / 历史`；未落地不得被 done T 引用；C11 落地，C9 部分，D9 未落地。
3. **R→方案→代码矩阵**：R | 用户需求 | 现行代码 | 方案/差距 | 验收；一眼看出需求与实现差异。
4. **方案确认门**：R 进入实现前必须有 §3 方案 + D + 不做什么；未确认只 `待澄清`，不开 T。
5. **代码为准收口**：`/splan-done` 发现代码与文档不一致 → 不勾 T；记 C；更新 §3.0；旧方案标历史；再收口。
6. **先 reconcile 再 archive**：`--archive` 只压缩已对齐的内容；先压缩会把错误固化。
7. **减少重复**：行为只写一处；C 只写“改了什么”；§5/§6 只写记录；旧版本进历史区。
8. **读文档顺序**：`/splan-enter` / `/splan-next` 先读 §0 → §3.0 → 最新 C（代码为准）→ 开放 T；旧 C/D 不默认读。
