## 2. 契约

- **架构**：本文件以面板（HC32F460KETA）为主；面板经 UART 命令协议连控制器（GD32F470ZI），控制器再经以太网 UDP 连上位机 / 其它控制器、经 CANopen 连电机节点；控制器细节见 [[261029S3维护]]
- **协议 / 数据格式**：
  - 面板协议：BCC 校验；单包上限 129 字节（`EVERY_PACK_MAX`），命令缓冲 5 包；重发 450ms、最多 2 次（`CmdProtocol.h`）
  - 控制器 UDP（边界）：结构体按 `#pragma pack(1)` 打包（`UDP_CMD.h`）；PC 心跳含 MAC、进站满、允许接收、链条启动、语言、屏蔽、返工模式
  - 版本：面板 `develop` 为 `CP060`、`release/V061` 为 `R61`；控制器 `V3.0.06.3`
- **换绑协议 v1（草案，T1-1 锁定）**：面板 → 控制器透传请求；控制器 → 上位机转发；上位机返回允许 / 拒绝；控制器回传面板。`0x1001` 心跳新增 `ReBindEnable` 字段，负载偏移 39；`u16PLen - 10 >= 40` 表示字段存在；字段不存在时按原“扫码自动出衣”语义；实现分支 `feature/换绑优化`
- **构建与测试命令**：见 §0 基线；无自动化测试

### 3.2 换绑开关方案（R1）

- **字段存在性即开关**：不判断版本号、不判断 S3；`0x1001` 负载长度 ≥ 40 字节视为存在 `ReBindEnable`，否则按旧“扫码自动出衣”逻辑。
- **状态分工**：`PCustomOCTb[4]` 为生效值，`PCustomOCShow[4]` 为编辑值；新增 `ReBindSupported` / `ReBindEnable` / 请求挂起标志与超时。
- **允许后生效**：KEY_OK 不直接赋值；发送透传请求，收到上位机“允许”后才写 `PCustomOCTb[4]` 并持久化；拒绝 / 超时保持原值并提示。
- **兼容**：字段不存在 → 保留旧文案“扫码自动出衣”与旧行为；字段存在 → 菜单文案“启动换绑”。
- **不做**：不改控制器 / 上位机；不改 0x0107 绑定数据格式；不改非标准版。

```mermaid
sequenceDiagram
    participant P as 面板
    participant C as 控制器
    participant PC as 上位机
    P->>C: 透传请求(目标值 0/1)
    C->>PC: 转发
    PC-->>C: 允许 / 拒绝
    C-->>P: 透传响应 + 0x1001 ReBindEnable
    alt 允许
        P->>P: 写入 PCustomOCTb[4] 并持久化
    else 拒绝 / 超时
        P->>P: 保持原值并提示
    end
```
