## 1. 通信协议基础（现行 `my_protocol`）

> 面板与控制器共用 `02_Middleware/my_protocol`（控制器侧 `APP/panel/my_protocol` 同版本），二进制分帧、请求-回复、库内分片/ACK/重传。以下帧格式为现行实现。

| 名称       | 长度    | 内容      | 备注                         |
| -------- | ----- | ------- | -------------------------- |
| 字段       | 字节数   | 取值/规则   | 说明                         |
| HEAD 帧头  | 1     | 0x55    | 固定帧起始魔术字                   |
| LEN 帧总长  | 2     | 整帧字节总数  | 包含 HEAD~TAIL 全部字段，**大端模式** |
| VER 版本   | 1     | 0x01    | 当前协议唯一版本                   |
| CFG 配置位  | 1     | 位图控制    | 通信属性配置位                    |
| SEQ 序列号  | 2     | 0~65535 | 分片/事务序号，**大端模式**           |
| CMD 指令码  | 2     | 自定义指令   | 业务功能码，**大端模式**             |
| DATA 数据域 | LEN-9 | 业务数据    | 最小0字节，当前配置上限501字节（`PROTOCOL_FRAME_MAXLEN=512`） |
| CHECK 校验 | 1     | CRC8    | 校验范围：LEN ~ DATA            |
| TAIL 帧尾  | 1     | 0xAA    | 固定帧结束魔术字                   |

> 实测配置：`PROTOCOL_FRAME_MAXLEN=512` → 单帧载荷上限 501B；JSON 每片 499B。

### 2.5 关键决策（后续必须遵守）
1. **值序契约**：参数值数组顺序 = JSON items 实参序（跳过 `type==""` 帧项），线宽 = 该 item 的 `length`（1/2B，大端）。
2. **JSON 零拷贝**：`JsonSpan_t` 指向 `s_json_rx`；解析后该 40KB 缓冲**只读常驻**，任何重拉前必须先复位模型。
3. **统一字号 20px**：全工程 `USER_DEFAULT_FONT_SIZE=20`；字库固定 20px，提供者忽略请求 px。
4. **字体钩子向后兼容**：未安装 `UI_FontOps_t` 时旧 5×7 路径不变（模拟器无字库可回退）。
5. **值源抽象**：页面只经 `ParamSource_Get()`；任务2 注册协议源即可，页面不改。
6. **控制器权威**：合法性最终由控制器判定（面板仅 min/max 预校验）；失败原因由控制器回 **ASCII 文本**，面板原样显示，不维护错误码表（§4.2）。
7. **单通道规则**：模块 4（主轨）/15（环形仓）`max_size=1`，面板不显示 CH2。
8. **启用/使能即参数**：`分拣仓使能` 等 `en_*` 属于系统参数模块（code=0），无需单独使能指令。
9. **模拟器复用固件页**：`PANEL_SIM_APP` 条件编译，主仓库 CMake 注入固件页面 + panel_model；GUI 子模块单独构建仍走 demo。
10. **双工程登记**：新增 `.c` 必须同时进 `Panel.uvprojx` 与 EIDE；EIDE 优先用 MCP，不手改 yml。

### 2.7 数据契约与字库格式速查

**JSON 结构**（UTF-8、紧凑、无转义）：
```jsonc
{"low_com_configs":[
  {"name":"分拣仓模块设置","code":1,"max_size":2,"items":[
    {"key":"命令","length":1,"defaultValue":0,"remark":"","type":"","min":0,"max":2},
    {"key":"模块号","length":1,...,"type":"","min":0,"max":0},      // 前3项=帧项，type==""，解析时跳过
    {"key":"通道号","length":1,...,"type":"","min":1,"max":2},
    {"key":"库区电机运行时间","length":2,"defaultValue":180,"remark":"单位：s",
     "type":"配置项","min":0,"max":65535}
  ]}, ...]}
```
- `type`：`配置项|输入口|输出口|读卡器`（未知→配置项并计数）。
- 容量：模块 ≤16、参数 ≤320、单模块 ≤48；模块号 0–12/14/15（13 缺席）。
- 生成端：控制器 `APP/src/param_json.c` ← `APP/inc/param_def.h`（唯一维护点）。

**字库格式**（W25Qxx，地址 0 起）：
- 头 12B：`fontok(0xAA) | pad | ugbkaddr(u32 LE) | ugbksize(u32 LE)`。
- 字模：`offset = ugbkaddr + unicode×60`（20px，槽 60B）；**列优先**：第 x 列 3 字节，每字节 8 像素 MSB 在上，仅前 20 行有效。
- 宽度：`uni<0x80` 半宽（10 列/advance 10），其余全宽（20 列/20）；全 `0x00` = 合法空白，全 `0xFF`/越界 = 缺字。

### 2.8 踩坑记录（务必保留）
1. 直接 `UI_PopupShow` 后必须 `UI_PopupRelayout()`（便捷封装内部已做），否则 `w/h=0` 不可见。
2. 目标工程 `-fshort-enums`：`UI_Event_t` = **5B**（pyOCD 注入事件按 5B 步长）。
3. `pyocd rtt` 强杀会使 CMSIS-DAP 假死 → 用脚本读 `_SEGGER_RTT` 后干净退出。
4. `eide_set_inc_dirs` **不要**回写 `ARMCLANG/include`、`libcxx`（会遮蔽 newlib）。
5. SPI3 需关闭 JTAG TDO/TRST 释放 PB3/PB4；MISO 内部上拉。
6. 字模全 `0x00` 视为空格，不按缺字处理。
7. 列表顶部再↑/底部再↓ 必须 `return 0`，把焦点交还页面导航（否则无法切通道）。
8. `UI_Obj_t` 为 `#pragma pack(1)`，32 位目标 `fresh_interval` 偏移 +17。
9. 模块列表只在解析完成时建一次，禁止每帧重建。
10. EIDE `srcDirs` 与 `virtualFolder` 同名文件会重复编译 → 去重。
11. RTT 大流量（全量字库 4MB）不稳定，长传输走 USART1 或分块。
12. 面板首次拉 JSON 需 11~20s（68 片逐片请求），等待期 UI 必须有进度。

## 4. 任务2规划：参数值读写（下一步）

### 4.1 目标与范围
**目标**：模块页进入/切通道时从控制器读取该模块该通道全部实参值；编辑保存时写回控制器，控制器校验/落盘/应用，面板用回显刷新。全过程有读取中/保存中/失败提示。

**范围内**：READ_VALS/WRITE_VALS 指令（两端）、控制器 `panel.c` 独立读写回调（**不改 `udp_comm.c`/`param_mgr.c`**）、面板异步值源、页面状态机、F1 重读、联调与回归。
**不在范围**：模块使能独立界面（`en_*` 已属系统参数）、运行开关、IP 专用页、参数值离线持久化、双面板并发冲突处理。

### 4.2 协议定稿

```text
0x0003 READ_VALS
  请求: [mod:1][ch:1]                      ch=1..max_size（面板按 JSON 保证合法）
  成功: [0xAA][values...]                  按 JSON 实参序，每项 length 字节，u16 大端
  失败: [0x00][idx:1][reason_ascii...]     idx=出错实参(1-based)，0=通用；reason 无结尾符，长度=帧数据-2

0x0004 WRITE_VALS
  请求: [mod][ch][values...]               长度必须 = Σlength（面板按 JSON 生成）
  成功: [0xAA][echo values...]             控制器回显生效值（面板直接覆盖本地值池）
  失败: [0x00][idx][reason_ascii...]
```

**失败原因（控制器回 ASCII 文本，面板原样显示，不维护错误码表）**：
| 场景 | idx | reason（ASCII） | 面板展示 |
|---|---|---|---|
| 模块不存在 | 0 | `bad module` | Alert 标题"读取/保存失败"，正文原样 |
| 通道号非法 | 0 | `bad channel` | 同上 |
| 载荷长度不符 | 0 | `bad length` | 同上 |
| 字段值越界 | i（1-based） | `param invalid` | Alert 正文 + 高亮第 i 行 |
| 独占端口被其他模块占用 | 0 | `port conflict` | Alert 正文 |
| SYS 立即落盘失败 | 0 | `flash write failed` | Alert 正文 |
| 超时（无回复） | — | — | 面板本地提示"控制器无响应" |

> 原因文本必须 ASCII（控制器 `param_def.h` 里中文名不参与）；面板把回复中的 reason 拷进静态缓冲再用——协议缓冲回调返回后即失效。

**约束核算**：模型容量单模块 ≤48 实参 × 2B = 96B；WRITE 请求 ≤98B、READ/WRITE 成功回显 ≤97B、失败 ≤26B，均远小于单帧 501B，无分片。当前 `UI.JSON` 最坏模块 15 为 41 实参/56B（WRITE 58B、回显 57B）。
**语义**（控制器侧，与 `udp_comm.c` 0x0A/0x0B 行为一致）：
- 读：`paramModuleReg(mod)` → `paramModuleVal(reg, ch-1)`，`length==2` 转大端。
- 写：校验长度 → 逐项 `paramValInRange` → `paramCheckModuleUnique` → 写入 → **模块0**镜像前 6 个网络字段到另一通道并 `paramFlush()`；其他模块 `paramMarkDirty()`（10s 防抖落盘）→ 成功后 `moduleClaimAllEnabled()` + `moduleParamChangedNotify(mod, ch-1)`。
- 失败不改任何值（面板收到失败后保持原显示）。
