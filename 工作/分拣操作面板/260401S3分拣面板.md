## 2. 契约

- **分层与硬件访问**：硬件只经 ops 表（`ST75256_Ops_t` / `W25Qxx_*` / `UI_Ops_t`），寄存器只出现在 `st75256_hc32_adapter.c`、`app_ui.c`。
- **通道基准**：页面与 `ParamStore` 0-based，协议 1-based（`ch+1`）。
- **值编码**：按 JSON 实参顺序，`length=1/2B`，u16 大端；JSON 缓冲借用面板 RX 缓冲，解析后只读。
- **失败格式**：`[0x00][idx][reason]`，字段级 `idx` 1-based、其它 0；reason UTF-8 ≤64B，面板原样显示。
- **协议头**：`04_Application/app/panel_cmd.h` 与控制器 `APP/panel/panel_cmd.h` 逐字节一致，由 `panel_cmd` 测试校验。
- **心跳与调试状态**：回复 `[0x01][ver_len][ver][active]`（`ver_len<=31`），面板只认结构化回复；调试态以心跳为源，`DEBUG_GET/SET` 只做即时回包，断链不清缓存、不自动退出。
- **UI 事件码**：`eKeyLight` 只由模块页消费，显示当前参数 `remark`（← C1）。
- **Flash 分区**：JSON A/B 槽 `0x00F00000` / `0x00F10000`，自检扇区 `0x00F9F000`，字体区 < `0x00F00000`。
- **时基与循环**：`Bsp_GetTickMs()` 为唯一 1ms 时基，`Bsp_SysTickInit()` 在 `Bsp_ClkInit()` 之后；主循环各 `*Loop` 不得阻塞。
- **依赖与构建入口**：GUI/ZenButton/my_protocol 以 submodule 钉 commit（克隆加 `--recursive`，不再复制副本）；固件走 Keil/EIDE 双工程，EIDE 优先 MCP `eide_build` / `eide_flash`，不手改 `.eide/eide.yml`（必改先 `eide_reload`），新增源文件双登记。

## 3. 方案

### 3.1 分层与主循环

```mermaid
flowchart LR
    C[控制器] -- 二进制帧 --> P[app_panel]
    P --> S[param_source_protocol]
    S --> M[panel_model]
    J[UI.JSON] --> M
    M --> PG[ui_pages]
    PG --> G[GUI]
    G --> U[app_ui]
    U --> L[ST75256]
    P <--> F[app_json_cache]
    F --> W[W25Qxx]
```

- 主循环：`App_KeyProcess` → `App_PanelLoop`（心跳/JSON/分片/命令）→ `App_ParamLoop`（JSON ready 后解析一次）→ `App_LogLoop` → `UI_Loop`。
- 页面只读模型/值池，写经 `ParamSource`，不直接拼协议字节；焦点契约集中在 `page_state.h`，模块页每通道独立行号、单通道忽略左右、编辑中左右归编辑器。

### 3.2 调试状态心跳同步（R2）

- 目标：控制器调试状态由心跳周期带回面板；面板断链/重启后 1s 内恢复；断链不改变控制器调试状态。
- 面板（已改）：`on_heartbeat_ack` 校验 magic / `ver_len` / 长度后取 `active` → `debug_cache_update()`，仅变化置 dirty，`active=0` 清输入快照；超时只置离线、保留缓存；不再消费 `0x0018`。
- 控制器（已改）：`cbHeartbeat` 回 `[0x01][ver_len][ver][active]`；删 `s_panel_debug_mode` / `s_panel_hb_*` / 3s 兜底；删 `DEBUG_STATE_EVT` 广播与宏。
- 兼容：新旧不兼容——旧控制器回原始版本串，新面板只置在线、拿不到调试态；升级必须双端同版烧录。
- 风险：断链后控制器保持调试（输出全停），需面板重连或 UDP / 复位退出；这是需求取舍。
- 验证：`panel_cmd` 常量与双端头文件、`app_panel_vals` 覆盖结构化/非结构化/仅变化置 dirty/超时保留；真机 V-4。

### 3.3 高级设置与参数重置（R3，面板侧完成）

- 入口：主页第 5 行 `高级设置` → `advanced_page`，页内一行「重置控制器参数」；主页 4 行改 5 行（列表 h=138、行高 20+3，可容纳）。
- 确认：OK/Cancel 弹窗「重置控制器参数？将恢复默认参数」；取消不发包，确认后发 `0x000C`（空载荷）。
- 面板：`App_PanelParamReset()` / Poll / Result 按现有请求-回复；成功 toast「参数已重置」，失败显示控制器 reason；不改本地 `ParamStore`，回模块页重新读取。
- 控制器：双端 `panel_cmd.h` 增 `PANEL_CMD_PARAM_RESET 0x000C`；`panel.c` 注册 `cbParamReset` 桩，校验空载荷后回「未实现」；真实重置由同事实现。
- 验证：`panel_cmd` 常量、`app_panel_vals` 成功/失败/超时/离线/忙、GUI `home_state` 4→5 与 advanced 场景、真机 V-5。
- 边界：不定义重置范围；不改网络页、调试页、UDP；不自动写面板值池。
