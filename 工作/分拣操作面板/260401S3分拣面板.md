### 0.1 问题判断

| 问题 | 判断 | 处理原则 |
|---|---|---|
| 长按连发松开键才开始、往下乱跳 | **面板 `app_key.c` 实现错误**，不是 GUI。之前用 `ZBTN_EVENT_LONG_PRESS` 作为连发起点，而 ZenButton 的长按事件在释放时产生；hold 标志没有可靠的释放清除，后续定时器继续投递 | 不要用 ZenButton 长按事件做连发；改为读按键电平/按下与释放，或先完全不做长按 |
| 模块列表进入后没有选中高亮，但 Enter 能进对应模块 | **页面/列表状态问题优先**。GUI 的列表只在 `UI_COMP_FLAG_SELECTED` 时给当前行反色；模块列表页只设置焦点、没有设置 `SELECTED`；模块参数页/首页基线有补这个标志 | 先修页面进入/焦点切换/列表重建时的 `SELECTED` 生命周期，不改 GUI 核心 |
| 显示/版本类页面同样没有选中高亮 | 同一类问题：焦点在列表，但列表未进入操作态 | 与模块列表一起统一页面契约 |

**结论**：这轮先不改 GUI 库。先把页面进入、焦点、列表选中高亮、列表重建四件事定成固定契约，并加回归测试；确认 GUI 契约本身有缺陷后，再单独改 GUI。

## 2. 架构与协议

### 2.1 分层

| 层 | 目录 | 职责 |
|---|---|---|
| 硬件 | `01_Hardware/bsp`、`component/*`、`adapt/*` | 时钟/SysTick/USART/SPI/LCD/Flash/按键 |
| GUI | `02_Middleware/GUI` | 静态 GUI、字体钩子、Win32 模拟器 |
| 模型 | `02_Middleware/panel_model` | JSON 解析、模型、UI 元数据、值池、值源 |
| 协议 | `02_Middleware/my_protocol` | 二进制分帧、分片、ACK/重传 |
| 应用 | `04_Application/app`、`ui_pages` | 面板协议、参数 glue、页面 |

### 2.2 启动与主循环

```text
Clk → SysTick → LED → USART1 → ST75256 → W25Qxx
App_LogInit → App_UIInit → App_FontInit → App_JsonCacheInit
→ App_KeyInit → App_PanelInit → App_ParamInit
主循环：
App_KeyProcess → App_PanelLoop(心跳/JSON_VERSION/缓存或逐片拉取/命令)
→ App_ParamLoop(ready 后解析一次) → App_LogLoop → UI_Loop
```

关键契约：

- JSON 缓冲借用板级 RX 缓冲，解析后只读常驻；重拉前先复位模型。
- 参数值顺序 = JSON 实参序（跳过 `type==""`），宽度取 `length`（1/2B，u16 大端）。
- 页面/`ParamStore` 通道 0-based，协议通道 1-based（`ch+1`）。
- 控制器是唯一权威；失败原因 UTF-8，上限 64B。
- 统一 20px 字体；未安装字体钩子时回退内置 5×7。
- 单通道模块 4/15 隐藏 CH2；使能走 `SET_ENABLE/READ_ENABLE`。

### 2.3 协议指令

| CMD | 名称 | 方向 | 说明 |
|---|---|---|---|
| `0x0001` | HEARTBEAT | 面板→控制器 | 当前回版本串；本轮不追加 work_mode，面板连接态由控制器 `panel_State` 维护 |
| `0x0002` | JSON | 面板→控制器 | `[seq]` 逐片请求；回 `[seq][total][data...]`，空=发完 |
| `0x0003` | READ_VALS | 面板→控制器 | `[mod][ch]`；成功 `[0xAA][values...]` |
| `0x0004` | WRITE_VALS | 面板→控制器 | `[mod][ch][values...]`；成功回显 |
| `0x0005` | SET_ENABLE | 面板→控制器 | `[mod][ch][en]`；成功 `[0xAA][ch1][ch2]` |
| `0x0006` | READ_ENABLE | 面板→控制器 | `[mod]`；空=全部 |
| `0x0007` | NETCONF_STAGE | 面板→控制器 | 当前 `sub=1~4`；任务4B 增加 `sub=5` 本地 IP 四段 |
| `0x0008` | NETCONF_CONFIRM | 面板→控制器 | `[sub][0xAA]`，写 Flash，复位生效 |
| `0x0009` | JSON_VERSION | 面板→控制器 | `[0xAA][crc32:4][len:2]` |
| `0x000A` | SWITCH_SET | 面板→控制器 | `[mod][ch][len][data...]` |
| `0x000B` | SWITCH_GET | 面板→控制器 | `[mod][ch]` |
| `0x0010` | DEBUG_GET | 面板→控制器 | `[0xAA][active]` |
| `0x0011` | DEBUG_SET | 面板→控制器 | `[0/1]` |
| `0x0012` | DEBUG_READ_INPUTS | 面板→控制器 | `[0xAA][18B]`，一次性诊断 |
| `0x0013` | DEBUG_PULSE_OUTPUT | 面板→控制器 | `[port]`，2s 自动关 |
| `0x0014` | DEBUG_OUTPUT_OFF | 面板→控制器 | 关闭当前点动口 |
| `0x0015` | DEBUG_READERS | 面板→控制器 | 读卡器快照，一次性诊断 |
| `0x0016` | DEBUG_INPUT_EVT | 控制器→面板 | 输入变化推送，18B |
| `0x0017` | DEBUG_READERS_EVT | 控制器→面板 | 读卡器变化推送 |
| `0x0018` | DEBUG_STATE_EVT | 控制器→面板 | 调试状态变化 |

失败统一 `[0x00][idx][reason]`；参数写入 `idx` 1-based，其余为 0；reason 为 UTF-8，≤64B。

### 4.2 主要风险

1. JSON 更新失败会 `memset` 清空旧模型，面板可能变空白。
2. 控制器 `paramJsonBuild()` 失败仍回 `len=0`，面板会无限重试。
3. 40KB 已用 83.2%；新增 1 个中等模块后余量约 1.7~4.6KB，2 个大模块会超。
4. 单模块 48 项是硬失败点；模块 15 只剩 7 项。
5. 未知 `type` 被当可编辑 `CONFIG`，可能误写。
6. SYS 新参数没有通用入口；网络页仍是固定主/高级结构，不是完全元数据驱动。
7. 页面静态缓存没有模型代次；JSON 自动更新会持有旧 flat/span。
8. 重复模块 code 未校验；模块列表行数需边界检查。
9. JSON 变化目前只支持版本页手动更新。

### 4.3 建议

- 先按 40KB 做预算测试和错误提示；若确认要加模块/SYS 页，一次扩到 60KB（同步控制器 `JSON_BUF_SIZE`、面板 `PANEL_JSON_MAX`、缓存 `APP_JSON_CACHE_MAX`）。
- 两阶段解析需第二份 `ParamModel_t`（约 +7.9KB RAM）；64KB JSON 再 +24KB RAM，需看 map。
- 未知 `type` 不进可写页面；`length` 只接受 1/2；`choices > 2` 明确报错或扩上限。
- 版本页显示 JSON 大小/模块数/实参数/余量/缓存命中/上次失败原因。
