### 2.3 旧面板 Operation_Panel（字库 Flash 格式权威参考，硬件同款）
- 字库芯片：W25Qxx 挂 **SPI3**：SCK=PB4(Func_Spi3_Sck)、MOSI=PB3(Func_Spi3_Mosi)、MISO=PB6(Func_Spi3_Miso)、CS=PB7(GPIO 软件控制)、WP=PB5(拉高禁用)；读指令 0x03、JEDEC ID 0x9F、`FLASH_MAX_ADDR=0x800000`(8MB)。出处：`midware/ziflash.h:38-84`、`midware/ziflash.c:165`（`SpiFlash_ReadData`）。
- Flash 地址 0 处为字库信息头 `_font_info{ uint8 fontok(==0xAA 有效); uint32 ugbkaddr; uint32 ugbksize; }`（`midware/fonts.h`、`fonts.c:34,299`）。
- **字模格式（unifont，Unicode 直接索引）**：
  - 取模偏移：`offset = unicode × size × 3`；每字模槽位 `size×3` 字节（`midware/Dispaly.c:5569`：`offset = char_uni * size * 3`）。
  - 旧固件菜单统一用 **size=20**（`OLED_ShowString(x,y,str,20)`，槽位 60B/字）。
  - 点阵排布：**列行式**——对第 x 列（x=0..size-1）有 3 字节 `buf[3x+0..2]`，每字节 8 个纵向像素、**MSB 在上**；超过 size 行的位忽略（`Dispaly.c:2068-2113` `OLED_ShowCHinese`）。
  - 宽度规则：`unicode < 0x2000` 半宽（advance=size/2，ASCII/数字），`≥0x2000` 全宽（advance=size，汉字/全角）（`Dispaly.c:5560-5585`）。
  - 全角标点疑点（已基本排除，且不影响本期）：`ziflash.h:86-87` 注释称"汉字区 0x000000~0x16f6af、全角区 0x16f6b0~0x1711f7"，与 `uni×60` 直接索引公式对全角区不一致。但 T1 实测字库头 `ugbksize≈0x003F4D94`（4.15MB）> U+FF5E×60≈0x3BE4E8，说明**字模很可能就是全 Unicode 直索引、全角区无独立起始地址**（T2 渲染确认即可）。另外**面板本期不显示 remark**，参数名/模块名均为纯汉字、值与标签为数字/ASCII/纯汉字，因此**不需要全角标点字模**。将来若要在界面显示全角标点，再按 T2 实测结论处理。

## 3. UI.JSON 数据契约（面板解析的唯一输入）

实测样本：仓库根 `UI.JSON`（33,577B，UTF-8 无 BOM，单行紧凑格式）。生成器保证：**字符串内无转义字符**（`\"`、`\\` 不会出现；解析器遇到 `\` 判为格式错误并记录日志，不做反转义）。

```jsonc
{"low_com_configs":[                     // 模块数组，按 code 升序，13 缺席
  {
    "name":"分拣仓模块设置",               // 模块中文名（UTF-8）
    "code":1,                            // 模块号 0..15
    "max_size":2,                        // 通道数：1 或 2（模块 4/15 为 1）
    "items":[
      // ── 前 3 项固定为"协议帧项"，type=="" ，非实参，面板必须跳过 ──
      {"key":"命令",  "length":1,"defaultValue":0,"remark":"","type":"","min":0,"max":2},
      {"key":"模块号","length":1,"defaultValue":0,"remark":"","type":"","min":0,"max":0},
      {"key":"通道号","length":1,"defaultValue":0,"remark":"","type":"","min":1,"max":2},
      // ── 实参项 ──
      {"key":"进站读卡器","length":1,"defaultValue":0,"remark":"",
       "type":"读卡器","min":0,"max":13},
      {"key":"库区电机运行时间","length":2,"defaultValue":180,"remark":"单位：s",
       "type":"配置项","min":0,"max":65535}
      // ...
    ]
  },
  // ... 共 15 个模块
]}
```

解析规则（规范性）：
1. **帧项判定**：`type` 为空串 → 跳过，不计入参数表（不要按 key 名字判定）。
2. `type` 映射枚举：`输入口`→INPUT、`输出口`→OUTPUT、`读卡器`→READER、`配置项`→CONFIG；未知值 → CONFIG 并记日志。
3. 数值字段：`code/max_size/length/min/max/defaultValue` 均为非负整数，`length∈{1,2}`、`max_size∈{1,2}`；越界 → 该项/该模块判错。
4. 参数顺序 = JSON items 顺序（**与控制器结构体字段序一致，任务2 线上读写按此序**），面板不得重排。
5. 容量规划（当前 15 模块/245 实参，留增长余量）：模块 ≤16、实参总数 ≤320、单模块实参 ≤48。
6. 解析失败（结构错/超容量/含 `\`）：记录错误原因字符串（ASCII，日志用）+ 首页状态行显示"JSON 解析失败"，界面不进模块列表；**不得崩溃、不得越界**（所有解析函数带边界检查，输入截断也能安全报错）。

## 5. 中文字库方案（W25Qxx + unifont）

### 5.1 决策
- **统一字号 20px**：汉字 20×20（全宽），ASCII/数字 10×20（半宽）。240×160 屏 → 每行 24 半宽字符（12 汉字），行距 22px（20+2）→ 正文约 6~7 行。与旧面板观感一致，字库现成。
- 内置 5×7 ASCII 字体保留为**回退**（钩子未安装 / 取模失败时画空心矩形），现有模拟器与旧页面不回归。
- 字模读取：SPI3 硬件 SPI（LL 库，参考官方 `examples/spi`），轮询阻塞式即可（本期不做 DMA/中断）。

### 5.2 新增驱动（三层，仿 st75256 模式）
1. `01_Hardware/component/w25qxx/w25qxx.c/h` — 复用官方 `drivers/bsp/components/w25qxx`（XHSC，LL 函数表，保留 license）：
   ```c
   typedef struct {
       void    (*Delay)(uint32_t);
       void    (*Init)(void);
       void    (*DeInit)(void);
       void    (*Active)(void);                            /* CS 低 */
       void    (*Inactive)(void);                          /* CS 高 */
       int32_t (*Trans)(const uint8_t* tx, uint32_t len);
       int32_t (*Receive)(uint8_t* rx, uint32_t len);
   } stc_w25qxx_ll_t;
   ```
   官方 API：`W25QXX_Init/DeInit/GetManDeviceId(0x90)/GetUniqueId/ReadStatus/.../ReadData/PageProgram/EraseSector/EraseChip`；另加 `W25QXX_GetJedecId(0x9F)` 便于读 `0xEF4018`。本期应用只读；写/擦除已具备，供后续字库更新。
2. `01_Hardware/adapt/w25qxx/w25qxx_hc32_adapter.c/h` — HC32 SPI3 适配（唯一碰寄存器处，仿官方 `ev_hc32f460_lqfp100_v2_w25qxx.c`）：
   - 引脚：PB4=SCK、PB3=MOSI、PB6=MISO 复用为 SPI3（`GPIO_FUNC_43/40/41`）；PB7=CS 推挽输出（软件控制，初值高）；PB5=WP 推挽输出恒高。PB3/PB4 需先关闭 JTAG 的 TDO/TRST 复用（`GPIO_SetDebugPort`，保留 SWD/RTT）。
   - SPI 配置：**`SPI_3_WIRE`（软件 CS）** + `SPI_DelayTimeConfig`（interval 8SCK、release 8SCK、setup 1SCK）；Mode0、8bit、MSB first、主机、PCLK1/8 = 12.5MHz（PCLK1=100MHz）。**`04_Application/hc32f4xx_conf.h` 的 `LL_SPI_ENABLE` 必须为 `DDL_ON`**。
   - `Trans/Receive` 直接走 LL 批量 `SPI_Trans/SPI_Receive`（带超时），不再逐字节轮询。
   - 对外只暴露 BSP 方便函数（`s_ll` 保持 static）：`W25Qxx_HC32Init/DeInit/Read/Write/EraseSector/EraseChip/GetIds/MaxAddr`；应用不再接触 `stc_w25qxx_ll_t`。写/擦已实现，本期只读应用不调用。
3. `04_Application/app/app_font.c/h` — 字体服务（实现 GUI 的 `UI_FontOps_t`，见 §6）：
   - `App_FontInit()`：W25Qxx_Init → 读 ID（记日志）→ 读地址 0 的 `fontok`（==0xAA 记日志，非 0xAA 仍继续，只告警）→ `UI_SetFontOps(&s_font_ops)`。
   - 取模（T2 已实测确认）：`offset = uni × 60`；每字 60B = 20 列 × 3B/列，列优先、MSB first，每列只取前 20 位（第 3 字节高 4 位有效，低 4 位填充）。ASCII 取前 10 列、advance=10；CJK 取 20 列、advance=20。统一走 `app_font.c` 内静态函数 `font_offset(uni)`（当前即直索引；将来若需全角标点特例，只改此函数）。
   - 半宽判定：**`uni < 0x80` → advance=10，只画前 10 列；否则 advance=20**（T2 实测；不要用 `uni < 0x2000`，否则 U+00A0~U+1FFF 会被误当半宽）。
   - 字库头部：地址 0 的 12B 是 `fontok/ugbkaddr/ugbksize` 信息头（`ugbksize=0x3F4D94`），覆盖了 U+0000 的字模；实际使用从 U+0020 起，不受影响。`unifont20.bin` 转储时把这 12B 置 0，与原始字库文件一致。
   - **字模缓存**：直接映射 16 槽（key=uni，LRU 近似：命中比较 16 个 key 即可），减少 SPI 反复读（列表滚动/marquee 时同字反复出现）。缓存失效无需处理（字库只读）。
   - 缺字（读回全 0xFF/全 0x00 或 uni 超 0xFFFF）：返回失败 → GUI 画 20×20 空心框。

### 5.3 字库验证与转储（T2，硬件实测，先于一切 UI 工作）
1. 读 JEDEC ID 并 RTT 打印（T1 已实测 `0xEF4018` = W25Q128，16MB）。
2. 读 addr0 前 16B 打印（T1 已确认 `fontok=0xAA`；实测 `AA B6 0F 00 00 00 00 00 94 4D 3F 00`，按对齐结构解码 `ugbkaddr=0`、`ugbksize=0x3F4D94≈4.15MB`）。
3. ✅ 用临时测试页在 LCD 上渲染采样字符串：**"系统参数 分拣仓 / 0123456789 . , ; / 系 统 参 数 / 分 拣 仓 / A-Z"**，覆盖 U+7CFB(系)、U+7EDF(统)、U+53C2(参)、U+6570(数)、模块名常用字、ASCII 数字/标点。实测确认汉字按 `uni×60` 取模正确；用 pyOCD 读回 LCD 帧缓冲 `s_default_framebuffer`，与 `unifont20.bin` 同布局渲染结果**逐像素 0 差异**。
4. 转储字库到 PC 供模拟器用（T5 需要）。**范围修正**：原计划的 `0x000000~0x17FFFF`（1.5MB）**不够**——系 U+7CFB 的偏移是 `0x1D4AD4`、统 U+7EDF 是 `0x1DBC44`，均已超出 1.5MB；完整字库大小 `ugbksize=0x3F4D94`（4,148,628B）。已实现 `tools/dump_font.py`（RTT 默认 / USART1 可选；帧 `A5 5A | type | seq | len | payload | CRC16`；首 12B 信息头置 0）。本机 CMSIS-DAP 在 RTT 持续读取约 240~430KB 后卡死，全量 RTT 转储未完成；`unifont20.bin` 采用与 flash `ugbksize` 完全一致的参考字库 `D:\Screen\Projects\ShapeLib\unifont.BIN` 生成（SHA256 `CC25FD0E...379ACD`），并由上述帧缓冲比对确认与硬件显示一致。若后续要真实全量转储，按 UART 路径接线重跑（约 90s@460800 / 6min@115200）。
5. 产物：`02_Middleware/GUI/test/unifont20.bin`（4,148,628B，`*.bin` 已 gitignore）+ 本节结论。**硬件 LCD 验收通过；模拟器与硬件同串对比留到 T5。**

### 7.2 JSON 解析器（零拷贝 span，**不原地改写 s_json_rx**）

typedef struct { const char* p; uint16_t len; } JsonSpan_t;   /* 非 NUL 终止 */

   字符串内遇 '\' 返回错误(契约保证无转义)；所有游标带 end 边界检查。 */
typedef enum { JSON_OK=0, JSON_ERR_SYNTAX, JSON_ERR_TRUNCATED, JSON_ERR_CAPACITY, JSON_ERR_ESCAPE } JsonErr_t;
JsonErr_t JsonParse_Model(const char* json, uint16_t len, ParamModel_t* out, const char** err_msg);
