> 口径：合计 150 + 34 + 6 + 11 = **201**（198 个定义 + 3 个无定义号 `0x154-0x156`）。

**一条 P1 不是"没实现"，是"号对不上"**：面板「站点类型」发 `0x1A1`，控制器 `0x1A1`（`OBJ_STATION_TYPE`）**没有 case**；控制器真正处理站点模式的是 **`0x166`（`OBJ_STATION_MODE`）**，而面板从不发 `0x166`。所以**在面板上改站点类型不会生效**，写入还会被回 `aIDErr`。

**另一条 P1 是整簇**：支轨相关的 9 个对象（`0x16D-0x175`）在控制器里**全部只有定义、`case` 被注释掉**，而面板的支轨菜单在正常发送。这批正好是多进站要用的那组号。

## 1 方法与口径

### 1.1 控制器侧怎么数的

```bash
# 定义（两个命名空间 + 水平仓）
git show 全封闭轨道/v3/develop:APP/Panel.h            | grep '^#define \(OBJ\|DATA_OBJECT\)_'
git show 全封闭轨道/v3/develop:APP/HorizWareHouse.h   | grep '^#define OBJ_'

# 生效的 case（三个 switch：Panel_WriteData@844 / Panel_ReadData@4016 / 另一处@4066）
git grep -n 'case OBJ_' 全封闭轨道/v3/develop -- APP/Panel.c     # 156

# 被注释掉的支轨 case（关键）
git grep -n 'case DATA_OBJECT_' 全封闭轨道/v3/develop -- APP      # 3 条，全部在 // 注释里
```

`DATA_OBJECT_*`（9 个，`Panel.h:248-257`）是支轨专用号段，**9 个 case 全部被注释**：

```
Panel.c:2192   //				 case DATA_OBJECT_IN_STORE_1_SENSOR:
Panel.c:2231   ////				 case DATA_OBJECT_IN_STORE_2_SENSOR:
Panel.c:2270   ////				 case DATA_OBJECT_IN_STORE_3_SENSOR:
```

### 1.2 面板侧怎么数的

面板不是硬编码对象号，而是三条来源：

1. **表映射**：`stc_S3_MSysParamTb[54]`（`MenuUI.c:37`）、`stc_S3_MIOinSetTb[]`（`:40`）、`stc_S3_MIOoutSetTb[]`（`:53`）把显示行映射成功能号，再由 `MenuParam.c` 的 `switch(PortNo)` 换成 OBJ。
2. **动态号**：`send_command_start(0x85, <基址> + MapHangNo, …)`，一共 20 多处，基址是 `0x101/0x11C/0x131/0x13E/0x146/0x148/0x14A/0x154/0x157/0x15B-21/0x160-29/0x162-31/0x163-29/0x165-31/0x175-43/0x177-27/0x17D-28/0x189-45/0x1A0-51/0x201/0x224-25/0x301/0x31F/0x339/0x359`。
3. **FE 专用**：`Menu_Fully_Enclosed_Track` 的 `ParamCMDId`/`SetIoCMDId`/`TestOutCMDId`。

所以「面板发没发」不是 grep 一个数就能定的，必须把上面三类都算进去。本轮已算，脚本口径见 §9。

### 3.6 站点类型：号对不上（P1）

```c
// 面板 MenuParam.c:1189-1201
case 52:    // 站点类型
    if (tempParaL >= 0 && tempParaL <= 1) {
        Data[0]  = (uint8_t)tempParaL;
        Data[1]  = 0x55;
        Data[2]  = 0x00;
        *DataLen = 2;
        result   = 0x1A1;          // ← 发 0x1A1
    }

// 控制器 Panel.c:3434
case OBJ_STATION_MODE:             // ← 0x166，收的是这个
    if (RecvCMD[StatNum].Databuf[0] <= 3) {
        //W25QXX_Write(&(RecvCMD[StatNum].Databuf[0]), STATION_MODE_ADDR + StatNum, 1);
        StatParam[StatNum].StatMode = RecvCMD[StatNum].Databuf[0];   // 只写内存，不落 Flash
        ret = aOK;
    }
```

- 面板写站点类型 → `0x1A1` → `OBJ_STATION_TYPE` 无 case → `aIDErr`，**不生效**。
- 控制器真正入口是 `0x166`，**面板从不发**（§4 的 B 类第一梯队）。
- 附带：`0x166` 的 `W25QXX_Write` 被注释掉 → 即使发对了，**也只写内存、掉电复位**。

## 5 与 T6-3 的关系

- T6-3 核的是**全封闭**那套（`0x501-0x56D`）＋广播帧，结论「一致」本轮维持。
- 本轮补的是**标准版**那套（`0x101-0x42B`、水平仓 `0x301-0x362`）。
- 两轮合起来，`OBJ_*` 的面基本盖全；FE 侧 `0x560`（`OBJ_FE_ORIG_CHECK`）和 `0x2007`（`OBJ_FE_READINSTATE`）面板未发，属控制器预留。

## 7 风险分级

| 级 | 内容 | 证据 | 证伪方法 |
|---|---|---|---|
| **P1** | 面板「站点类型」发 `0x1A1`，控制器只认 `0x166` → 改站点类型无效 | 面板 `MenuParam.c:1189-1201` ↔ 控制器 `Panel.h:125`（无 case）/`Panel.c:3434` | 面板改站点类型，抓 RS485 看 ObjID 是 `0x1A1`；控制器回 `aIDErr` |
| **P1** | 站点模式即使发对也只写内存不落 Flash（`W25QXX_Write` 被注释） | `Panel.c:3436-3438` | 发 `0x166` 后断电重启，读回 `StatParam.StatMode` |
| **P1** | 支轨 9 个对象（`0x16D-0x175`）控制器 `case` 全注释，面板在正常发送 | `Panel.h:248-257`、`Panel.c:2192/2231/2270`、`MenuUI.c:3002`、`key.c:750/784/1488` | 面板点支轨阀/配支轨延时，控制器回 `aIDErr`；抓包看 ObjID |
| **P2** | 站点灯/线体灯/减速阀/顶被/反转/报警器 共 11 个输出对象无解析，且 `MotionUnit` 无对应动作单元 | `MAN`；`MotionUnit.c:1793-1999` 只有 7 个 case | 面板配这几路输出，控制器不报错也不生效（`aIDErr`） |
| **P2** | 急停按钮/进站确认/缓存1满 3 个输入对象无解析 | `Panel.h:173/179/181` | 同上 |
| **P2** | 取消键/确认键/顶被键 3 个键对象无解析 | `Panel.h:216/217/221` | 同上 |
| **P2** | 备用 3 个号（`0x154-0x156`）为空号段，面板照发 | 控制器无定义 | 见 T2-5：可作为进站阀3/4 的新号 |
| **P3** | `0x16B` 桥接延迟次数无解析 | `Panel.h:220` | 面板配桥接延迟，控制器不认 |

## 8 未覆盖

1. **139 个一致项未逐字节核**：本轮只逐字节核了 4 个多字节对象（§2.1），其余按「有 case + 号一致」判为一致。
2. **未上 RS485 抓包**：全部结论来自两侧源码对读，没有线路证据。
3. **动态号的精确取值域未穷举**：`0x101+MapHangNo` 等 20 多个基址，只按菜单结构推了范围，没逐菜单把所有可能的 `MapHangNo` 列全。§4 的 13 项因此标「待人工确认」。
4. **水平仓那 13 个对象未深入**：`0x31F+HangNo`/`0x339+HangNo`/`0x359+HangNo` 三族只核了号段能对上，没核字段。
5. **`0x901`/`0xA01`/`0xA03` 只核了号存在**，没核报文长度。
6. **未验重发/超时**：面板 450ms 重发 × 2 次与控制器 DMA 忙标志的配合未验（与 T6-3 同一处遗留）。
