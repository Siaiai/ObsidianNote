# 多进站：到底多了哪些东西

> 依据：`全封闭轨道/v2/多进站支持`（`a1eafd8`）逐 hunk 实读；范围按 C27——**只给全封闭线**、满光电/支轨阀/支轨读卡器全独立。
> 「改前」= v3 `b4a5fcf`（单口）；「改后」= 多进站分支 B。

## 1. 数据结构多了什么

| 位置 | 改前 | 改后 |
|---|---|---|
| `main.h` | `IN_V_NUM 2` | **`IN_V_NUM 4`** |
| `StatParam` | `InTaskCnt`（单值） | **`InTaskCnt[4]`** |
| `StatParam` | `InHangerCnt`（单值） | **`InHangerCnt[4]`** |
| `StatParam` | `AllowRecv`（单值） | **`AllowRecv[4]`** |
| 全局 | `InTaskList[sNUM][MAX]` | **`InTaskList[sNUM][4][MAX]`** |
| 全局 | `into_pole_data_flag[sNUM][MAX]` | **`into_pole_data_flag[sNUM][4][MAX]`** |
| 全局 | `InValve[sNUM][2]`、`InFullPD[sNUM][2]`、`InValveFD[sNUM][2]`、`MotionIn[sNUM][2]` | 全部 **×4** |
| `Command_Data` | `PoleArrayFull:1`、`PoleArrayFullCancel:1`、`PoleFull:1`、`PoleFullCancel:1` | **改成数组 `[4]`**（每支轨一个标志） |
| `Command_Data` | `Come_in_station_hanger_id_apply:1` | **`[4]`**（每支轨一个上报位） |

## 2. 指令与帧多了什么（重点）

| # | 报文 | 多了什么 | 依据 |
|---|---|---|---|
| CMD-1 | 上位机 → 控制器「接收衣架」 | **`Data[4]` = 支轨号 1..4**；为 0 或 >4 时默认第 1 条支轨 | `UDP_CMD.c` `HangerRecvCmd`：`if (Data[4]>0 && Data[4]<=IN_V_NUM) z = Data[4]-1;` |
| CMD-2 | 上位机 → 控制器「拒收衣架」 | 同上写了 `Data[4]` 取支轨，**但紧接着被内层 `for(z=0;z<IN_V_NUM;z++)` 覆盖** → 实际是四条轨全搜，`Data[4]` 等于没用 | `HangerRefuseCmd` |
| CMD-3 | 上位机 → 控制器「心跳」 | 多了 **4 个「允许接收」字段**：`AllowRecv`、`CH2_AllowRecv`、`CH3_AllowRecv`、`CH4_AllowRecv`，分别写进 `AllowRecv[0..3]` | `UDP_Comu.c:265-268` |
| CMD-4 | 控制器 → 上位机「进站上报」 | **`Len` 8 → 9**，`Data[8]` = 支轨号（`j+1`，1..4） | `UDP_Comu.c` |
| CMD-5 | 控制器 → 上位机「满站/满站取消」 | 由单条变**每支轨一条**：`PoleFull[4]`、`PoleFullCancel[4]`、`PoleArrayFull[4]`、`PoleArrayFullCancel[4]` | `UDP_Comu.c:1216-1242` |
| CMD-6 | 控制器 → 上位机 | **新增 `CMD_UP_ZHI_CARD 0x08`**：上报支轨读卡器衣架号（`Command_Data.ZhiRFIDApply` 触发） | `command.h` |
| CMD-7 | 上位机 → 控制器 | **新增 `CMD_ZHI_ACK 0x0A`**：支轨阀确认 | `command.h` |

## 3. 逻辑多了什么（按流程）

### 3.1 谁决定一张衣架走哪条支轨

**上位机决定**：下发「接收衣架」时在 `Data[4]` 里点明支轨号 1..4；控制器只是按这个号把卡号塞进对应队列。

### 3.2 入队（`HangerRecvCmd`）

1. 取 `Data[4]` → `z = 支轨号-1`（0 表示第 1 条）
2. `InTaskCnt[z]++`
3. 在该支轨队列里查重（同一卡号重复下发 → 回退计数、不重复入队）
4. 该支轨任务满（`InTaskCnt[z] == InTaskMax`）→ 置 `PoleArrayFull[z]` 上报「这条轨满了」
5. 有空位 → 写卡号、置 `into_pole_data_flag[z][i]`

### 3.3 进站判定（`CheckEnterStation_`）

1. 读到卡 → 消费标志 → 300ms 过滤 → 判 `RailRun`
2. 在 4 条支轨的任务队列里逐个匹配卡号 → 命中哪条轨就返回 `ALLOWED_n`
3. 判该轨满光电是否未满
4. 结算该轨：`InHangerCnt[n]++`、清任务、`InTaskCnt[n]--`

### 3.4 进站执行

按命中的支轨号动对应阀：标准线 `InValve[stat][n]`；全封闭 `enter_station[n].enter_valveA/B`（A/B 各自保持时间 `0x505/0x506`，`dlyclose_A/B_start_time` 各自计时）。

### 3.5 上报

进站上报带支轨号（`Len=9`）；满站/满站取消按支轨各报一条；支轨读卡器上报走新增的 `0x08`。

### 3.6 出站与缓存

多支轨**不影响出站**：全封闭出站仍走 `FE_Out_Station`（`a1eafd8` 只是简化了 FE 进站/出站的状态流转，没有引入支轨维度）。

## 4. 端口多了什么

| 类别 | 多了什么 | 备注 |
|---|---|---|
| 输入 | 进站满光电从 2 路 → **4 路** | B 把第 3/4 路**复用存储 3/4 光电**（`Sensor.c:96-97`，覆盖 Flash 值、绕过冲突检查）→ **C27 定：必须独立，不复用** |
| 输出 | 无新增 | 全封闭 4 口 × A/B = 8 个阀本来就有；标准线 `InValve` ×4 |
| Flash | 五个地址全部按 `IN_V_NUM` 跨步；新增 `IN_DELAY_POLE_ADDR 0x4000`、`IN_DELAY_TP_ADDR 0x4080` | 2→4 会整体错位，必须一次改到位 |
| 串口 | 无新增，但**支轨读卡器要独立就需要** | 8 个串口已全占 |

## 5. 三个坑（合并时必须处理）

1. **进站循环只对 1 号口生效**：`BusinessLogic.c:137` 的 `else return EnterStation_REJECT` 在第一圈就返回，支轨 2/3/4 永远到不了。
2. **`is_matched` 跨圈不复位**：只删那个 `else` 会变成「卡号对不上也放行」。
3. **拒收命令的支轨号是死代码**：`Data[4]` 赋了 `z` 又被内层循环覆盖，现在实际是四条轨全搜。

## 6. 资源账（硬件核对后）

| 资源 | 真实情况 | 4 口够不够 |
|---|---|---|
| 输入 | 每站 8 路（`X01-X08`/`X11-X18`，整机 16）；全封闭现用 4 路 | 4 口满光电后 6 路，剩 2 |
| 输出 | 真实可驱动 **12 路**（`OUT_IO_1-6`、`11-16`；`0/7/8/9/10/17/18` 是空宏） | 单站要 10 路 → **一控一可以，一控二装不下** |
| 串口 | 8 个全占（4 读卡器 + 2 面板） | 支轨读卡器独立无空口 |
