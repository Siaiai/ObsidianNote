**B 的循环缺陷（实测行号）**

```c
// 全封闭轨道/v2/多进站支持:APP/BusinessLogic.c
113:  for (uint8_t in_num = 0; in_num < IN_V_NUM; in_num++)
124:      if (is_matched && InFullPD[statnum][in_num].State == 0)
132:          matched_in = in_num + EnterStation_ALLOWED_1;
137:      else
138:          return EnterStation_REJECT;   // ← 第一圈就返回
143:  return EnterStation_REJECT;           // ← 注释写着"进站成功"
```

第一圈 `in_num=0`：匹配且光电空闲 → `break`；否则 → `return REJECT`。**`in_num=1..3` 永不执行**。后果：只配在 2/3/4 号支轨的进站任务，刷卡一律按"路过"上报（`No_station_hanger_id_apply`）。

另：`is_matched` 在循环外声明，跨圈不复位——修循环时如果只删 `else`，这条会变成"上一圈匹配过就放行"。这条要在合并时一并处理，否则出现"卡号对不上也进站"。

### 3.3 `Command_Data` 位域改数组——**不改线上协议**

- `Command_Data[].COMMAND`（`command.h:152`）全仓**只声明、无读取**（`git grep "\.COMMAND\b"` 仅命中定义），实际发送是逐位判断、每位各成一帧（`UDP_Comu.c:1058/1168/1184/1194...`）。
- 所以位域改数组**只改源码写法，不改帧格式**。这点可以放心，但 union 尺寸变大（约 +15B×`sNUM`）。
- **编译面冲突**：A 侧所有 `Command_Data[..].PoleFull = 1` 这类赋值在 B 的头文件下全部报错（少了下标），需要逐处补 `[z]`。涉及 `UDP_CMD.c`（12 处）、`UDP_Comu.c`、`BusinessLogic.c`、`Panel.c`。

### 3.5 Flash 参数区随 `IN_V_NUM` 错位

| 地址 | 用途 | 跨步 |
|---|---|---|
| `IN_VALVE_N_ADDR 0x1000` | 进站阀 pinID | `+ i*IN_V_NUM + n` |
| `IN_FULL_N_PD_ADDR 0x2000` | 进站满光电 pinID | `+ i*IN_V_NUM`，一次读 `IN_V_NUM` 字节 |
| `IN_FULL_N_SENS_ADDR 0x3700` | 进站光电灵敏度 | `+ i*IN_V_NUM` |
| `IN_DELAY_POLE_ADDR 0x4000` | **B 新增**，进站阀 DlyPole | `+ i*IN_V_NUM + n` |
| `IN_DELAY_TP_ADDR 0x4080` | **B 新增**，进站阀 DlyOpenTP | `+ 2*(i*IN_V_NUM + n)` |

- `2→4` 后：站 1 的进站阀地址从 `0x1002/0x1003` 挪到 `0x1004..0x1007`；原来存在 `0x1002/0x1003` 的**旧参数会被当成站 1 的阀 3/4 读走或直接失效**。
- 0x4000/0x4080 与现有最高块 `0x39C0` 不冲突（`w25qxx.h`）。
- **全封闭侧不受影响**：FE 的参数在 `0x6140` 起的独立块，按 `statnum*0x20` 跨步，与 `IN_V_NUM` 无关。
- 含义：`IN_V_NUM` 这个改动天然要求**重新配站/重新写参数**，或者合并时另开一套 4 路的地址（这属于方案，不由我定）。

### 3.6 全封闭的进站光电是"幽灵判据"

- FE 结构体里**没有进站光电**：`FE_Enter_Station_t`（`FullyEnclosed.h`）只有 `enter_valveA/B`、`enter_shift`、`enter_pole_index`、队列和状态，无 PD 字段。
- `CheckEnterStation_` 第 5 步对所有站型都用 `InFullPD[statnum][...]`（A `:117`，B `:124`），而 FE 面板的 2 个输入只有"出站光电(0x521)"和"缓存光电(0x522)"，**没人配 `InFullPD`**。
- `InFullPD` 未配时的默认值：`n==0` → `PinID = 1 + 10*i`（`Sensor.c:89` 附近），`n>=1` → `PinID = 0` → `IN_IO_FLAG[0]`。
- 推论（需真机证伪）：FE 站 0 的进站放行条件实际挂在 `X01` 上。若 FE 面板把出站光电配成 `X01`，则出站光电亮时**进站被拒**。这是 V2/A 既有状态，不是多进站引入，但多进站把 `InFullPD` 从 1 路扩到 4 路，会让 3 路指向 `IN_IO_FLAG[0]`。

## 4 IO 端口清单

### 4.1 编号规则（两侧相同）

- 输出：`OUT_IO_MAX = 17`（`BSP/OUTPUT/Output.h:68`），pinID `0..16`；`OUT_IO_FUNC[]` 是函数指针表，`0` 号为空指针。
- 输入：`IN_IO_MAX = 19`（`BSP/INPUT/Input.h:54`），pinID `0..18`。
- 输出 pinID **7/8/9/10 被硬排除**（`MotionUnit.c:68` 等所有读 pinID 处都判 `!= 7 && != 8 && != 9 && != 10`），不能配。
- 电机：`MOTOR_IO_MAX`，`MotorPinUsed[]` 单独一套。
- 站点：`sNUM = 2`（A 站/B 站）。

### 4.2 输出端口账

| 单元 | A（IN_V_NUM=2） | B（IN_V_NUM=4） | 差异 |
|---|---|---|---|
| `InValve[sNUM][IN_V_NUM]` 进站阀 | 2×2 = **4** | 2×4 = **8** | **+4** |
| `OutValve[sNUM]` 出站阀 | 2 | 2 | 0 |
| `StoreValve[sNUM]` 下放阀 | 2 | 2 | 0 |
| `BuffValve[sNUM][11]` 缓存阀 | 22 | 22 | 0 |
| `LiftArm[sNUM][2]` 提升臂 | 4 | 4 | 0 |
| 站点灯 / 线体灯 / 报警 | 不变 | 不变 | 0 |
| **全封闭侧** `enter_station[4]` × `enter_valveA/B` | **8**（`FE_IN_VALVE_1A..4B`，`0x6140` 起 `statnum*0x20`） | **8** | **0** |

**结论：多进站对全封闭侧的输出端口是 0 变化。** FE 的 8 个进站阀在 A 里已经配好、已经从 Flash 读、已经被面板 8 个菜单项覆盖。

标准线多出的 4 个进站阀（每站 2 个）：
- Flash 位置：`IN_VALVE_N_ADDR 0x1000 + i*4 + n`（i=0 → `0x1000..0x1003`，i=1 → `0x1004..0x1007`）。
- 默认值：只有 `n==0` 有默认 `1 + 10*i`，`n=1..3` 未配即 `PinID=0`（`MotionUnit.c:68-85`）。
- 可配路径：面板输出功能"进站阀n" → `Panel.c` → `nInValve` → `InValve[StationNo][MotionNum-1]`（`MotionUnit.c:1793-1818`）。

### 4.3 输入端口账

| 单元 | A | B | 差异 |
|---|---|---|---|
| `InFullPD[sNUM][IN_V_NUM]` 进站满光电 | 2×2 = 4 | 2×4 = 8 | **+4（但其中 2 路是借的）** |
| `OutStatPD` 出站光电 | 2 | 2 | 0 |
| `BuffPD[sNUM][11]` 缓存光电 | 22 | 22 | 0 |
| 主轨推杆/气压/张紧/提升臂行程/避让/急停/按钮 | 不变 | 不变 | 0 |
| **全封闭侧** 输入 | 2（出站光电 `0x521`、缓存光电 `0x522`） | 2 | **0** |

**第 3/4 路进站光电不是新点，是复用**（`Sensor.c:96-97`）：

```c
//临时把存储3，4作为进站3，4满光电
InFullPD[i][v3].PinID = InFullPD[i][v3].PinDisp = BuffPD[i][v3].PinID;
InFullPD[i][v4].PinID = InFullPD[i][v4].PinDisp = BuffPD[i][v4].PinID;
```

后果：
1. 上面刚按 Flash 配好的 `InFullPD[i][3]/[4]` 立刻被覆盖 → **第 3/4 口满光电配不了**，用面板配了也白配。
2. 这两行写在 `for (n...)` 循环体内，每圈执行一次（无害但冗余）。
3. 缓存光电 4 亮 → 第 4 口判"满" → 第 4 口进站被拒。语义上把"缓存4满"和"进站4满"绑在一起。

面板输入菜单**不需要新增第 3/4 路进站光电项**（因为不让配）；但若以后要让它们独立，就得真加 2 个物理输入点。届时受限的是 `IN_IO_MAX=19`（`Input.h:54`，pinID 只有 `0..18`），现在输入段已占用到多少要重新点一遍——`stc_S3_MIOinSetTb` 是"功能名下标"，不等于 pin 号，不能直接拿它算余量。

### 4.4 RAM 账（未编译验证）

### 4.5 端口占用的两个边界

1. **`nInValve` 无上界校验**：`MotionUnit.c:1793` 只判 `if (MotionNum > 0)`，随后 `InValve[StationNo][MotionNum - 1]`。`IN_V_NUM=2` 时面板发 `MotionNum=3` 就越界；`IN_V_NUM=4` 时发 5 越界。这是既有问题，多进站只是把上界从 2 挪到 4，**没有修**。
2. **`CheckPinReUseConflict`**：`InFullPD` 走冲突检查（`Sensor.c:83`），但 §4.3 那两行复用**绕过了检查**，`OutPinUsed`/`InPinUsed` 不会标记 BuffPD 3/4 被二次占用。

### 5.2 多进站需要 FE 面板加什么

**答案：0 项。**

- 4 个进站口距离（`0x508-0x50B`）已在。
- 4 个进站口只读偏移已在（`FEParamPack` 18 项顺序与之逐项一致，见 T6-3）。
