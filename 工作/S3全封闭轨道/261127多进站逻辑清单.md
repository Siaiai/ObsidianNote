## 0 一句话结论

**「多进站」的缺口只在三个地方：谁决定支轨、队列按支轨拆、上报带支轨号。**
FE 侧的执行层（4 支轨状态机、每支轨 A/B 阀、推杆绑定、进站偏移）**A 里本来就有，而且 A/B 两侧逐字相同**——`FE_StartEnterStation` 早就接 `branch_rail` 参数，`brach_rail_name[0..3]` 也早就初始化为 `FE_ENTER_1..4`。

B 真正贡献的是：`IN_V_NUM 2→4` 的数据模型、`Data[4]` 选支轨、`CheckEnterStation_` 返回 `ALLOWED_1..4`、上报 `Len=9`。**但这 4 笔里有 5 个硬缺陷**（§7），其中 2 个是本次合并会让全封闭线变坏的方向。

## 2 环节二：进站判定

### 改前（A）：`BusinessLogic.c:86-140`

单层查找，返回 `EnterStation_ALLOWED`（`BusinessLogic.h` 只有 3 个值：`NOCARD/REJECT/ALLOWED`）。

顺序（A，已按 a119 口径修过）：
1. `RecvFlag[B] != 1` → NOCARD
2. `RailRun != 1` → NOCARD（**不消费、不计时**）
3. `InStatDlyTC != 0` → NOCARD
4. **消费** `RecvFlag[B]=0`，**重置** `InStatDlyTC`
5. 站型门：只对 `wmStandard`/`wmHorizWareHouse` 查 `InValve.PinID`
6. `InFullPD[stat][v1].State != 0` → REJECT
7. 单层找任务 → 找到就 `InHangerCnt++`、清任务、`InTaskCnt--`、返回 ALLOWED

### 改后（B）：`BusinessLogic.c:87-145`

- 返回值扩成 `ALLOWED_1..4`（`BusinessLogic.h:23-28`），**告诉上层走哪条支轨**
- 查找变双层：`for(in_num=0..IN_V_NUM)` × `for(taskindex=0..InTaskMax)`
- **顺序回退**：`RecvFlag[B]=0` 消费（`:94`）和 `InStatDlyTC` 重置（`:101`）都被挪到 `RailRun` 判断（`:105`）**之前**
- **去掉了站型门**：`wmFullyEnclosed` 也要过 `InValve[...].PinID == 0` 这一关

### 对全封闭站的影响

| 项 | 影响 |
|---|---|
| 支轨定位 | 靠"卡号在哪个支轨的队列里"反查——**这层设计是对的**，与 `Data[4]` 入队配对 |
| **硬缺陷①：早退** | `:136-138` 的 `else return EnterStation_REJECT` 写在 `for(in_num)` 里，**第一圈没匹配就返回** → 支轨 2/3/4 永远到不了 |
| **硬缺陷②：`is_matched` 不复位** | 跨圈残留，修早退时若只删 `else`，会变成"上一圈匹配过就放行" |
| **硬缺陷③：轨道不稳也消费卡号** | B 在 `RailRun` 判断前就 `RecvFlag[B]=0` + 置 300ms → 轨道抖动时这张卡**直接丢**，且 300ms 内后续卡也被吞 |
| **硬缺陷④：全封闭被 `InValve` 门挡住** | FE 全文件零引用 `InValve`，`PinID` 恒为 0（除 n=0 默认 `1+10*i`）→ 若照 B 加上这个门，**全封闭进站全部判 REJECT** |
| `a1eafd8` 修了什么 | 只把 `for (uint8_t in_num; ...)` 补成 `in_num = 0`（原来**未初始化**，比早退更早出问题）。**早退没修** |

**B 的 `FE_PROCESS`（`FullyEnclosed.c:1337` 起）**：

### 对全封闭站的影响（这条最重）

| 变化 | 后果 |
|---|---|
| **`for(statnum < sNUM)` 被删** | `statnum` 恒为 0 → **B 站的 FE 业务完全不执行**。一控二时第二站死掉 |
| **固定周期块移出 `if` 且无循环** | 只有 0 号站，而且**不再受 `wmFullyEnclosed` / `Lan8720InitFlag` / 升级状态门控**：标准站也会跑 FE 的 `FE_OutBuff/FE_NewPoleDeal/FE_PoleUpdate/...`，升级中（`sRecive/sErase`）也照跑 |

## 7 异常路径（单列）

| 场景 | A 的行为 | B 的行为 | 问题 |
|---|---|---|---|
| 卡号一条支轨都匹配不上 | 单层没找到 → `EnterStation_REJECT`，`Func_InStation` 把 `RecvFlag[B]` 塞回，置 `No_station_hanger_id_apply` 上报"路过" | 同左，但**第一圈就返回** | 支轨 2/3/4 的卡**全部**按"路过"上报 |
| 多口同时来卡 | 不适用（1 口） | 只有 `in_num=0` 会被检查 | 早退缺陷①② |
| 目标支轨满 | `InFullPD[stat][v1].State != 0` → REJECT | `InFullPD[stat][in_num].State != 0` → REJECT | 对 FE 站，`InFullPD` 是**标准线数组**，FE 面板不配它（FE 只有 `0x521/0x522` 两个输入）→ 判据挂在未配置的输入上 |
| 轨道不稳（`RailRun != 1`） | 不消费卡号、不置 300ms → 稳定后还能进 | **已消费 + 已置 300ms** → 这张卡丢 | 硬缺陷③ |
| 重复读同一张卡（300ms 内） | `InStatDlyTC` 过滤 | 同上，但计时在 `RailRun` 之前就起 | 轨道抖动时过滤窗被无谓消耗 |
| 支轨读卡器失联 | 不适用 | 用 `RFIDLostTC[ZhiReader[z].UartName]` 计时（`RFIDReader.c:705`） | `R_UART_NAME_ENUM` 是**稠密索引** 0..6（`nUartNull=0`…`nUart7=6`），`RFID_NUM=7` → **不越界**（已核，排除误报） |
| 支轨阀无动作/不匹配 | 不适用 | `Func_ZhiValve`：`ZhiStoreFullPD` 满 → `zFull`；`ZhiReader[i].ID != ZhiHangerID[i]` → `zUnMatch`；动作完成 → `ZhiReleaseAck[i]` | **硬缺陷⑥**：`StatParam[i].InHangerCnt[i]` 用支轨号当站号 → 越界写 |
| 上位机不发 `Data[4]` | 不适用 | 静默落到支轨 0 | 无告警，4 口退化成 1 口 |
| 上位机发「清进站寄存器满」 | 清队列 + 回 ACK | **整段注释，不清也不回 ACK** | 回归，上位机会重发到超时 |
