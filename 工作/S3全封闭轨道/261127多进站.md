# 多进站（全封闭线）

> **一句话**：多进站的缺口只在三处——**谁决定支轨、队列按支轨拆、上报带支轨号**；FE 侧执行层（4 支轨状态机、每支轨 A/B 阀）在 A 里本来就有、且 A/B 逐字相同。B 的 4 笔语义提交里带 **6 个硬缺陷 + 3 处回归**，所以方案是**不合 B、在 v3 上补三层**。
>
> **基线**：A（目标侧）= `全封闭轨道/v3/develop` @ `b4a5fcf`；B（来源侧）= `全封闭轨道/v2/多进站支持` @ `a1eafd8`；面板 = `D:\Screen\HangerOperatePanel\Operation_Panel` @ `C2-全封闭轨道/develop` `bb89359`（C2A）。
> **依据**：全部来自 `git show` / `git diff` 只读比对，**未编译、未上板**。
> **来源**：本文合并 `261127多进站功能清单.md`、`261127多进站逻辑清单.md`、`261127T2-5多进站差异与端口清单.md` 三份底稿（原文件已删除）。

### 2.3 逻辑流程

**① 谁决定支轨——上位机决定。** 下发「接收衣架」时在 `Data[4]` 点明支轨号 1..4，控制器只按这个号把卡号塞进对应队列；不靠卡号在哪个队列里反查。两帧同 ID 会分别落到不同支轨。

**② 入队 `HangerRecvCmd()`**（A `UDP_CMD.c:32-88`）

1. 取 `Data[4]` → `z = 支轨号-1`（0 → 第 1 条）
2. `InTaskCnt[z]++`
3. 该支轨队列查重（同卡号重复下发 → 回退计数、不重复入队）
4. 该支轨任务满（`InTaskCnt[z] == InTaskMax`）→ 置 `PoleArrayFull[z]` 上报「这条轨满了」
5. 有空位 → 写卡号、置 `into_pole_data_flag[z][i]`

队列写点 4 处（都多一维）：`UDP_CMD.c:73`（入队）、`UDP_CMD.c:216`（拒收清）、`BusinessLogic.c:133`（进站消费）、`main.c:221`（上电初始化）。

**③ 进站判定 `CheckEnterStation_`**

- A（`BusinessLogic.c:86-140`，单层）：`RecvFlag[B]!=1` → NOCARD；`RailRun!=1` → NOCARD（**不消费、不计时**）；`InStatDlyTC!=0` → NOCARD；**消费** `RecvFlag[B]=0` + 重置 `InStatDlyTC`；站型门（只对 `wmStandard`/`wmHorizWareHouse` 查 `InValve.PinID`）；`InFullPD[stat][v1].State!=0` → REJECT；单层找到 → `InHangerCnt++`、清任务、`InTaskCnt--`、返回 `ALLOWED`。
- B（`BusinessLogic.c:87-145`，双层）：返回值扩成 `ALLOWED_1..4`；`for(in_num<IN_V_NUM)` × `for(taskindex<InTaskMax)`；**顺序回退**（消费/计时挪到 `RailRun` 之前）；**去掉站型门**。

**④ 进站执行**：按命中支轨动对应阀。标准线 `InValve[stat][n]`；全封闭 `enter_station[n].enter_valveA/B`（A/B 各自保持时间 `0x505/0x506`，`dlyclose_A/B_start_time` 各自计时）。

**⑤ 上报**：进站上报带支轨号（`Len=9`）；满站/满站取消按支轨各报一条；支轨读卡器上报走新增 `0x08`。

**⑥ 出站与缓存**：不影响（见 §1 范围边界）。

| `IN_DELAY_TP_ADDR 0x4080` | B 新增，进站阀 DlyOpenTP | `+ 2*(i*IN_V_NUM + n)` |

- 2→4 后：站 1 进站阀地址从 `0x1002/0x1003` 挪到 `0x1004..0x1007`；原 `0x1002/0x1003` 的旧参数会被当站 1 的阀 3/4 读走或直接失效。
- `0x4000/0x4080` 与现有最高块 `0x39C0` 不冲突。
- **全封闭侧不受影响**：FE 参数在 `0x6140` 起独立块，按 `statnum*0x20` 跨步，与 `IN_V_NUM` 无关。
- 含义：`IN_V_NUM` 改动天然要求**重新配站/重新写参数**，或另开一套 4 路地址（属方案，不由清单定）。

### 3.9 全封闭的进站光电是「幽灵判据」

- FE 结构体里**没有进站光电**：`FE_Enter_Station_t` 只有 `enter_valveA/B`、`enter_shift`、`enter_pole_index`、队列和状态，无 PD 字段。
- `CheckEnterStation_` 对所有站型都用 `InFullPD[statnum][...]`（A `:117`，B `:124`），而 FE 面板 2 个输入只有「出站光电 `0x521`」「缓存光电 `0x522`」——**没人配 `InFullPD`**。
- 默认值：`n==0` → `PinID = 1 + 10*i`（`Sensor.c:89` 附近）；`n>=1` → `PinID = 0` → `IN_IO_FLAG[0]`。
- 推论（**需真机证伪**）：FE 站 0 的进站放行条件实际挂在 `X01` 上；若把出站光电配成 `X01`，出站光电亮时进站被拒。这是 V2/A 既有状态，不是多进站引入；但 `InFullPD` 从 1 路扩到 4 路会让 3 路指向 `IN_IO_FLAG[0]`。

## 6. 资源账

### 6.1 编号规则（两侧相同）

- 输出 `OUT_IO_MAX = 17`（`BSP/OUTPUT/Output.h:68`），pinID `0..16`；`OUT_IO_FUNC[]` 是函数指针表，`0` 号为空指针。
- 输入 `IN_IO_MAX = 19`（`BSP/INPUT/Input.h:54`），pinID `0..18`。
- 输出 pinID **7/8/9/10 被硬排除**（`MotionUnit.c:68` 等处都判 `!= 7 && != 8 && != 9 && != 10`），不能配。
- 电机 `MOTOR_IO_MAX`，`MotorPinUsed[]` 独立一套；站点 `sNUM = 2`。

### 6.2 输出账

| 单元 | A（`IN_V_NUM=2`） | B（`IN_V_NUM=4`） | 差异 |
|---|---|---|---|
| `InValve` 进站阀 | 2×2 = 4 | 2×4 = 8 | **+4** |
| `OutValve` / `StoreValve` | 2 / 2 | 2 / 2 | 0 |
| `BuffValve[11]` | 22 | 22 | 0 |
| `LiftArm[2]` | 4 | 4 | 0 |
| 站点灯/线体灯/报警 | 不变 | 不变 | 0 |
| **全封闭** `enter_station[4]` × A/B | **8**（`0x6140` 起 `statnum*0x20`） | **8** | **0** |

**结论：多进站对全封闭侧输出端口 0 变化。** FE 的 8 个进站阀 A 里已配好、已从 Flash 读、已被面板 8 个菜单项覆盖。

标准线多出的 4 个进站阀：Flash `0x1000 + i*4 + n`（i=0 → `0x1000..0x1003`，i=1 → `0x1004..0x1007`）；默认只有 `n==0` 有 `1+10*i`，`n=1..3` 未配即 `PinID=0`（`MotionUnit.c:68-85`）；可配路径 面板输出「进站阀n」→ `nInValve` → `InValve[StationNo][MotionNum-1]`（`MotionUnit.c:1793-1818`）。

### 6.3 输入账

| 单元 | A | B | 差异 |
|---|---|---|---|
| `InFullPD` 进站满光电 | 2×2 = 4 | 2×4 = 8 | **+4（其中 2 路是借的）** |
| `OutStatPD` / `BuffPD` | 2 / 22 | 2 / 22 | 0 |
| 主轨推杆/气压/张紧/提升臂行程/避让/急停/按钮 | 不变 | 不变 | 0 |
| **全封闭** 输入 | 2（`0x521`、`0x522`） | 2 | **0** |

第 3/4 路不是新点、是复用（`Sensor.c:96-97`，注释写「临时」）：

### 6.4 串口与「一控二被牺牲」

- 8 个串口全占（4 读卡器 + 2 面板）。B 把 4 个支轨读卡器固定指到 `nUart4/nUart7/nUart1/nUart6`（`RFIDReader.c:82-89`），其中 `nUart6` 与出站读卡器**二选一**（`ReaderEnSta.Out` 为 1 给 OutReader，否则给 `ZhiReader[3]`）。
- A 的 `RFID_Init` 按 `for(i < sNUM)` 初始化两站 `InReader/StoreReader/OutReader`；**B 只初始化 `[0]`**，第二站读卡器不再被赋值（A `RFIDReader.c:58-110` ↔ B `:60-90`）。
- **即 B 等价于「一控一 + 4 个支轨读卡器」，一控二在它里面已被砍掉。**

### 6.5 真实可驱动资源（硬件核对）

| 资源 | 真实情况 | 4 口够不够 |
|---|---|---|
| 输入 | 每站 8 路（`X01-X08`/`X11-X18`，整机 16）；全封闭现用 4 路 | 4 口满光电后 6 路，剩 2 |
| 输出 | 真实可驱动 **12 路**（`OUT_IO_1-6`、`11-16`；`0/7/8/9/10/17/18` 是空宏） | 单站要 10 路 → **一控一可以，一控二装不下** |
| 串口 | 8 个全占 | 支轨读卡器独立无空口 |

一控二 + 4 口全配需 8 口 × A/B = **16 路输出**，现板只有 12 路 → **配不满，只能按配置取舍**；「一控二 + 4 口」在现板上是「逻辑支持、开几口算几口」，跑满要等新板。

### 6.6 端口占用的两个边界

1. **`nInValve` 无上界校验**：`MotionUnit.c:1793` 只判 `if (MotionNum > 0)`，随后 `InValve[StationNo][MotionNum-1]`。`IN_V_NUM=2` 时发 3 越界；=4 时发 5 越界。既有问题，多进站只把上界从 2 挪到 4，**没修**。
2. **`CheckPinReUseConflict`**：`InFullPD` 走冲突检查（`Sensor.c:83`），但 §6.3 那两行复用**绕过检查**，`OutPinUsed`/`InPinUsed` 不标记 BuffPD 3/4 被二次占用。
