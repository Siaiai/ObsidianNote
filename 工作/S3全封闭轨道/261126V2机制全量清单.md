# V2 机制全量清单（全封闭 v2 基线）

> **一句话**：以已批量验证的 `全封闭轨道/v2/develop@3cf2b62` 为唯一事实源，把全封闭线的 **24 个机制**逐条落到函数级：位置、职责、触发条件、关键常量、与标准版的关系、实测状态。这份清单是 `全封闭轨道/v3/develop` 重做的「不许丢」底单。
> **依据**：全部来自 `git show 全封闭轨道/v2/develop:<file>` 只读比对，**没有上板实测**；凡未实测一律标「未实测」。
> **不含**：标准版独有机制（见 `261029S3维护.md`）、多进站 0t 分支机制（不在本仓库）。
> **状态**：`261128` 之前的所有 V3 结论作废，本清单是重做起点。

## 0. 怎么用这份清单

1. 重做时按 M01~M24 逐条对：**v3 分支上必须存在、且行为一致**。
2. 每条后面的「实测」列只有 `代码`（读到实现）或 `未实测` 两档，没有第三种。
3. §5 的扩展点表是「收口」判据——V2 里全封闭对标准版的侵入一共 **15 处判定 + 17 处调用**，这是重做时扩展点的上限。
4. 表里 `FE_` 位置行号均为 V2 `3cf2b62` 行号，切分支后行号会变，**以函数名为准**。

## 2. 数据模型（重做时必须同构）

### 2.1 每站状态 `FE_station_t`

| 字段 | 类型 | 含义 |
|---|---|---|
| `statnum` | u8 | A/B 面（0/1） |
| `initialized` | u8 | 参数装载完成 |
| `config` | `FE_Config_t` | 8 个参数量（见 §4.1） |
| `GetTimeMs` | 函数指针 | 时间基准，注入 `GET_SYSTICK_MS` |
| `enter_station[4]` | `FE_Enter_Station_t` | 四个进站口，各自独立状态机 |
| `pole` | `FE_Pole_Fifo_t` | 推杆队列 |
| `out_station` | `FE_Out_Station_t` | 出站（含出站缓存子结构） |
| `test_out` / `test_in` | 调试 | 面板调试 |
| `enter_function` | u8 | 进站算法：0 衣架、1 推杆 |

全局 `FE_Func_t`：`station[2]` + `GetTimeMs` + `stop_main_rail_flag/time` + `stop_err` + `stop_rail`。

### 2.2 推杆队列 `FE_Pole_Fifo_t`（核心）

- `poles[IN_TO_OUT_POLE_MAX]` 环形，`head` 离出站口最近、`tail` 最远。
- `FE_Pole_t`：`addtime`（入队时刻，**全部时机的 0 点**）、`occupy`（`0x00` 无效 / `0xAA` 有衣架 / `0x55` 无衣架）、`HangerID`、`branch_rail`。
- 另有 `newpole`（读卡器触发）、`new_enter`/`enter_hanger_id`/`branch_rail`/`enter_hanger_start_time`（进站任务）。

> [!important] 时机基准
> 所有判定都是 `get_time_diff(addtime, now)` 与 `out_shift` / `enter_shift` 比较，**没有独立定时器**。重做若改用别的基准，全盘时机都会漂。

### 2.3 状态机枚举

| 枚举 | 值 | 用途 |
|---|---|---|
| `FE_Enter_Station_State_t` | `IDLE → WATE_OPEN → WATE_CLOSE → FINISH` | 四个进站口 |
| `FE_Out_Station_State_t` | `IDLE → ANTISHAKE → WATE_OUT → OUTING` | 出站 |
| `FE_Out_Buff_State_t` | `IDLE → FIRST_ANTISHAKE → WATE_OPEN → WATE_CLOSE` | 出站缓存 |
| `FE_Out_Res_State_t` | `WAIT_RES / SUCCESS / FAIL` | 出站结果 |
| `FE_Motor_Err_t` | `NullErr / Rail / Raise / HorizWarehouse / PowerOut` | 急停上报源 |

## 3. 关键机制细节

### M02 主处理顺序（不可换序）

```
for 站 in [0,1]:
  若 该站==全封闭 且 网口已初始化 且 不在 接收/擦除 状态:
      4 个进站口: enter_function==0 → FE_HangerEnterStation; ==1 → FE_PoleEnterStation
      FE_OutStation
      FE_PowerOutStateUpload
  # 以下固定周期，不看线体类型
  FE_OutBuff → FE_NewPoleDeal → FE_PoleUpdate → (FE_EnterTaskUpdate 已注释) → FE_HangerToEnterUpdate → FE_TestOut_Test_Read
FE_LineControl
```

> `FE_EnterTaskUpdate` 在 V2 里**被注释掉**（`FullyEnclosed.c:1187`），注释原文「先不加这个逻辑，也没问题」。这代表：进站任务超 500ms 的清理只发生在 `FE_NewPoleDeal` 内部匹配路径，没有独立兜底。重做要不要补——**待确认，V2 现状是不补**。

### M04 偏移换算（重做最容易算错的一处）

```
out_shift   = ((width − 25 − 6) / (railspeed/30) − trip / (outspeed/30)) × 1000   [ms]
enter_shift = effective_distance / (railspeed/30) × 1000                          [ms]
```
- `railspeed` 存的其实是**主轨电机转速**（`FE_ParamInit`：`(50.0/(PolePerd/1000.0))×30`，1.2s/推杆 → 1250），`/30` 后 ≈ 线速度 cm/s。
- `width` = 进站读卡器到出站口距离（cm）；`−25` = 半个推杆；`−6` = 机械误差。
- `trip`/`outspeed` = 动力出站行程与速度，`/(outspeed/30)` 换成秒。
- 衣架算法：`effective_distance = distance`；推杆算法：`distance > FE_ENTER_DISTANCE_BIAS_CM ? distance − BIAS : 0`。
- 两者都有下限 `FE_SHIFT_MIN_WINDOW`。
- **单位依赖参数配置口径**，`FE_ENTER_DISTANCE_BIAS_CM` 当前值**未在本清单核实**（见 §7）。

### M06 新推杆入队（`FE_NewPoleDeal`）

1. `CtrlParam.ChainStart != 1` → 直接返回（**只在整链启动后才认推杆**）。
2. `pole.newpole == 1` 才处理，处理后清零。
3. 过滤：距 `last_add_pole_time` 不足 `FE_POLE_FLT`(1000ms) → 丢弃（多读卡器同推杆去重）。
4. 若配置了 `ReaderSelect` 且是本控制器读卡器：置 `RailPDTC`，前 3 个推杆只计数 `PreCnt`，第 4 个起 `CtrlParam.RailRun=1`，并按 `PolePerdMin/Max` 置 `PushLessFlg`/`PushMoreFlg`（推杆过密/过疏故障源）。
5. `RailRun != 1` → 不入队。
6. 入队取值：`InReader[站].ID_In.Val == 0` → 空推杆（`0x55`）；否则看 `new_enter`：
   - 衣架 ID 一致 + 任务在 500ms 内 → `occupy=0x55`（判为要进站）+ 带 `branch_rail`；
   - 衣架 ID 一致但超 500ms → 清支轨；**推杆算法下改回 `0xAA`**（这个衣架不进站）；
   - 不一致 → `0xAA`。
   - 无论哪种，有任务就消费 `new_enter`。

### M07 推杆刷新（`FE_PoleUpdate`）

1. `head` 无效 → 返回。
2. `StatParam[站].AvoidPDFlg == 1` → 清零并把 **HEAD** 推杆置 `0xAA`。这是「避让光电」唯一消费点，**HEAD 语义即「即将出站的那根」**。
3. `head.addtime` 超过 `out_shift` → 弹出（这根推杆已过出站口）。

### M10/M11 进站状态机（两套，同一状态枚举）

| 状态 | 衣架算法（M10） | 推杆算法（M11） |
|---|---|---|
| IDLE | 队列非空即进 WATE_OPEN | `FE_SearchPoleByBranchRail` 找到带支轨的推杆才进 |
| WATE_OPEN | 时间差 > shift → 出队回 IDLE；< shift−50 等待 | 超 shift → 清该推杆支轨回 IDLE；< shift−50 等待 |
| 触发 | 落在 `[shift−50, shift]` 且 `RailRun==1`、A/B 阀 `pinID!=0` | 同左，额外把该推杆置 `0x55`、清支轨与 ID、弹不出队 |
| WATE_CLOSE | 窗口内可「连续进站」再开阀并出队 | 窗口内可「连续进站」再开阀并消费该推杆 |
| 关闭 | A 超 `valveA_keep_open_time` 关、B 超 `valveB_keep_open_time` 关；都关 → IDLE | 同左 |

> 关键细节：**阀打开失败（`pinID==0`）时，衣架算法出队、推杆算法清支轨**——即「任务被消耗但不进站」。这是 V2 明确选择的行为，重做不许「顺手改成重试」。

### M12 出站状态机（`FE_OutStation`）

| 状态 | 行为 |
|---|---|
| IDLE | ① 空闲 >15s 且 `OutCnt >= OutLimit` 且缓存光电无衣架 → `OutCnt=0`（防人为压缓存）；② 判「有衣架」：光电模式看 `out_PD`，读卡模式看 `OutReader.ID != 0`；③ 有 → 记 `out_process_start_time`、`anti_shake_start_time`，进 ANTISHAKE |
| ANTISHAKE | 超 `FE_OUTING_MAX_TIME`(10s) → 回 IDLE；衣架被晃开 → 重置防晃起点、**留在 ANTISHAKE**（防止放行新衣架）；满 `FE_ANTISHAKE_TIME`(200ms) → WATE_OUT |
| WATE_OUT | 衣架不在 → 回 ANTISHAKE（跳过 IDLE）；放行条件全满足才继续：`RailRun==1`、`out_valve.pinID!=0`、`NextFull!=FULL`、`is_masked!=0x55`、读卡模式下要 `BridgeOutAck!=0`（除非 M22 生效）；`head.occupy==0x55` 且时间落在 `[out_shift−50, out_shift]` → `FE_PolePopHead` + `StatMotorInitCallback(mtPowerOut,…,FE_OutValveOpen_)` → OUTING |
| OUTING | 等出站周期 `trip/(speed/30)×1000+100`；到点关阀、`BridgeOutAck=0`；若 `SUCCESS` 但出站口仍有衣架 → 改判 `FAIL` 并 `SendFault(dOutMtrDrv,CH1,FE_UNACT)`（**只在之前无错时报**）；`SUCCESS` → `OutCnt--`、有旧错则 `SendFault(rCancel)`；回 IDLE |

> `FE_UNACT = 13`、`FE_UNALIGNED = 12`，两个都是出站电机故障码。

### M13 出站缓存状态机（`FE_OutBuff`）

`IDLE`（光电高→记时间进 FIRST_ANTISHAKE）→ `FIRST_ANTISHAKE`（2s 内光电消失回 IDLE；满 2s 进 WATE_OPEN）→ `WATE_OPEN`（**三道互锁**：出站状态必须 `FE_OUT_IDLE`、出站光电必须无衣架、`OutReader.ID==0`；都满足才开缓存阀、记 `open_time`）→ `WATE_CLOSE`（保持 `FE_BUFF_KEEP_OPEN_TIME` 1s 后关阀回 IDLE）。

### M14 出站电机回调（`FE_OutValveOpen_`）

`result == R_SUCCESS` 才开阀；读卡模式下顺带清卡号。失败路径不改状态机，由 M12 的周期超时兜底。

### M15 动力出站状态上报（`FE_PowerOutStateUpload`）

- `power_out_ready = MotorSta[mtPowerOut+站].State.sta.Custom & 0x01`；电机离线则**直接置 1**（当作未校准）。
- 每 1000ms 且 `RailRun != 1` 时置 `Command_Data[站].link_test = 1; Command_Num++`（借用链路测试上报槽位）。
- 在线时比对 `Error` 与上次：变 0 发 `rCancel`，变非 0 发 `rFault`，故障码用电机自身 `Error`。

### M16 急停（两处入口 → 一个出口）

- `FE_LineControl`：`stop_main_rail_flag` 且距今 >3000ms → 清标志 + `RailMotorInit(0)`。
- `stop_err != NullErr` → 组 `0xFA / CTRL_CMD_G3 / CMD_ERR_EMS` 广播帧、`UDP_SendOut(dBoradcast)`、`Motolan_UDPRecive()`，然后清 `stop_err`。
- 入口：`main.c:193`（主轨停）、`UDP_Comu.c:1970`（上位机停线）、`FaultDetect.c:777`（线控制器报错，先置 `FE_Instance.stop_err = Rail`）。

### M17/M18 参数与端口

- 面板侧对象号：`OBJ_FE_* 0x504~0x50D`（参数）、`0x521/0x522`（输入）、`0x541~0x54A`（输出阀）、`0x560~0x56D`（调试输出）、`0x2006/0x2007`（参数包/读状态）。
- Flash 侧每参数一块 0x40：`0x6000` 进到出距离、`0x6040` 出站行程、`0x6080` 出站速度、`0x60C0/0x6100` 阀 A/B 保持、`0x62C0` 主轨速度、`0x6140~0x6440` 十个阀、`0x6240/0x6280` 两个光电、`0x6480~0x6540` 四个进站距离、`0x6580` 进站方式、`0x65C0` 停轨开关。
- 写面板 → `FE_PNL_WriteData` 同步刷新 `config` 并 `FE_RecalcShift_`（改参数即时生效，不需重启）。

### M21/M22 出站放行判据

`NextFull == FULL`（下一站满）或 `is_masked == 0x55`（本站屏蔽）→ 不放行。
`ReaderEnSta.Bits.Out == 1`（出站读卡模式）时默认要 `BridgeOutAck != 0`；若该站被配置成「下放读卡器」(`FE_OUT_READER_DETECT_ONLY`)，跳过这条确认，读卡器只用来判「有没有衣架」。

## 5. 扩展点：全封闭对标准版的全部侵入

### 5.1 判定点（15 处，重做后应等价于「每站一个算法选择」）

| 模块 | 行 | 判定 | 作用 |
|---|---|---|---|
| `BusinessLogic.c` | 144 | `case wmStandard` | 标准业务分支 |

## 6. 已知行为与「看起来像 bug」的地方

以下都是 V2 现状，**批量机在用**，重做时按原样保留，除非用户明确要改：

1. `FE_EnterTaskUpdate` 被注释 → 进站任务没有独立超时兜底（见 M02）。
2. 阀打开失败时任务被消耗而非重试（见 M10/M11）。
3. `FE_NewPoleDeal` 在 `ChainStart != 1` 时完全不认推杆 → 整链启动前的读卡不入队。
4. 动力出站电机离线时 `power_out_ready` 直接置 1（不可校准），上报口径与在线时不同。
5. 空闲 15s 清 `OutCnt` 有前置条件「缓存光电无衣架」，防止人为压缓存。
6. `FE_PROCESS` 里「固定周期」那组**不看线体类型**，标准站也会跑 `FE_OutBuff`/`FE_NewPoleDeal`/`FE_PoleUpdate`（内部靠 `pinID==0`/`ChainStart` 自我短路）。这是 V2 的写法，重做时如果加判据，会改变标准站行为——**待确认**。

## 8. 与旧 V3 机制登记的差异

旧 V3 的「机制登记」表只有 11 行，本清单 24 项。差在：

- 旧表把「进站」合成一行，本清单拆成 M05~M11 七项（队列/入队/刷新/任务/两套状态机），因为**这是重做最容易丢细节的地方**。
- 旧表没有 M21/M22（出站放行判据组合、读卡仅检测）——这两条是 V2 上真实存在的分支，缺失会导致「出站不放行」类故障。
- 旧表没有 M23/M24（缓停、线控制器报错停轨）——它们是跨模块机制，不在 `FullyEnclosed.c` 里。
- 旧表的「线体算法 `AlgoSel`」是 V3 新增设计，**V2 里不存在**；V2 用的是 `exFunction_En == wmFullyEnclosed`。重做是否改名，属架构决定，不在本清单范围。
