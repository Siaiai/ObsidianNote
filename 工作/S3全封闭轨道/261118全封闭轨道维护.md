## 2. 契约 v2（2026-11-19）

- 帧格式沿用 `0xFA CMD1 CMD2 CMD3 LineNo StatNo LenHi LenLo Data`；空推杆上报用**新码 `0xC2`**（`CMD2=0x01`），建议 `Len=2`：`Data[0]` = 去重序号（每站自增或取 `addtime` 低 8 位），`Data[1]` 保留 0，站号走帧头 `StatNo`；去重键 `LineNo + StatNo + 序号`（**帧内容待与上位机确认**）
- 不复用标准线 `0xC1`：它报的是「避让光电触发＝有衣架」，与本需求相反（← D1）
- 判空依据（全封闭模型）：推杆 FIFO `FE_Pole_Fifo_t` 的 `poles[head].occupy == POLE_NO_HANGER`（`0x55`）。来源是双源：`FE_NewPoleDeal` 的读卡判定（推杆到来前 500ms 内读到卡才算有衣架）+ `FE_PoleUpdate` 的避让光电置位（二次保险）
- 时间基准：一律用 `poles[head].addtime + out_station.out_shift`（下称「出站时机点」），`out_shift` 由 `CALC_OUTSHIFT` 计算：`((站宽−25−6)/(主轨转速/30) − 出站行程/(出站转速/30))×1000`；按调试说明取站位 165cm / 行程 79cm / 1250·1500 rpm → **1636ms**
- **仓出站要注意**：进到出 108cm 代入同式只有 **268ms**，小于避让光电提前的 600ms → 「时机点前 25cm」的装法在仓出站不成立（光电会早于推杆入队）；仓出站要么不配避让光电，要么单独定位置（**待现场确认**）
- 光电位置：装在出站时机点前 **25cm**（半个推杆）→ 触发时刻 = 出站时机点 **前 600ms**（1636−600=1036ms）
- 首发时机：**窗口中点** = 出站时机点前 **300ms**；三帧 `−300 / −100 / +100 ms`（相对出站时机点），第 3 帧落在出站动作之后，属预期
- 出站判定窗：`FE_OutStation` 的 `WATE_OUT` 只在 `[out_shift−50, out_shift]` 这 **50ms** 内判定；上报帧全部在此之前发出
- 重发：首发 + 2 次重发（共 3 帧），超时 **200ms**；收到上位机应答即停；3 帧后静默丢弃，不报故障
- 版本号：全封闭 v2 线改动必须递增 `ControlVer`（当前 V3.3.05.8）

## 3. 方案

按 `FullyEnclosed.c` 的真实链路实现（← D1 / C2）：

- **判空与启动**：在 `FE_PoleUpdate` 里 `AvoidPDFlg` 触发时（代码 1042-1047 行，此时 HEAD 就是 600ms 后要出站的推杆），若 `poles[head].occupy == POLE_NO_HANGER`，结束「等待」并算出上报时刻 `report_due = poles[head].addtime + out_shift − 300`。
- **发送**：`FE_PROCESS` 每轮检查 `now >= report_due`，置 `Command_Data[站].AvoidPDReport = 1` + `Command_Num++`，由 `Pc_UDPSend` 沿用现有排队发出 `0xC2`（每轮一帧，不抢其它上报）。
- **重发**：每站一组字段（`report_last_time` / `report_sent` / `report_due`），`FE_PROCESS` 里 200ms 到期且 `report_sent < 3` 就再置一次上报标志；收到应答或 HEAD 被 `FE_PolePopHead` 弹出即清。
- **应答**：`PC_AckDeal` 的 `CTRL_CMD_G1` 分支新增 `case M_CMD_AVOID_PD_EMPTY (0xC2)`，清该站上报状态。
- **不动出站逻辑**：`FE_OutStation` 的 `WATE_OUT` 判定（`occupy==0x55` 且 `out_shift−50 ≤ now−addtime ≤ out_shift`）保持原样，上报是旁路，只影响上位机决策。
- **边界**：不改 `out_shift` 计算、不动 `FE_OutBuff`/`FE_PowerOutStateUpload`、不碰标准线 `develop`。

### 3.1 时机点对照（调试说明参数：站宽 165cm、行程 79cm、主轨/出站 1250·1500rpm、阀保持 1300/1600ms → out_shift = 1636ms）

| 时机点 | 相对 `addtime` | 说明 |
|---|---|---|
| 读卡器判定 | −500 ms | `FE_NewPoleDeal`：推杆到来前 500ms 内读到卡才算有衣架 |
| 推杆入队 | 0 | `FE_PoleEnqueue(occupy, hanger_id, addtime)` |
| 避让光电触发 | **+1036 ms** | 出站时机点前 25cm → 提前 600ms；此时 HEAD 即目标推杆 |
| 首发 0xC2 | **+1336 ms** | 窗口中点（出站时机点前 300ms） |
| 重发 1 / 2 | +1536 / +1736 ms | 200ms 超时，末帧在出站后 100ms |
| 出站判定窗 | **+1586 ~ +1636 ms** | `WATE_OUT` 只在这 50ms 内判定 `occupy==0x55` |
| 出站动作 | +1636 → +3316 ms | `OUTING` 等待 `trip/speed+100 = 1680ms`；机械行程约 1580ms |

- 三帧里只有前两帧在判定窗之前；末帧 +100ms 落在出站动作内，属预期，上位机按序号去重
- 机械位置（由公式与实物反推）：读卡器 1650mm、避让光电 1218mm、出站时机点 968mm、落点 310mm（= 25cm 半推杆 + 6cm 装置偏置）
- 出站臂路径（按图纸）：出站缓存位于**出站时机点下方**，衣架先**竖直上升**，再沿 **658mm 横臂**滑到**落点**落到空推杆上，随后随主轨向出站口离开；横臂起点在 658 左端（时机点侧）
- 仓出站（进到出 108cm）`out_shift` 仅 268ms，避让光电若仍按 25cm 装会落在推杆入队之前 → 仓出站需单独确认（见 §2）
- 可交互核对：`D:\S3\docs\避让上报时机仿真.html`（站宽 165/108、行程 79、超时与应答可调，`?at=` 定位时刻）
- 二号站待核：`进到出 1.73m` 按公式得 ~1.5s，参数表写 0.75（=0.90s），差约半个推杆
