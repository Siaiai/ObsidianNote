## 2. 契约 v1（2026-11-18）

- 帧格式沿用 `0xFA CMD1 CMD2 CMD3 LineNo StatNo LenHi LenLo Data`；避让上报走 `CMD2=0x01`、`CMD3=0xC1`（标准线宏 `M_CMD_AVOID_PD`）
- 标准线现行帧内容（对齐基准）：`Len=2`，`Data[0]` = 当前主轨杆号 `NowPoleNum`，`Data[1]` = `0xAA` 满 / `0x55` 取消满（`main.h: FULL / NO_FULL`）
- 上位机应答：回复同码 `0xC1` 即表示「当前推杆窗口不再上报」；控制器据此置 `AvoidPDBan[0]`（BridgeMode）或 `AvoidPDBan[1]`（StdMode）
- 杆号来源唯一：`StatParam[].NowPoleNum`，由主轨光电驱动刷新；不得另建杆号
- 避让光电安装约束（现场调参定稿）：离出站口约 1000mm、固定位置误差 ≤2cm，最小距离 ≥ `S_出/速比 + 0.25m + 0.05m`；与避让读卡器重叠时 1300mm；站间距 ≥1800mm。上报时刻由光电物理位置与主轨速度决定，固件不做距离补偿
- 版本号：全封闭 v2 线改动必须递增 `ControlVer`（当前 V3.3.05.8）

## 3. 方案

待定。候选（未选定，等你确认）：

- **A. 全量对齐标准线**：`0xC1` 帧（`Len=2`，杆号 + `0xAA/0x55`）、上升沿报满、下降沿报取消满、上位机 ACK 置 `Ban`、新推杆时 `Ban` 双槽位轮转。与标准同构，日后合并冲突最小；依赖上位机回 ACK。
- **B. 简版只报满**：只发上升沿（`0xAA`），不做取消满与 ACK 抑制。代码量约一半，但上位机拿不到释放事件，与标准版行为不一致。
- **C. 帧内容先行**：先定帧长/状态字节/是否带杆号，再决定实现范围。

已探明的 v2 与标准的差异点（无论选哪个都要面对）：v2 的 `MainRailPD_Deal` 没有 `Ban` 双槽位轮转；v2 的 `PC_AckDeal` 没有 186/187（进站读卡器卡号）分支，即「读卡器已确认的推杆也免报」这条标准行为在 v2 无处落地。

### 3.1 参考：全封闭调参要点（整理自 [[260128全封闭轨道新加机制与待测试项]]）

- **出站时机点**：`S_出/速比 + 0.25m`（动力出站行程 + 半个推杆，使落点居中）；主轨 `V_主 = 25 m/min`，速比现场按 `1:1 / 1:1.2 / 1:1.3` 调
- **避让光电最小距离**：`S_min = S_出/速比 + 0.25m + 0.05m`（机械误差按 2cm）；离最右边沿再加 `0.06m`（进到出距离修正）
- **26/2/6 定稿**：避让光电离出站口 1000mm、误差 ≤2cm；与避让读卡器重叠时 1300mm；两站间距 ≥1800mm；需要安装避让光电时进出站间距最小值 700mm
- **调参注意**：实际落点稍微靠前；避让光电装早了会在出站动作开始前就报「满」，装晚了则该推杆已出站才报——**这正是本需求要交给上位机判断的那段时间差**
- **未迁移部分**：笔记里的逐站参数表（1250 速度下 1:1 / 1:1.2 / 1:1.3 的一二号站参数）、历次会议纪要与测试记录属现场资料，仍留在笔记，不搬进本文
