### 4. 截图生成方案

#### 4.1 原理

模拟器本身已经把 `draw_pixel` 写入 `sim.c` 的 32 位帧缓冲；我们不需要另做一套 UI。新增一个**无窗口、确定性时间**的测试工具：

- 用 `UI_Ops_t` 把像素写进 `uint8_t` 单色缓冲；
- `get_time()` 由变量控制，不读真实时钟；
- 事件用 `UI_NotifyEvent` 注入，手动推进时间并调用 `UI_Loop`；
- 最后把缓冲写成 24 位 BMP；
- PowerShell 用 `System.Drawing` 转 PNG，并用最近邻放大 2×。

这样截图与真实渲染完全同源，不会出现“文档图和代码不一致”。

#### 4.2 新增文件

```text
test/
├─ shot.c / shot.h        # 单色帧缓冲、确定性时钟、事件注入、BMP 写出
├─ doc_gallery.c / .h     # 截图专用页面/组件池（可选，也可放 doc_shots.c）
└─ doc_shots.c            # CLI + 场景注册表
scripts/
└─ gen_doc_images.ps1     # 构建后批量生成 docs/images/*.png
docs/images/
└─ *.png
```

`test/CMakeLists.txt` 增加：

```cmake
add_executable(gui_doc_shots
    doc_shots.c
    # doc_gallery.c   # 若把 gallery 拆成独立文件，取消注释
    shot.c
    font_file.c)
target_compile_features(gui_doc_shots PRIVATE c_std_11)
target_include_directories(gui_doc_shots PRIVATE ${GUI_TEST_INCLUDES})
target_link_libraries(gui_doc_shots PRIVATE my_ui)
```

注意：`gui_doc_shots` 是 **console** 程序，不要加 `WIN32`；不依赖 `sim.c`、不创建窗口、不依赖固件页面和 `UI.JSON`。

#### 4.3 工具 API（建议）

```c
void Shot_Init(uint16_t w, uint16_t h);
const UI_Ops_t* Shot_Ops(void);
void Shot_SetTime(UI_Time_t ms);
void Shot_Advance(UI_Time_t ms);
void Shot_Press(UI_EventCode_t code);
void Shot_Render(void);              /* 置 need_refresh 并跑一轮 UI_Loop */
int  Shot_SaveBmp(const char* path, uint8_t scale);
```

实现要点：

- 帧缓冲用 `static uint8_t s_fb[320 * 240]` 或 `malloc`（测试工具可用 malloc；库仍然无 malloc）。
- `draw_pixel` 只接受 0/1；`clear` 填 0；`refresh` 置 `s_frame_ready`（可不用）。
- `Shot_Advance` 推进 `s_now` 后调用 `UI_Loop`；`Shot_Press` 用当前 `s_now` 填 `timestamp`，`UI_NotifyEvent` 后推进一帧。
- 初次绘制：`UI_PageSwitch` 不置 `need_refresh`，截图前必须 `Shot_Render`（或先 `Shot_Advance(20)`）。
- 动画：先 show 弹窗/聚焦文本，记录 `start_tick`，再 `Shot_SetTime(phase)` + `Shot_Render`，可精确截到转圈/滚动位置。
- BMP：24 位、正高度（bottom-up）、行 4 字节对齐、像素 0→黑、1→白；`scale` 用最近邻复制。
- 每个场景**独立进程**运行（CLI 只接受一个场景），避免 `UI_Init` 不清理静态池/队列导致的串场；如果 S1 增加了 `UI_DeInit`，也可以改成单进程多场景。

#### 4.4 CLI

```text
gui_doc_shots --list
gui_doc_shots --scenario list-active --out out/list-active.bmp --scale 2
gui_doc_shots --scenario font-20px --out out/font-20px.bmp --font test/unifont20.bin
```

参数：

- `--scenario <name>`：场景名；不带则打印用法。
- `--out <path>`：BMP 输出路径。
- `--scale <n>`：默认 2。
- `--font <path>`：可选；不给则用内置 5×7。`font-20px` 场景缺字库时应报错退出，而不是静默生成错误图。
- `--list`：列出所有场景。

#### 4.6 生成脚本

```powershell
# scripts/gen_doc_images.ps1
param(
  [string]$BuildDir = "build",
  [string]$OutDir   = "docs/images",
  [string]$Font     = "test/unifont20.bin",
  [int]$Scale       = 2
)
# 1. 检查 gui_doc_shots.exe
# 2. New-Item -ItemType Directory -Force $OutDir
# 3. 遍历场景：& $exe --scenario $s --out "$OutDir\$s.bmp" --font $Font --scale $Scale
# 4. System.Drawing 读取 BMP -> Save PNG -> 删除 BMP
# 5. 检查输出文件非空；打印清单
```

要求：

- 脚本从 GUI 根目录运行；路径用 `$PSScriptRoot\..` 计算，不写死绝对路径。
- 生成的文件名与上表一致（`01-hello.png` 等）；场景名和文件名用 `scenario -> file` 映射表。
- BMP 中间文件不要提交；可在 `.gitignore` 加 `docs/images/*.bmp`。
- PNG 提交到仓库，保证读者没有 4MB 字库也能看到图。
- 如果 `System.Drawing` 不可用，退回纯 C PNG writer（1-bit grayscale，stored deflate）或保留 BMP 并在 README 说明；优先 PNG。
