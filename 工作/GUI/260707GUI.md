### 2. 架构评价与审阅范围

#### 2.1 做得好的地方

- **静态内存模型**：页面、组件、列表项、弹窗池、事件队列全部静态；无 malloc，适合 RTOS。
- **组件模型轻量**：`UI_CompBase_t` + 静态 vtable + 实例事件表，局部定制不需要新类型。
- **路由链清晰**：弹窗层 → 焦点组件 → 页面表 → 内置导航 → 全局表；消费即停，易追踪。
- **列表操作态转发**：List `SELECTED` 下把键先交给当前项，参数/文本项可复用，不需要页面级编辑模式。
- **弹窗统一 Tab/优先级栈**：Toast、Alert、Confirm、Titled、Progress 共用池和绘制骨架，扩展成本低。
- **模拟器与固件共用页面代码**：`panel_ui_test` 20 个场景验证真实页面流程，不是纯 demo。
- **绘制骨架统一裁剪**：`UI_DrawComponent` 的 PushCanvas → 边框 → vtable → PopCanvas 约束明确。

#### 2.2 主要架构风险

| 风险 | 说明 | 影响 |
|---|---|---|
| 全局单例 `g_ui` | 所有状态集中，初始化/反初始化/多实例能力弱 | 重复初始化残留、测试串场 |
| 含指针结构体 `#pragma pack(1)` | `UI_CompBase_t::vtable` 偏移 15、`events` 偏移 19 | Cortex-M0/严格对齐配置可能 HardFault |
| 弹窗状态机复杂 | 池 + 优先级栈 + tab_index + 回调 + 超时 + 页面绑定 | 选中漂移、回调重入、槽复用 |
| 文本换行两套实现 | `popup_count_lines` 与 `popup_draw_wrapped` 各写一遍 | 测量/绘制不一致、空行、滚动范围错 |
| HAL 契约未校验 | `UI_Init` 直接解引用 `ops`；绘制时不检查 `clear/refresh/get_time` | 空指针崩溃、移植期难定位 |
| 全屏重绘 | 每个刷新周期 `clear()` + 全组件重画 | 240×160 下 pixel 调用多，功耗/CPU 不稳 |
| 文档与注释漂移 | 头文件描述的去重、按钮焦点、导航职责与代码不一致 | 使用者按文档写出错误代码 |

#### 2.3 审阅范围与方法

- 逐文件阅读 `inc/` 14 个头文件、`src/` 14 个实现、`test/` 主要页面与测试。
- 手工追踪：初始化 → 事件入队 → 五级路由 → 页面/焦点 → 组件绘制 → 弹窗覆盖 → HAL。
- 静态检查：
  - `gcc -std=c11 -Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion -Wcast-qual -Wstrict-prototypes -Wmissing-prototypes -Iinc -fsyntax-only src/*.c`
  - `gcc ... -fanalyzer -fsyntax-only src/*.c`
  - 结果：无编译错误；`-Wconversion/-Wsign-conversion` 有十余条窄化/符号转换告警；`-fanalyzer` 未报新问题。
- 动态验证：
  - 现有 `ctest` 20/20。
  - 临时无窗口 harness 复现 R02/R04/R05/R06。
- **未做**：目标板 HIL、ASan/UBSan（MinGW 工具链限制）、覆盖率、cppcheck/clang-tidy、压力/模糊测试。T1-16 补齐 CI 侧。

#### 2.4 严重度与优先级

| 级别 | 定义 | 处理 |
|---|---|---|
| **S1 Critical** | 崩溃、内存破坏、死循环、数据丢失、槽/链表损坏 | 本轮必须修，先写失败测试 |
| **S2 Major** | 主要功能错误、流程被阻断、目标平台可移植性风险 | 本轮必须修或给出明确规避 |
| **S3 Minor** | 边界、视觉、API 不一致、可维护性问题 | 低风险顺手修；破坏性进路线图 |
| **S4 Trivial** | 注释、命名、死代码、格式 | 文档/清理阶段处理 |
| **P0** | 阻断 T1 冻结或 T2 文档/截图 | 必须关 |
| **P1** | 本轮应做，影响质量/体验 | 修复或有书面延期理由 |
| **P2** | Backlog，按影响/成本排期 | 记录，不阻塞冻结 |

> 本轮没有“真正意义上的 S1 数据损坏”；R14/R15/R38/R40 属于可能导致崩溃/挂死的 S1，优先级 P0/P1。

#### 3.2 P0/S1 修复要点（先做）

**A. 弹窗选中与栈不变量（R04/R05/R41）**

- 定义唯一不变量：`tab_index` 始终指向“当前绘制/接收按键的栈项”，空栈为 0，范围 `0..popup_top`。
- `popup_remove_at(idx)`：
  - `idx < tab_index` → `tab_index--`；
  - `idx == tab_index` → 删除后优先保持原“下一个”位置，越界再钳到 `popup_top`；
  - 空栈 → 0。
- 新弹窗入栈：
  - 非 Toast：新弹窗成为当前选中（现有行为可保留）；
  - Toast：如果栈中已有阻塞弹窗，**不抢选中**；只有全 Toast 时才可选。
- 所有入口先钳位 `tab_index`（含 `<0`），再取 `popup_stack[tab_index]`。
- 验证：三弹窗关闭最低索引；模态 + Toast；Toast 超时关闭；`tab_index=-1` 防御。

**B. 弹窗生命周期与回调（R13/R14/R33/R37）**

- `popup_insert` 失败必须 `active=0` 并返回 NULL；Show 不得返回未入栈指针。
- 关闭顺序改为：先从栈移除 → 触发 `on_close` → 再释放池槽/清字段。释放前回调期间池槽仍 `active`，避免 `on_close` 内 `UI_PopupShow` 复用同一槽导致外层 `on_confirm/on_cancel` 拿到被改写对象。
- `popup_close_with_cb`：保存回调函数指针；先完成 `on_close`，再调用 confirm/cancel；明确“回调内允许 Show，不允许再操作已关闭对象”。
- `UI_PopupTick`/`CloseByPage`：先收集待关闭指针到固定数组（≤ `UI_POPUP_MAX`），统一移除，再逐个回调；避免遍历中改栈。
- `BTN_NONE`：Cancel 应关闭（触发 `on_close`，reason=KEY），或明确提供 `UI_PopupClose` 调用；不能静默吞掉。
- 验证：池满/插入失败、on_close 内 Show、on_close 内 Close 另一个、超时回调、BTN_NONE Cancel。

**C. 弹窗布局与几何（R02/R03/R06/R07/R17/R38）**

- `UI_PopupShow` 结束前按 style 做一次布局：TOAST → `popup_toast_layout`；其余 → `popup_layout_center`。直接 Show 不再得到 0 尺寸。
- `UI_PopupRelayout` 按 style 分发，不能把 Toast 居中。
- 百分比：`0` 表示样式默认；非 0 钳到 `1..100`；算完再保证 `width/height` 至少能容纳边框+字高+内边距。
- `popup_prep_inner`/Toast 内层/进度条：先判断 `width > 2*bw`、`height > 2*bw`，不满足直接返回，禁止无符号减法下溢。
- 单行判定：`text_w <= avail && !has_newline`；多行测量与绘制共用同一函数/同一换行算法。
- 硬断算法：每消费一段字符只前进一行；单词结束/文本结束不再额外 `line_count++`/`y += line_h`；补“长 CJK/长 ASCII 单词”像素级测试。
- 宽度语义：Toast 单行/多行用“最大行宽”或显式逐行判断，不用 `UI_GetTextWidth` 的全字符串总和。
- 验证：`A\nB`、200% 宽高、1px 卡片、长 CJK、长单词、空文本、只有空格。

**D. 字体与文本绘制（R01/R16/R28/R29/R47）**

- 补 `<`、`>`；至少再补 `=`、`+`、`(`、`)`、`[`、`]`、`*`、`#`、`%`、`_`、`|`、`\`、`'`、`"` 中常用的。
- 缺字回退改为查找 `?` 字模；不要依赖数组下标。
- 提取 `UI_CompContentRect()`：统一“边框 + 聚焦加粗”内缩；Text/Button/TabBar/Param/List/Popup 共用，消除 +1/+2 不一致。
- TabBar 箭头/邻项推进用 `UI_GetCharAdvance()`，不要用内置 cell 宽度。
- 文本宽度用 `uint32_t` 累加后再钳到 `uint16_t`；`max_offset` 用 `int32_t` 再钳位。
- 验证：内置字体全 ASCII 表；外部 20px 中英混排；聚焦长文本；TabBar 箭头；`UI_GetTextWidth` 边界。

**E. 页面/焦点/列表（R08/R09/R10/R11/R15/R19/R20/R39/R42/R43/R50）**

- `UI_PageAddComponent`：先检查节点是否已在链表；重复添加直接返回/断言，禁止自环。
- `UI_PageFocusReset`：对旧焦点调用 `UI_CompSetFocused(old,0)`，再选新焦点；所有焦点变化走同一入口。
- `HIDDEN`：`UI_CompIsFocusable`、`UI_CompOnKey`、列表绘制/命中统一检查；或者文档明确“HIDDEN 只影响顶层绘制”，但本轮建议实现一致。
- `UI_ListSetCount`：增加 `UI_ListSetCountEx(list,count,preserve_focus)`；默认保持旧行为，新 API 供刷新场景。
- 列表空指针：`items==NULL` 时强制 `item_count=0`；绘制/按键前再 guard。
- 页面跳转后置 `need_refresh`；页面栈满返回状态（新增 `UI_PagePushEx` 或 `UI_PageCanPush`），保留 void 兼容入口。
- 根页 Pop：定义策略（禁止/绘制空页/回首页），不能停在不可交互的最后一帧。
- TabBar 入口先钳 `selected`，再处理左/右，保证 `on_change` 索引合法。
- 验证：重复 Add、页面重进、List 刷新保留、HIDDEN 焦点、根页退出、TabBar 越界。

**F. 初始化/HAL/事件（R12/R18/R40/R45/R46）**

- `UI_Init` 先校验 `ops` 与必需函数；空指针直接返回（或 `UI_InitEx` 返回错误码）。
- `UI_Init` 清理：页面栈、弹窗栈、池槽 `active/pending`、事件队列、`need_refresh`、`last_refresh_time`、`tab_index`。
- 新增 `UI_DeInit()`：关闭所有弹窗（FORCE，回调可选）、清池/队列/栈、`initialized=0`。
- 新增 `UI_RequestRefresh()`；库内不再直接写 `g_ui.need_refresh`（保留 `g_ui` 兼容）。
- 事件队列：保留 `UI_NotifyEvent` 兼容，新增 `UI_NotifyEventEx` 返回成功/失败，或 `UI_GetEventDropCount()`；队列满至少可观测。
- 时间：新增 `UI_NotifyEventAt(evt, timestamp)` 或 `evt.timestamp` 有效标志，解决 0 歧义。
- 路由：处理器切页后返回 0 时，重新取 `current_page` 或直接停止后续层；不允许旧 page 继续分发。
- 验证：NULL ops、重复 Init/DeInit、队列满、时间 0、处理器切页后返回 0。

**G. 参数（R24/R25/R27）**

- `DEFAULT_LIST_PARAM_CONFIG` 的 `border_width` 改为 0，恢复列表项反白；或引入 `is_list_item` 标志，避免靠边框猜模式。
- dirty `*` 不放在 `value` 里：由页面/模型维护 dirty 标志；组件只负责字符串。
- 本轮至少支持负号（新增 `eKeyMinus`，或复用现有标点/自定义事件码）和“校验返回值/格式钩子”的 API 设计；完整光标移动/删除进路线图。
- 验证：列表参数反白、负值、非法提交、Cancel 还原、缓冲边界。

#### 5.5 截图方案与清单

**原理**：模拟器已把 `draw_pixel` 写入 `sim.c` 的帧缓冲；新增无窗口、确定性时间的 `gui_doc_shots`，用同一套 `UI_Ops_t`/`UI_Loop` 渲染，输出单色 BMP，再转 PNG。

**工具要求**：

- `test/shot.c/.h`：静态 `uint8_t` 帧缓冲（240×160 或 480×320），`get_time` 由变量控制，`UI_NotifyEvent` 注入按键，BMP 24 位写出，2× 最近邻放大。
- `test/doc_shots.c`：CLI `--list/--scenario/--out/--scale/--font`；每个场景独立进程。
- `test/doc_gallery.c/.h`：截图专用页面/组件池，不依赖固件/JSON。
- `scripts/gen_doc_images.ps1`：自动定位 exe，批量 BMP→PNG，失败非零退出。

**CLI 示例**：

```text
gui_doc_shots --list
gui_doc_shots --scenario hello --out out/01-hello.bmp --scale 2
gui_doc_shots --scenario font-20px --out out/19-font-20px.bmp --font test/unifont20.bin
```

### 14. 新需求：超长滚动刷新节流（2026-10-27）

**现象**：单行文本 marquee 超过 2 倍内容区时，滚动持续十几秒，屏幕按全局 10 ms 周期重绘，
实机出现拖影；同时用户关心“滚动时其他组件是否要跟着高频刷新”。

**需求**：
- 超长文本滚动时加大刷新间隔，降低屏幕更新频率，减轻拖影。
- 不改变滚动速度；两端增加停留，给面板和眼睛留恢复时间。
- 其他组件不需要按滚动节奏单独加速刷新；只更新发生变化的区域。

**方案（已实现）**：
- 判定：`max_offset > avail_w`（文本宽度 > 2 倍内容区）视为超长。
- 普通：1 px / 50 ms（≈20 px/s），两端各停 1 s。
- 超长：2 px / 100 ms（仍 ≈20 px/s，刷新率 20 Hz → 10 Hz），两端各停 2 s。
- 其他组件仍按整帧绘制；HAL（ST75256）按页 memcmp，只把变化的页写入屏幕，静态区域不重发。
- 配置缝：`UI_TEXT_SCROLL_LONG_STEP_MS`、`UI_TEXT_SCROLL_LONG_PX_PER_STEP`、
  `UI_TEXT_SCROLL_LONG_DWELL_MS`（`inc/ui_user_def.h`）。

**验收**：
- 新增库级用例 `text_scroll_long_pacing`：首停留内不动、未到 100 ms 不动、过 100 ms 移动 2 px；
  普通溢出仍按 50 ms 步进。
- GCC 构建通过，CTest **62/62**（含工作区他人的 IP 测试）；库级用例 36 项。
- 文档：README §8.6 / §11.1 已同步。

**状态**：代码/测试/文档完成；实机拖影效果需上板确认（与 HIL 一起）。

### 15. 新需求：列表参数反显范围可配置（2026-10-27）

**现象**：list 内的参数行选中时整行反白，数值也被反色；数值较长或带单位时观感较差。

**需求**：可配置“只反显名称”或“整个选项反显”，由页面按行/按页选择。

**方案（已实现）**：
- `UI_Param_t` 新增 `uint8_t reverse_mode`，取值：
  - `eParamReverseAll = 0`：整行内容区反白（默认，兼容旧行为）。
  - `eParamReverseName = 1`：只反白名称区（含左侧内边距），value 保持常规配色。
- 仅 `border_width==0`（列表项模式）+ 聚焦时生效；非列表项/失焦不反白。
- 编辑光标块跟随 `value_reverse`：整行反白时用反色，只反白名称时用常规色。
- 用法：`s_row.reverse_mode = eParamReverseName;`（`DEFAULT_LIST_PARAM_CONFIG` 默认仍是整行）。

**验收**：
- 扩展 `param_r27_border`：整行模式 name/value 区均有反白；只名称模式 value 区反白像素显著下降，
  且 value 文本仍可见。
- GCC 构建通过，CTest 62/62，严格告警 0；README §9.4 已补字段/用法。

**状态**：代码/测试/文档完成；固件页面默认未改，需要时按行设置。
