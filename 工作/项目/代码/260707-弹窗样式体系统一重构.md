# GUI 弹窗样式体系统一重构

## 背景
当前弹窗有四种 style(TOAST/FILLED/TITLED/PROGRESS),单优先级栈,"有弹窗即冻结页面"。TOAST 透明背景与其他三种实心卡片视觉不统一;且 toast 作为通知也冻结页面,语义过重。详细重构计划见代码库 `.claude/plans/popup-redesign.md`。

## 目标模型:两类弹窗
**消息(MESSAGE)**:顶部、黑底白字不透明、纯文字、倒计时自消。非交互、不冻结页面。多个纵向堆叠(新在上),超上限丢最老。
**卡片(CARD)**:居中、黑底白字不透明。交互、冻结页面。内容由字段组合:正文(换行/滚动)+ 可选标题(反色条)+ 可选按钮 + 可选进度(条/转圈)。多个用 ↑/↓ 切换 + 点指示。
冻结策略:消息不冻结,卡片冻结。同屏时按键全给卡片,消息只显示 + 倒计时。这是相对现状(任意弹窗即冻结)的行为变更——toast 不再挡输入。

## 关键决策
- 消息条:全屏宽、高=字高+4、不透明黑底、居中单行、超长截断不换行;最新在顶 y=0,旧的往下排;上限 4,溢出丢最老;默认时长 1500ms。
- 卡片点指示:右上角点(≥2 张时画),同现状。
- 卡片恒冻结(无 MODAL 标志),prio 仅排卡片栈顺序 + 驱逐。
- 进度卡片:无按钮(Cancel 关闭)、文字在上、进度在下,同现状。
- `UI_PopupToast` 删除(改名 `UI_PopupMessage`),仅 `main_page.c` 两处调用,一并改。

## 风险
- 路由冻结条件改动是承重点:消息不再挡输入(符合提示语义),但依赖"toast 期间页面暂停"的调用方需注意。
- 双栈增加 `UI_Obj_t` 状态,`UI_Init` 须把两个 top 置 -1。
- 池共享,活跃总数 ≤ 8;按栈上限约束布局(`MSG_MAX + CARD_MAX = POOL_MAX = 8`)。
- 保持无 malloc,全静态。
- API 改名(`UI_PopupToast`/`UI_PopupShow`)是破坏性变更:库内调用点已盘点(`main_page.c` 2 处 + 便捷封装 + 库内 `ui.c`/`ui_page.c`),外部面板 app 若直接调用需同步。
