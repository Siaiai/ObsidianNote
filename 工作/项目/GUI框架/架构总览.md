## 概述

嵌入式 RTOS 面板上的 GUI 框架,C11,单线程事件驱动,无动态分配。硬件无关——只通过 4 函数 HAL 对接:`draw_pixel` / `clear` / `refresh` / `get_time`。Win32 LCD 模拟器(`test/`)作为开发宿主目标,键盘输入映射到 `UI_EventCode_t`(方向键、Enter、Esc→eKeyCancel、0–9)。

所有页面、组件、列表项、事件表都由用户静态定义,运行时链接。库内零 malloc。构建无 linter/formatter。

## 三阶段主循环

`UI_Loop`(`src/ui.c`):`UI_Events()` → `UI_Proc()` → `UI_Draw()`,循环往复。

- **`UI_Events`**:从固定大小环形队列(`UI_EVENT_QUEUE_SIZE` = 32)取一个事件。事件由 `UI_NotifyEvent` 入队(时间戳由 `get_time()` 盖戳,调用方传 0 时)。
- **`UI_Proc`**:先跑 `UI_PopupTick`(两阶段超时扫描:先标记后收割,避免迭代中改栈),再走页面 proc。
- **`UI_Draw`**:画当前页面,再叠 `UI_PopupDrawAll`(tabbar toast + 居中弹窗)。只在 `need_refresh` 置位或 `fresh_interval` ms 到时才画。

单全局 `g_ui`(`UI_Obj_t`)持有:页面栈、当前页面、默认事件表、当前裁剪矩形、弹窗栈、刷新时序。`popup_top` 在 `UI_Init` 里设为 `-1`(零值 0 会被 `UI_PopupTick` 当活槽位解引用)。

## 页面与导航

`UI_Page_t`(`ui_page.h` / `src/ui_page.c`)是上下文 + 调度器,**不是**可绘制组件。它拥有:生命周期回调(`enter`/`exit`/`proc`/`draw`)、组件链表(焦点环)、当前 `focused` 节点、事件表。

导航是固定深度栈(`UI_PAGE_STACK_DEPTH`):`UI_PagePush` / `UI_PagePop` / `UI_PageSwitch`(替换栈顶,不增长)。三者都在 outgoing 页面 `exit` 前调 `UI_PopupCloseByPage`,收割绑定到该页的弹窗(全局弹窗 `bind_page==NULL` 存活)。页面**不**继承 `UI_CompBase_t`。

## 组件机制

每个可绘制单元是一个结构体,**首成员是 `UI_CompBase_t`**(`ui_component_base.h` / `src/ui_base.c`)。按类型的行为放在静态 `UI_CompVTable_t`(`draw` / `on_key` / `on_focus`)里,每个类型一个静态 vtable 实例(如 `g_text_vtable`、`g_list_vtable`、`g_button_vtable`)。组件通过 `UI_ComponentListNode_t` 包装节点挂在页面里。

标志位(`UI_COMP_FLAG_FOCUSABLE`/`FOCUSED`/`SELECTED`/`HIDDEN`)驱动焦点环和绘制决策。`SELECTED` 是容器内部操作态(列表用),路由层看不见。

Key 派发有两个 helper:`UI_CompOnKey`(node 包装,页面路径)和 `UI_CompOnKeyRaw`(裸 `UI_CompBase_t *`,弹窗用——弹窗没有 list node;列表项也用,转发时 ctx 传转发用的 list)。两者都先查实例事件表(`component->events`)再回退到 vtable `on_key`。

## 事件路由链

`UI_Events`(`src/ui.c`)对每个事件按序尝试,首个消费者(返回 1)截断:

0. **弹窗层**(有弹窗时):页面冻结。↑/↓ 切换当前选中弹窗(`UI_PopupSelect`,拦截,绝不到卡片);Enter/Cancel/←/→ 派发到选中卡片 `on_key`;未消费的键被吞。下面 1–4 全跳过。
1. **焦点组件**:实例事件表 → 类型 vtable `on_key`(`UI_CompOnKey`)
2. **页面事件表**(`page->events`)
3. **内置导航**(`UI_PageHandleNav` — ↑/←=上一焦点,↓/→=下一焦点)
4. **全局默认表**(`g_ui.default_events`,来自 `UserDef_GetDefaultEvents` — 如 `eKeyCancel`→`UI_PagePop`)

事件表是 `UI_EventMap_t[]`,以 `END_EVENT_MAP`(`{0}`)结尾;handler 返回 0 让事件继续冒泡。实例事件表能让某个具体 list item(不是整个类型)绑定比如 Enter 开页面,见 `main_page.c`。

`ctx`(handler 第二参数)随分派层级走:独立焦点组件收到自身(`page->focused->component`);页面/全局 handler 收到当前 `page`;弹窗 handler 收到弹窗;**列表项** handler 收到转发的 **list**(`UI_CompBase_t *`),不是 item——item 只作为派发目标到达。列表项派发走和独立组件相同的 `UI_CompOnKeyRaw`(events → vtable `on_key`),所以列表项与独立组件共享派发*机制*,只是 `ctx` 不同。

## 画布与裁剪

层级矩形裁剪(`ui_canvas.h` / `src/ui_canvas.c`)。`UI_PushCanvas` 把组件矩形与当前 `g_ui.clip_rect` 求交并保存前值;`UI_PopCanvas` 恢复。**所有**绘制必须走 `UI_Draw*Clipped` helper(`UI_DrawPixelClipped` 是叶子——它检查裁剪矩形再调 `draw_pixel`)。`UI_DrawFillRectClipped` 逐像素穿过叶子填实矩形(列表滚动条 thumb 和按钮聚焦高亮都用它)。

`UI_DrawComponent` 是标准组件绘制骨架:PushCanvas → 边框(聚焦时加粗)→ `vtable->draw` 内容 → PopCanvas。加组件时照这个骨架,别画到裁剪矩形外。

5×7 位图字体(`g_font_map`)内建在 `ui_canvas.c`;`UI_DrawTextClipped` 按 `font_size` 缩放字形。

## 核心组件

### 列表(`ui_list.h` / `src/ui_list.c`)
`UI_List_t` 是 `UI_ListItem_t` 的垂直容器(每个 item 持有任意 `UI_CompBase_t *`,通常是 `UI_Text_t`)。管理视口滚动(`first_visible_index`)、选中(`focused_index`)、滚动条模式。支持静态(编译期 item)和动态(`UI_ListInitDynamic` + `UI_ListSetCount`/`UI_ListSetItemText`,固定容量,无 malloc)两种用法。item 用 `DEFAULT_LIST_TEXT_CONFIG` 共享 text vtable。

列表是唯一有内置 key 行为的组件(`UI_ListOnKey`):Enter 通过 `SELECTED` 标志切操作态——操作态里 ↑/↓ 滚动列表、Enter 转发到焦点 item 自身派发(`UI_CompOnKeyRaw`,ctx = list),←/→ 被吞(不退出操作态,避免并排列表误失焦),Cancel 退出;非操作态 ↑/↓/←/→ 返回 0 落到页面导航。这是 README「Enter 进操作态」设计意图的落地形态(没有原计划的 NAV/EDIT/MODAL 模式层)。

### 按钮(`ui_button.h` / `src/ui_button.c`)
`UI_Button_t` 结构上同 `UI_Text_t`(`text` + `align`),同布局不同绘制。`border_width` 设 0 让 `UI_DrawComponent` 骨架不画边框,`UI_ButtonDraw` 自己画 1px 轮廓(失焦)或整块反色填充(`UI_DrawFillRectClipped`,文字 color 0,聚焦)。**无**内置 key 行为(`on_key == NULL`)——Enter 完全由实例事件表(`base.events`)绑定,见 `main_page.c` 的 `btn_open`(声明式 define-and-bind 模式)。按钮像任何 `UI_COMP_FLAG_FOCUSABLE` 组件一样参与页面焦点环,只有 *draw* 和 *Enter 绑定* 跟 text 不同。

## 弹窗系统

`UI_Popup_t`(`ui_popup.h` / `src/ui_popup.c`)是组件(首成员 `UI_CompBase_t`,静态 vtable `g_popup_vtable`),住在**优先级排序栈**(`popup_stack[]` in `g_ui`,降序,数组尾 = 栈顶 = 最高优先级)里——不在任何页面的组件链表里。实例来自固定池(`UI_POPUP_MAX`,无 malloc):`UI_PopupShow` 分配槽位、按优先级插入、新弹窗成为当前选中(`tab_index`)。池满时若新弹窗优先级更高,踢掉最低优先级栈项。

**统一 tabbar**:每个弹窗——toast、alert、confirm、titled、progress——都是一个 tabbar 条目。`tab_index` 在整个栈里选一个弹窗(`UI_PopupCurrent`/`UI_PopupSelect`/`UI_PopupCount`)。新弹窗抢选中;关闭时 `tab_index` 钳位。`UI_PopupDrawAll` **只画当前选中弹窗**的卡片(经 `UI_DrawComponent`),加右上**点指示器**(≥2 时,当前点高亮)。其他弹窗不画——只占 tab 槽。**无全屏遮罩**:每张卡片的不透明实色填充只遮自己矩形,卡片外页面透出来(toast 只遮顶部条)。页面仍由 `UI_Draw` 在弹窗下先画。

**Key 路由(统一冻结)**:有弹窗时页面冻结——`UI_Events` 把所有键送弹窗层:↑/↓ 切换选中弹窗(`UI_PopupSelect`,拦截);Enter/Cancel/←/→ 送当前卡片 `on_key`;未消费键被吞(页面焦点不动)。基于优先级的 modal/non-modal 划分不再驱动冻结(优先级只排栈和踢出),但 `UI_PopupIsModal` 保留。

**按钮**(`UI_PopupBtn_t`:NONE/OK/OK_CANCEL):OK_CANCEL 弹窗有 `btn_focus`(0=OK/左,1=NO/右),←/→ 切换(↑/↓ 被拦截用于 tab 切换);聚焦按钮画真反色填充,Enter 触发。BTN_OK 吞 ←/→ 当 no-op。

**样式**(`UI_PopupStyle_t`:TOAST/FILLED/TITLED/PROGRESS)按屏占比定尺寸,自动换行/滚动;indeterminate PROGRESS 画旋转 270° 弧 spinner(整数点表,无 math.h)。`UI_PopupShow` 默认 FILLED;`UI_PopupToast` 设 TOAST(顶条)。便捷函数:`UI_PopupToast`/`Alert`/`Confirm`/`Titled`/`Progress`/`SetProgress`/`Relayout`。生命周期:`duration_ms`>0 经 `UI_PopupTick` 自动关(不论是否选中);`on_close(reason)` 在弹窗**离开栈后**触发(里面安全开新弹窗)。`bind_page` 绑页面(页面 exit 时收割);NULL = 全局。`text`/`title` 借用不拷贝(字面量最安全)。
