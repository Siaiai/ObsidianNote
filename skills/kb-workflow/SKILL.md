# kb-workflow — 知识库维护工作流

把某个开发工程（QT/嵌入式/软件等）与 Obsidian 知识库绑定后，所有项目文档、任务笔记、设计决策统一维护在知识库内，工程内只留一行指向知识库的指针。本 skill 定义这套维护流程。

## 重要：不硬编码 vault 路径

本 skill **不假设知识库在某个固定位置**。每次需要定位知识库时，按下面顺序获取：

1. 若当前会话/工程已有绑定信息（工程根 `AGENTS.md` 或用户之前告知的路径），直接使用
2. 否则**主动询问用户**：「请告诉我 Obsidian 知识库的根目录绝对路径」，用用户给的路径
3. 得到路径后，把它写入工程级 `AGENTS.md`（见 init 模式），下次就不用再问

## 单一事实源

知识库根目录下有且只有一个规范事实源文件：`规范.md`（根目录的 `CLAUDE.md` 是它的极简指针）。**任何读写知识库的操作，第一步都是完整 Read `规范.md`**，严格按其中的目录结构、frontmatter 格式、wiki 内链规则、各笔记模板执行。不要在 SKILL 或工程文件里复制规范正文 —— 只引用它，避免规范漂移。

## 知识库结构速览（详见规范.md）

- 5 个领域：`工作/`、`日志/`、`输出/`、`学习/`、`个人/`
- 三级结构：`{领域}/项目/{项目名}.md`（项目定义）+ `{领域}/{项目名}/{笔记}.md`（项目笔记）
- 项目文件 `项目` 字段用纯文本，其它文件用 `[[wikilink]]`
- 任务笔记命名 `YYMMDD{任务}.md`，frontmatter 用 `项目: "[[项目名]]"` 关联，dataview 自动汇总

## 核心操作流程

**新建任务笔记**
1. 确认项目已在 `{领域}/项目/{项目名}.md` 存在（不在则先建项目文件）
2. 严格按 `规范.md` 中对应领域任务模板生成 frontmatter（含 `任务`、`相关任务` 空行、`截止时间` 带秒）
3. 文件放 `{领域}/{项目名}/YYMMDD{任务}.md`，内容为待办列表

**完成任务**
1. 勾选待办项 `- [x]`
2. `状态` 改为「完成」
3. 填写 `完成时间`（带秒）

**产出设计文档 / 文章**
1. 放对应目录，frontmatter `项目: "[[项目名]]"` 保证正确
2. 项目文件的 dataview 查询会自动汇总，**无需手动改项目文件**

## init 模式（初始化/绑定知识库）

当用户说「初始化知识库绑定」「绑定这个项目到知识库」或首次在一个工程里要求维护知识库时，执行：

1. **询问 vault 路径**（见上文，不硬编码）
2. 探测当前工程类型，生成**该工具认的固定段**（内容统一、只做指针）：
   - Claude Code → 工程根 `AGENTS.md`，或全局 `~/.claude/CLAUDE.md`
   - opencode / Codex → 工程根 `AGENTS.md`
   - Cursor → `.cursor/rules/knowledge.mdc`
   - 其他兼容 Agent Skills 的工具 → 引导用户指向本 SKILL

   固定段统一为：
   ```markdown
   ## 知识库
   本项目文档/任务/决策统一维护在 Obsidian 知识库：`<vault 路径>`
   涉及项目文档、任务笔记、设计文档、ADR，或查阅知识库时，加载 skill `kb-workflow` 执行。
   ```

3. **幂等**：写入前先检查该文件是否已含此固定段，已存在则跳过，不重复堆叠
4. 若工具需授权读写 vault（如 opencode），提示用户在对应配置中放行 vault 目录

## 输出文章写作

知识库中的输出文章（`输出/{项目}/{文章}.md`）要求手册级详细程度：给出完整背景、方案对比、数据结构定义、关键代码，配 mermaid 图或表格。frontmatter 用 `项目: "[[项目名]]"` 关联，dataview 自动收录进对应项目。

## 待办

本 skill 是一个通用知识库维护模板。首次在某个具体工程使用时，可在工程 `AGENTS.md` 里追加该项目特有内容（如该工程绑定的项目名、领域、特殊约定）。
