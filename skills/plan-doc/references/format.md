# 规划文档格式 v1

> 本文件是 plan-doc skill 的格式事实源。纯 Markdown，不绑定 Obsidian；放在任何仓库或目录都可以。
> 如果文件在 Obsidian vault 内，可额外按 vault 的 `规范.md` 补属性（见文末）。
> 创建文档用 `assets/plan-template.md`；本文件说明结构与规则。

文档正文第一行放 `<!-- plan-doc:v1 -->`，lint 见到该标记才启用严格检查。

## 全文骨架

```markdown
---
title: {标题}
status: active
created: 2026-01-01
updated: 2026-01-01
---
<!-- plan-doc:v1 -->

# {标题}

> **一句话**：这个文档解决什么问题、交付什么。
> **仓库 / 路径**：`仓库A`｜`仓库B`
> **维护规则**：本文只保留 当前状态 / 待办 / 契约 / 决策 / 实施记录；过程与日志进各仓 `README.md` / `AGENTS.md` 或 `git log`。
> 血缘：前身 —｜后继 —
> 冻结：—（YYYY-MM-DD @ commit）
> 最后更新：2026-01-01
> 活跃变更：—
```

## 各节的职责

| 节 | 写什么 | 不写什么 |
|---|---|---|
| 顶部引用块 | 一句话、仓库、维护规则、血缘、冻结、最后更新、活跃变更 | 过程描述 |
| AI 入口 | 当前阶段、下一条任务、事实源优先级、本次范围 | 详细方案 |
| §0 | 任务总览、代码快照、基线与环境 | 逐条任务细节 |
| §1 | 未完成任务，按 P0/P1/P2 排序 | 已完成 / 已取消 |
| §2 | 契约、协议、构建测试命令 | 设计论证过程 |
| §3 | 方案要点与边界 | 完整代码 |
| §4.1 | 设计决策 D | 需求变更 |
| §4.2 | 需求变更 C（含否决 / 待定） | 实施过程 |
| §5 | 实施记录，一行一条 | 长日志、截图、代码 |
| §6 | 完成 / 取消 / 取代 / 延期 | 未完成任务 |
| §7 | 源码、文档、测试入口 | 复制正文 |

## 任务行格式

```
- [ ] **T1-5 动作** → 产出：…；验收：`命令` → 期望；来源：— 或 C3；边界：不做什么
```

- `T1-5`：阶段号 + 序号，只增不改
- `动作`：动词开头，一次会话能完成
- `产出`：文件、提交、截图、报告
- `验收`：命令 + 期望结果，必须可复制
- `来源`：普通任务写 `—`，变更产生的写 `← C3`
- `边界`：明确不做什么，防止范围膨胀

## 变更记录（C）

类型只有 6 个：`新增 / 修改 / 删除 / 延期 / 否决 / 待定`。

- **否决和待定也要记**，这是防止 AI 重提旧需求的唯一证据
- 影响列必须写清打到谁：任务 ID、契约版本、测试、文档
- `处理` 列写落地的任务 ID，或 `不做 + 理由`
- 编辑已完成任务的原文是禁止行为；变化一律走新任务或归档

## 归档（§6）

结果只有 4 个：`完成 / 取消 / 取代 / 延期`。

- `关联` 列写 `← C3`（被哪条变更影响）或 `→ T1-9`（被哪个任务取代）
- `提交` 列写短 hash；没有提交写 `—`
- 归档行的原文保留，不删不改

## 血缘与冻结

- 文档升到新阶段、正文超过 800 行或进入冻结时，新建 `{同名}-P2.md`
- 旧文档 `status: done`，顶部写 `> 已迁移至 新文档`，新文档写 `相关规划: 旧文档`
- 冻结写 `冻结：P1 @ commit（YYYY-MM-DD）`；冻结后改契约必须开新阶段

## 契约版本

- 标题带版本：`## 2. 契约与规范 v2（2026-01-01）`
- 契约变更必须引用 C：`v2：新增 NETCONF_SUB 5（← C2）`
- 任务里标明所用版本：`T1-20（契约 v2）`

## 可选：Obsidian 集成

如果文档在 Obsidian vault 内，按 vault 的 `规范.md` 补 frontmatter（通常是 `领域 / 类型 / 项目 / 任务 / 相关任务 / 状态 / 创建时间 / 截止时间 / 完成时间`）。此时：

- `status` / `created` / `updated` 可以省略，lint 按 Obsidian 字段检查
- `状态=完成` 必须有 `完成时间`；`状态≠完成` 不能填 `完成时间`
- 时间统一 `YYYY-MM-DDTHH:mm:ss`（带秒）

通用格式与 Obsidian 格式可以共存：保留 `title/status/created/updated` 不影响 vault 属性。

## 兼容旧文档

旧文档没有 `<!-- plan-doc:v1 -->` 时，lint 只报 WARN，不阻塞。需要升级时：

1. 补 frontmatter（标题、状态、日期）
2. 顶部补 AI 入口与最后更新
3. 在正文首行加 `<!-- plan-doc:v1 -->`
4. 跑 `/plan-check`，按 ERROR 逐条修
