# 执行 SOP（人 + 规划AI + 执行AI）

> 一篇从零到收尾的完整教程。所有提示词可直接复制。
> 通用 Markdown，不绑定 Obsidian；在 vault 内可按 `references/obsidian.md` 补属性。

---

## 0. 三个角色

| 角色 | 是谁 | 职责 | 禁止 |
|---|---|---|---|
| **人** | 你 | 决策、验收、确认变更、批准提交 | 不用自己写任务记录 |
| **规划AI** | 加载 `plan-doc` skill 的 AI | 拆任务、记变更、生成执行提示词、记结果 | 不做实现 |
| **执行AI** | 任意模型/会话 | 只做一条任务，跑验证，回报 | 不改规划文档、不做超出范围的事 |

一条铁律：**规划文档是唯一事实源**。聊天记录不是；只在对话里说的变更，下一个 AI 不知道。

## 1. 首次启动

### 1.1 创建规划文档

方式 A：命令

```
/plan-new docs/plan.md "XX项目阶段1"
```

方式 B：给规划AI的初始化提示词

```text
你是本项目的规划AI。

目标：<一句话说明要交付什么>
仓库/路径：<代码仓库路径>
出口条件：<怎样算做完，例如 真机验收通过 + 62/62 测试>

请加载 skill plan-doc，做四件事：
1. 在 docs/plan.md 创建规划文档（用 assets/plan-template.md）
2. 把目标拆成 T1-1、T1-2… 任务，每条含：
   动作 / 产出 / 验证命令（可复制）/ 来源 / 机制（复用 X 或 新建 D#）/ 边界（不做什么）
3. 填 §0.4 机制登记：列出本项目现有或将建的机制（位置 / 用途 / 扩展方式 / 使用者），一功能一机制
4. 只输出 §1 待办清单，先不做任何实现

注意：
- 一条任务 = 一次会话能完成 + 能跑完验证
- 验收必须是「命令 → 期望结果」，不能写“确保正确”
- 超过 800 行或要开新阶段时，拆成 P1/P2 文件并写血缘
```

### 1.2 人工补两处

- §0.3 基线：仓库 / 分支 / 构建命令 / 测试命令
- §2 契约：影响任务的约束（协议、接口、单位、命名）

## 2. 每日循环：领取 → 执行 → 回报 → 记录

### 2.1 领取（规划AI，每轮开始）

```text
你是规划AI。规划文档：<路径>。

请加载 skill plan-doc，读 §0 / §1 / §4.2。
1. 如果有未处理的需求变更，先用 /plan-change 记录
2. 用 /plan-next 生成下一条任务的执行提示词
   - 任务必须有“机制：复用 X / 新建 D#”字段
   - 会新建机制的任务，先在 §4.1 立 D 决策
只输出提示词，不做实现。本次只做一条。
```

规划AI 输出形如（这就是执行提示词）：

```text
任务：T1-2 参数值读写
事实源优先级：代码 > 测试 > README/AGENTS > 文档 §0
涉及文件：04_Application/app/param_source_protocol.c、02_Middleware/panel_model/value_pool.c
验证命令：ctest --test-dir 02_Middleware/panel_model/build → 2/2
边界：不改协议格式、不改 GUI
DoD：READ_VALS/WRITE_VALS 真机联调通过，错误定位到参数序号
收尾：§5 一行、§6 归档、§0 与最后更新
```

### 2.2 执行（执行AI，新会话）

把上一步的提示词贴进去，前缀加：

```text
你是执行AI。只做下面这条任务，不做其他。开工前先 git status。

开工前先读规划文档 §0.4 机制登记：同类功能已有机制就扩展它，不要新建；要新建机制时先停下，输出"需要 D决策"。

发现需求超出任务边界（含引入新机制），先停下来说"这需要记 C"，不要顺手实现。

<粘贴规划AI输出的任务提示词>

结束时固定回复：
1. 改了什么
2. 验证命令 + 结果
3. 遗留问题
4. 下一步建议
```

### 2.3 回报（执行AI → 人）

执行AI 回报后，**人要判断**：

- 通过 → 执行 2.4
- 不通过 → 在同一对话里让执行AI继续修（这是 bug，属于实现细节）
- 发现需求/验收不对 → 去规划AI记变更（见 §3）

### 2.4 记录（规划AI）

```text
任务 T1-2 已完成，执行回报如下：
<粘贴执行AI的回报>

请加载 skill plan-doc，用 /plan-done 更新：
- §5 加一行
- §6 归档
- §0 与最后更新同步
- 跑 lint
```

也可以直接：

```
/plan-done docs/plan.md T1-2
```

规划AI 会自己跑验证命令并更新；失败就记阻塞，不勾选。

### 2.5 会话收尾（每轮结束，固定动作）

- [ ] §0 状态与实际一致
- [ ] §1 下一条任务明确
- [ ] §5 加了一行
- [ ] §6 归档了完成/取消项
- [ ] 顶部"最后更新"是今天
- [ ] lint 0 error

## 3. 需求变更

### 3.1 何时走变更

| 场景 | 归属 | 做法 |
|---|---|---|
| Bug、编译/测试失败、实现细节 | 执行对话 | 直接修，§5 记一行 |
| 实现路线换了，目标/验收不变 | 执行对话 | 不动计划；影响契约才升级 |
| 需求新增/修改/删除、优先级、验收、接口/契约 | **规划AI** | `/plan-change` |
| 不确定 | **规划AI** | 记录便宜，漏记代价高 |

### 3.2 给规划AI的变更提示词

```text
需求变更：<一句话描述>
原因：<为什么改>
请加载 skill plan-doc，用 /plan-change：
1. 生成 C 号（不复用），定类型：新增/修改/删除/延期/否决/待定
2. 扫影响五个面：§1 未做任务、§6 已完成需重做、§2 契约、测试/文档、§0.4 机制（复用哪个 / 新建哪个）
3. 更新任务：
   - 新增 → 加任务，来源 ← C#
   - 修改 → 不改旧任务；新开"重做 T1-x（← C#）"；旧任务进 §6 标"被取代"
   - 删除/否决 → 移入 §6 标"取消 ← C#"，原文保留
   - 延期 → 移入 §6 标"延期 ← C#"
4. 更新 §4.2"处理"列、顶部"活跃变更"、"最后更新"
5. 跑 lint
6. 输出新的执行提示词
```

### 3.3 执行AI发现越界

执行AI 被提示词明确要求：**先停下**。输出固定格式：

```text
超出任务边界：当前任务 T1-x 的边界是 <边界>。
本次要求的是 <新需求>（或：会引入新机制 <机制名>）。
需要先记 C / D，我不继续做。请转给规划AI。
```

然后人把这句话转给规划AI，走 3.2。

## 4. 交接（换会话 / 换AI）

```text
你是（规划AI / 执行AI）。请加载 skill plan-doc，读规划文档 <路径>。

事实源优先级：代码 > 测试 > README/AGENTS > 文档 §0
当前阶段见 §0，下一条任务见 §1.1，需求变更见 §4.2，历史见 §5 / §6。

先复述你理解的当前状态和下一条任务，再继续。
```

要点：**先复述再干**。复述错了立刻纠正，比干错了再返工便宜。

---

## 5. 收尾与归档

```text
阶段完成。请加载 skill plan-doc：
1. 跑 lint -Strict
2. §0 全部置完成，frontmatter status: done，补 completed
3. §6 归档所有任务
4. 顶部标"冻结：P1 @ <commit>（日期）"
5. 如需新阶段，建 {同名}-P2.md 并写血缘：前身 [[旧文档]]
```

## 6. 提示词速查表

| 场景 | 用谁 | 提示词要点 |
|---|---|---|
| 建规划 | 规划AI | 目标 / 仓库 / 出口条件 → 拆 T1-1… → 只输出待办 |
| 领任务 | 规划AI | 读 §0/§1/§4.2 → /plan-next → 任务含机制字段 → 只输出提示词 |
| 做任务 | 执行AI | 先查 §0.4 机制登记 → 只做一条 → 越界/新机制先停 → 固定回报 |
| 修 bug | 执行AI | 同对话直接修，不动计划 |
| 改需求 | 规划AI | /plan-change → C 号 → 影响五面（含机制） → 新提示词 |
| 交接 | 新AI | 读文档 → 复述状态 → 再干 |
| 记结果 | 规划AI | /plan-done 或 /plan-check |
| 收尾 | 规划AI | lint → status done → 冻结 → 拆 P2 |

## 7. 常见问题

**Q：执行AI做完了，规划AI还没记录，下次怎么看？**
A：看 §5。每条实施记录都有验证命令和结果；§0 是快照。两边永远以文档为准。

**Q：一条任务做了一半会话断了？**
A：§5 记 `- [ ] **T1-x** —— 进行中：卡在…`；下次 /plan-next 会优先捞未完成项。

**Q：两个执行AI能并行吗？**
A：能，但必须任务边界不重叠、改动文件不重叠。规划AI 在任务表里写明"涉及文件"。

**Q：要不要给规划AI和执行AI用同一个模型？**
A：不用。规划AI 用强模型拆任务；执行AI 用能写代码的模型即可。关键是角色分离，不是模型分离。

**Q：lint 报了很多 WARN？**
A：WARN 是提醒，不是门禁。逐条回复里说明原因即可；ERROR 必须清零。
