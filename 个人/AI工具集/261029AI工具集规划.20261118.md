## 2. 契约

**v1（2026-10-29）**

- 每个 skill 一个目录（`SKILL.md` + `scripts/` + `references/`）；skill 间不硬依赖
- keil 脚本输出 JSON；命令统一 `/splan-*`
- 无统一构建；keil 用 `python <skill>/scripts/keil_*.py ...`

**v2（2026-11-18，← C6）**

- 入口只有 `/splan <动作>`：new / req / next / done / change / check / enter / tidy；无命令文件、无安装器
- 文件数：`1 总规划 + 1 归档 + A 个活动 R 文档`；无完成 R 时归档不存在
- 单一归属：建了 R 文档 → 该 R 的 §3 / T / 局部 D、C 全在 R 文档；总规划只留 §0 一行 + §6 一行
- 标记：总规划 `plan-doc:v1`、R 文档 `req-doc:v1`、归档 `archive-doc:v1`；归档 append-only，锚点 `## R# 标题（YYYY-MM-DD）`
- 编号：R / T / D / C 全局单调，§0 顶部维护「下一号」
- 预算：总规划 ≤200 行、活动 R ≤10、未完成 T ≤15；超 240 行报 `DOC-010`

## 3. 设计要点

- 阶段 1：keil / eide / kb-workflow / splan 各自独立，一 skill 一目录
- 阶段 2：Splan 从「单文档全记」改为「三件套 + 预算 + 归档」；历史只在归档，总规划只留当前
- 归档事务顺序固定：追加归档段（锚点幂等）→ 改总规划 §0 / §6 → 处理 R 文档；失败即停，重跑续做
- 入口：skill 即命令；装好 skill 就有 `/splan <动作>`，动作词省略默认 `next`
